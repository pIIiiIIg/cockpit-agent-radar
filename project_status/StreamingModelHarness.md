## 当前已知问题

## 已知问题

- **解码 110ms/token 偏慢**。根因不是 KV（速度不随长度变化），而是 HF 的 MoE 实现在单 token 解码时每层多次 GPU→CPU 同步（`.nonzero()` + 循环里的 GPU 标量比较 + `torch.where`）。48 层 × 17 次 ≈ **816 次同步/token**，正好对上 110ms。

  理论下限按 config 实算（128 专家取 8、`moe_intermediate_size=768`、48 层、GQA 32:4）：
  每 token 激活约 **2.72B 参数 → bf16 读取 5.44GB**。5090 带宽 1.79TB/s 下约 **3.0ms**，
  H200 带宽 4.8TB/s 下约 **1.1ms** —— 实测 110ms 是下限的 **36 倍**（5090）。
  可用无同步的 `index_select`+`bmm` 快路径 monkeypatch 掉。

  > 判别实验：H200 带宽是 5090 的 2.7 倍。若瓶颈真是带宽，换卡后该快 2 倍多；
  > 若是同步开销（延迟性质，与带宽无关），几乎纹丝不动。跑 `tests/stress_multiturn.py` 看 ms/token 即可判定。
- **闲聊仍注入工具**。用 6478 条真实车控指令验证过：加分数门槛要滤掉全部闲聊需 T=5，代价是误伤 6.25% 的真指令，不划算，故保留现状。
- **上下文引力**：光场屏偶被选成副驾屏。工具淘汰缓解未根治。
- **聚合意图**展开不全。
- `DynamicCache.update()` 用 `torch.cat`，每 token 重拷整条 KV（O(n²)）。当前 KV 规模下影响可忽略（KV=2500 时约 0.2ms），KV > 10000 才值得换 StaticCache。

# H20 Qwen3-Omni Harness A/B 端到端结果

日期：2026-08-03  
硬件：NVIDIA H20 96GB，模型运行在独立 GPU 0；正式 GPU 1/2 未改动。

## 数据

- 文本清单：300 条车控 + 100 条确定性日常对话，覆盖 300 个不同工具。
- 语音：2 个中文音色，并生成 clean / 20dB SNR 版本。
- 成功生成 1,566 个 PCM16、16kHz、单声道 WAV。
- 公平对照：A/B 使用 `audio_index.jsonl` 中完全相同的前 100 条音频：
  82 条车控、18 条日常对话。
- 音频以真实 100ms 时钟发送；延迟从用户音频结束（commit）开始。

## 方案

### A：main

```text
音频 → faster-whisper → 文本 RAG Recall@24
→ 候选工具晚注入 Qwen3-Omni → §工具标签§ → 执行
```

### B：harness_b

```text
音频直接进 Qwen3-Omni KV
→ 模型自主 search/state/call 多跳
→ CarSim 回执进 KV → 成功后口播
```

B 已增加 Harness 强制门：每轮 `call` 前必须先 `search`，不能仅靠提示词约束。

## 结果

### 正确性

| 指标 | A main | B harness_b |
|---|---:|---:|
| 完成率 | 100% | 100% |
| 严格工具召回/执行成功率 | **80.49%** | 79.27% |
| 日常对话误车控 | 0% | 0% |
| 整体任务成功率 | 84.0% | 约 83.0% |
| RAG Recall@24 | **98.78%** | 不适用 |
| ASR micro CER | 6.39% | 无 ASR |

100 条样本下两者置信区间高度重叠，不能据 1.22 个百分点差异断言 A 更强。

严格召回要求 `expected api_name == actual call api_name`。语义等价工具也会被计为失败，
所以这是偏保守的数字；后续需增加参数与最终车态的语义成功判定。

### 时延

| commit 后时延 | A P50 / P90 | B P50 / P90 |
|---|---:|---:|
| ASR 完成 | 183 / 248ms | 无 |
| RAG 完成 | 227 / 315ms | 按需多跳 |
| 首文本 | 758 / 1,006ms | **131 / 141ms** |
| 首动作 | 1,094 / 1,440ms | **700 / 850ms** |
| 首音频 | **2,918 / 3,453ms** | 3,491 / 4,171ms |
| 整轮结束 | 2,945 / 4,224ms | 3,576 / 4,246ms |

结论：

- B 的模型决策明显更快，省掉 ASR/RAG 前置等待。
- A 的单次候选注入比 B 多跳更快进入最终口播。
- 两者首音频都在约 3 秒，当前主要瓶颈是 Edge TTS，而非 Qwen 首 token。
