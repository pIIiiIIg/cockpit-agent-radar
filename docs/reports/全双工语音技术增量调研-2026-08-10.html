一、先说结论

P0：直接命中当前工程短板

  1. 继续项目自有的 Qwen3-Omni MoE 无同步 fast path。 2026-08-10 Radar 没有出现可替代该判别实验的新内核；不要用 KV 压缩、服务吞吐或另一模型的 RTF 解释现有 110ms/token。
  2. 新增一个仅离线的 OmniVoice 16-step 外挂 TTS 候选。 论文的 H20、batch=1、10 秒完整音频 RTF 为 0.0319，说明有速度潜力，但不是 TTFA 或流式首包证据。候选只验证“Edge→官方 OmniVoice”这一变量，预计正确性修复数为 0，因此明确禁止请求 H20。

P1：适合形成下一阶段架构

  1. 用 RIME 的 assignment/branch/return gate 设计聚合意图回放契约。 它支持“未完成 assignment 或仍有开放 branch 时禁止返回”，但音乐编辑结果不能外推为车控准确率。
  2. 参数和最终车态仍优先于工具名。 在当前错误桶没有按聚合意图量化之前，只形成评测规范，不重复启动参数化本体、云监督、SoulX 或其他独立实验。

P2：长期模型研究

  1. 文件系统记忆只作为负面设计证据。 论文显示组织主要节省大材料搜索成本，并不稳定提高答案正确率；不能拿它直接修复当前上下文引力。
  2. 2026-08-10 的小型全双工仓库和第三方模型镜像不进入候选。 它们缺少与当前 100 条 A/B、110ms/token 或约 3 秒首音频可比较的一手基准，也没有形成可安全归因的单变量。

1. OmniVoice: Towards Omnilingual Zero-Shot Text-to-Speech with Diffusion Language Models

论文（2026-04-01）：https://arxiv.org/abs/2604.00688 作者项目页：https://zhu-han.github.io/omnivoice 官方代码：https://github.com/k2-fsa/OmniVoice 官方模型：https://huggingface.co/k2-fsa/OmniVoice Radar 于 2026-08-10 发现的第三方 GGUF 镜像：https://huggingface.co/jiangzhuo9357/omnivoice-0-6b-gguf

它是什么

OmniVoice 是约 0.8B 总参数的零样本多语种 TTS。2026-08-10 的 Radar 条目是第三方 GGUF 转换，并不是新论文或新官方版本；本报告只用论文、作者项目页和官方模型页核验，不把镜像的量化质量或许可证外推到官方模型。

核心方法

模型以 Qwen3-0.6B 初始化双向 Transformer，直接从文本和参考音频条件预测八码本声学 token。它采用单阶段、离散 masked-diffusion NAR 路径，以全码本随机 mask 训练，并在推理时迭代解 mask。候选固定为论文公开的 16-step 设置，避免同时改变模型和推理步数。

论文结果

  • H20、PyTorch、3 秒提示生成 10 秒音频时，16-step、batch=1 的完整波形 RTF 为 0.0319；32-step 为 0.0598。论文没有报告首包时间、流式 chunk 时间或打断后残留。
  • 16-step 在 Seed-TTS test-zh 上报告 SIM-o 0.773、WER/CER 口径值 0.99、UTMOS 3.00；32-step 对应 0.777、0.84、3.11。这说明速度和质量存在可测取舍，不证明在项目中文车控文本上优于 Edge。
  • 完整 32-step 官方模型在 Seed-TTS test-zh 的 WER/CER 口径值为 0.84；论文中的 CosyVoice3 对照为 1.14，但二者训练数据、结构和推理方式不同。

对 StreamingModelHarness 的帮助

编辑判断：它只替换判停和文本生成后的外挂 TTS，直接对准当前约 3 秒首音频，不改变 Qwen 音频 KV、工具选择或车控执行。实验应冻结生成文本、音色提示、播放器、100 条样本和计时起点，记录完整波形可用时间、真正首音频时间、P50/P90/P95、RTF、显存、中文 CER、重复/漏词与打断残留。

编辑判断：论文 RTF 给出了值得测的上界线索，但 NAR 完整波形可能没有可增量播放的首包。若实际必须等整句完成，即使 RTF 很低，也需按真实 commit→首音频口径判断，不能把 RTF 当 TTFA。

局限与开放状态

  • 论文公开；官方代码公开并标 Apache-2.0；官方预训练权重因训练数据约束标为 CC-BY-NC，不能作为量产商业后端直接采用。训练数据逐项许可证仍需独立审查。
  • 当前官方说明返回完整 np.ndarray；流式接口、首包、取消和生成中断能力未知。
  • 论文速度只在 H20 上测过；5090、Windows、当前播放器和并发 Qwen3-Omni 条件下未知。
  • 第三方 GGUF 镜像的转换正确性、速度、实现完整性和许可证传递均未知，不进入实验依赖。

2. RIME: Enabling Large-Scale Agentic Music Post-Production

论文 v2：https://arxiv.org/abs/2607.19605v2

它是什么

RIME 把音乐后期制作表示为受约束编辑图，并用 POEMS 的 20 余个 MCP 音频工具生成“输入音频—编辑指令—目标音频”三元组。该工作由 Radar 于 2026-08-02 发现；2026-08-10 完成开放状态复核，不是 2026-08-10 新发表的工作。

核心方法

系统先按曲目元数据绑定 recipe，检查前置条件和效果链顺序，再展开 motif、按工程先验采样参数并执行 separate→process→mix。Agent 维护 working audio、assignment、execution 和 failure/repair 四类状态；未完成 assignment 或仍有开放分支时，运行时 gate 阻止提前返回。

论文结果

  • 作者从互斥的 10,000 曲目子样本筛得训练 549 首/37 小时、评测 297 首/20 小时，训练和评测各生成 3,000 个三元组，另有 300 个污染修复样本。
  • 2,922 个有效目标上，GPT-4o Mini、Gemini 3 Flash、Gemma 3n 的编辑方向相似度分别为 0.611、0.512、0.480，Graph F1 为 0.845、0.702、0.803。
  • 指令从精确 AL0 变为抽象 AL2 后，GPT-4o Mini 相似度从 0.733 降到 0.449，Gemma 3n 从 0.673 降到 0.325。
  • Gemma 3n SFT 在 AL2 达到 FAD 0.066、KAD 0.162、编辑方向相似度 0.474、Graph F1 0.747，但平均仍只正确预测约一半操作参数。

对 StreamingModelHarness 的帮助

编辑判断：聚合车控可借鉴 assignment state 和 branch gate，把每个子意图、前置条件、参数、执行结果和补偿状态变成 typed ledger；只有所有 assignment 有终态、无开放分支且最终车态通过 verifier 时才允许口播成功。

编辑判断：这只是评测和执行契约。当前快照没有聚合意图独立失败数，也没有参数/最终车态基线，因此无法写出可信的预计修复数，不进入候选 JSON。

局限与开放状态

  • 任务是完整音乐片段上的离线多步 DSP，不是流式语音车控；最多 20 步工具循环无法满足座舱动作时延。
  • 数据和目标编辑由人工 recipe 与合成效果链构造，不能代表真实用户聚合指令。
  • 截至 2026-08-10，论文和作者页面未提供 RIME/POEMS 官方仓库、Gemma 3n SFT 权重或生成的训练/评测三元组；代码、权重、派生数据和许可证未知。

3. Filesystem-Based Memory for LLM Agents: Organization, Evolution, and Sustainability

论文：https://arxiv.org/abs/2607.26637

它是什么

该工作把一个文件系统记忆拆成管理、搜索和执行三种角色，在长对话与 ALFWorld 技能任务上比较 Agent 自组织层级、原样日志、分块检索和不同工具 harness。Radar 于 2026-08-03 发现，开放状态于 2026-08-10 复核。

核心方法

管理 Agent 按 chunk 写入和重组 Markdown 文件树，搜索 Agent 只读检索并返回带路径/行号的证据，执行 Agent 消费技能后把轨迹回写。论文控制记忆形态、模型能力、规模和工具接口，并同时测正确率、引用、token/调用成本和存储健康。

论文结果

  • 没有统一最优记忆形态：LoCoMo 上 Agent-curated 与 Foldered sessions 均为 86.1%，Verbatim dump 为 84.2%；PersonaMem-32k 上 Agent-curated 仅 37.5%，Verbatim dump 为 78.1%。
  • PersonaMem-32k 每问成本中 Agent-curated 为 2.5 美分，Verbatim dump 为 4.0 美分；组织结构较确定的收益是搜索经济性，不是稳定提高正确率。
  • 技能任务中，强执行模型下 Episode log 为 87.1%、Guidance Synthesis 为 82.1%；弱执行模型下顺序反转为 66.4% 与 76.4%。
  • 仅更换工具 harness 就能显著改变文件数量和组织形态；Shell 在技能任务达到 82.9%，但长对话中的不同组织质量基本持平。

对 StreamingModelHarness 的帮助

编辑判断：它提醒项目不要把工具说明自动整理、摘要层级或记忆树视为“上下文引力”的默认修复。应在相同错误桶上分别比较原始证据、摘要、候选说明和工具接口；只有严格工具、参数和最终车态改善才算有效。

编辑判断：论文处理 endpoint 后的文本记忆，不涉及流式音频 KV、MoE 同步或 TTS，不能解释当前 110ms/token 和约 3 秒首音频。

局限与开放状态

  • 长对话主实验样本很少，PersonaMem 32k/128k 不是纯规模对照；部分小差异与 judge 或单次运行波动同量级。
  • 主要模型与任务域不等于 Qwen3-Omni 车控，长期增长实验也只覆盖一条 140-task 链。
  • 截至 2026-08-10 未发现作者官方项目页、代码、模型或数据发布；相关许可证未知。

编辑判断：它们最多提供 WebRTC/浏览器/VR/LiveKit 产品编排线索。现阶段应继续项目自有的多轮、打断、取消和补偿回放，不运行陌生仓库代码，也不把“full-duplex”标签当作模型级全双工证据。

论文、权重、数据、基准和许可证未能逐项由当前一手材料确认，均记为未知。它们没有清晰的单变量和项目可比指标，因此不进入候选 JSON。

今日建议路线

第一阶段

  1. 继续原 HF MoE 与 index_select+bmm fast path 的 5090/H200 输出一致性和 ms/token 判别；这是项目内核实验，不重复包装为新 candidate。
  2. 对 OmniVoice 先做依赖、模型许可和完整波形接口审查；本次报告不运行其仓库代码。

第二阶段

  1. 若审查通过，只在非 H20 隔离环境执行 Edge TTS→官方 OmniVoice 16-step 单变量回放。
  2. 冻结文本、工具结果、音色提示、播放器和计时点，联合记录首音频、完整波形、CER、重复/漏词、显存和打断残留。
  3. 候选预计正确性修复数为 0，故无论离线时延结果如何，本轮都不请求 H20；H20 只能按既定 414 零退化和净修门另行决定。

第三阶段

  1. 为聚合意图建立 typed assignment/branch/final-state 回放规范，等待既有参数化本体 result manifest。
  2. 只有得到独立错误桶、单变量和预计净修数后，才把 RIME 式 gate 转成候选；不得用强制 candidate-ID、CMTF 或已拒绝 verifier 扩大触发面。

风险提醒

  • 指标偷换风险：OmniVoice 的 RTF 是完整音频生成速度，不是首包时间；MoE 的目标是 batch=1 ms/token，不是服务吞吐。
  • 许可证风险：OmniVoice 代码是 Apache-2.0，但官方权重为 CC-BY-NC；第三方 GGUF 不会自动消除上游限制。
  • 重复实验风险：candidate-ID/CMTF、conditional top-2 verifier 已有负结果；参数化本体、云监督和 SoulX 只消费 result manifest。
  • 安全风险：TTS 替换不得改变工具选择和最终车态；聚合意图未完成分支不能提前口播成功。
  • 证据日期风险：2026-08-10 新发现的镜像不等于 2026-08-10 新论文；本报告没有使用或伪装任何 2026-08-10 之后的证据。
