一、结论

本次候选来自 2026-08-04 报告生成后被 Radar 收录的条目，以及此前已收录但没有进入前一日报告的条目。只采用论文正文、arXiv/Hugging Face 论文页、作者官方项目页、官方代码仓库和模型页。下文用“论文/官方来源事实”和“编辑判断”明确分开；编辑判断不代表论文结论。

今天有三项可直接改变当前工程实验设计的增量：

  1. P0 · UltraEval-Audio：可作为 ASR、TTS、Codec 和 Audio LLM 的统一离线评测底座，但必须自行补上判停、打断、工具、最终车态和端到端流式时延。
  2. P0 · LongHorizon-Harness：把任务状态、单步执行和环境审计拆成 Manage–Execute–Audit，直接支持 Harness C 的外置状态、验收契约和执行后验证。
  3. P0 · Sparse Event-KV：证明下游事件的 KV 可能“物化”已经删除的源信息，现有 KV 删除消融会产生误判；应先修订长会话 KV 评测，再讨论裁剪策略。

另有五项值得重点跟踪：

  • P1 · JoyAI-Talker：用独立 Joy-Duplex 每 160 ms 判断 partial/complete/backchannel/accept/reject，对打断、附和和非目标语音有直接参考价值；但不是统一原生双音频流，且没有代码、权重和端到端时延。
  • P1 · SpeechAgent-R：把音频技能文档、typed call、音频/文本工具回执和继续推理串成闭环；工具选择明显改善，但平均耗时约 22 秒，不是实时路径。
  • P1 · Model or Harness?：提供 interaction edge + fault side + earliest unrecovered event 的故障归因框架，适合统一模型、上下文、工具、环境和 grader 的回放标签。
  • P1 · OPOD v3：已发布 Qwen3-Omni-30B-A3B 等学生权重，可做 thinker 离线 A/B；这是既有 OPOD v2 的修订版，不建立第二项技术。
  • P1 · Macer：先分配音频/视频 token 预算，再做模态内排序，能降低 OmniLLM prefill 负担；仅适用于可访问浅层注意力和 KV 的共享解码器。

DAIEN-TTS 和 GROW 属于 P2：前者适合环境匹配口播或生成带噪/混响压测数据，后者是 flow-matching TTS 后训练方法；两者当前都没有可用实现或权重，也没有流式首包结果。

今天仍然没有可改变现有路线的 AEC/降噪、空间听觉、真正在线的语义判停、MoE 解码内核或实时服务新结果。前一日的 AEC/LMPAN → 因果 NS → 判停、多座位受话对象门、无同步 MoE fast path 和真实双讲回放优先级不变。

1. UltraEval-Audio：统一音频评测底座

来源：官方代码仓库；论文 / arXiv:2601.01373；ACL 2026 论文页。

论文与官方来源事实

问题。 ASR、TTS、Audio Codec 和 Audio LLM 通常各自维护数据读取、提示词、模型接口和指标，难以在同一运行层公平复现；中文高层语音理解与生成评测也较少。

方法。

  • 用 YAML 注册数据集、模型和任务，用 Jinja 管理提示词。
  • 本地模型以隔离环境、常驻子进程和 IPC 运行，后处理与 evaluator 可组合。
  • Codec 同时报告 ASR WER/CER、WavLM speaker similarity、UTMOS 和 DNSMOS。
  • 官方仓库加入 SpeechCMMLU 和 SpeechHSK 等中文语音理解/生成任务。

明确结果。

  • 论文版本覆盖 10 种语言、14 类任务、24 个模型和 36 个基准。
  • 当前官方 README 的口径是 10 种语言、12 类任务和 34 个基准，说明框架仍在演进，不能混用不同版本榜单。
  • 当前官方理解榜中 Qwen3-Omni 平均分为 84.92；其中 AISHELL-1 CER 0.87、WenetSpeech test-net CER 4.82、CoVoST2 英译中 BLEU 46.58、MELD 准确率 56.81。
  • 当前生成榜中 GPT-4o-Realtime 平均分为 74.00，Qwen3-Omni 为 57.15；这些是官方榜单结果，不是 StreamingModelHarness 实测。

开放状态。

  • 代码与文档已公开，仓库标注 Apache-2.0；官方 release 为 v1.1。
  • 框架不提供一套统一模型权重，只提供适配器和复现配置。
  • 各上游数据继续受各自许可证约束；没有逐项核验到许可证的任务应标为未知。

编辑判断：对当前项目的帮助

将 UltraEval-Audio 作为离线音频运行层，而不是替代现有 Harness：

现有座舱 WAV / 模型输出
  → UltraEval-Audio 适配层
  → ASR / TTS / Codec / Audio LLM 指标
  → 自定义 endpoint / barge-in / cancel / Action / 最终车态 evaluator
  → 与首文本、首动作、首音频、整轮 P50/P95 合并

接入时必须固定仓库 commit、数据 revision、提示词和 judge 版本。论文的语音生成评测常先经 ASR 或模型裁判，不能替代真实用户听测，也不能用总分掩盖打断取消和车控安全。

局限与优先级

  • 官方论文与当前 README 的基准数、任务数已有版本漂移；部分复现文档与榜单数字也不完全一致。
  • 不原生覆盖连续双工、AEC、打断取消、工具调用、最终车态或视觉座舱。
  • UTMOS、DNSMOS 和模型裁判都是代理指标。
  • 建议优先级：P0。 先接入数据与 evaluator 接口，不运行本次未审计的仓库代码。

2. LongHorizon-Harness：Manage–Execute–Audit 长任务控制

来源：论文 / arXiv:2608.01964；作者项目页；官方代码仓库。

论文与官方来源事实

问题。 长任务把执行、状态维护和完成判断全部放进持续增长的上下文，会积累错误自评、上下文腐化和状态丢失。

方法。

  • Manager 维护外置结构化任务状态和验收条件。
  • Executor 在新上下文中只执行一个子任务。
  • 只读 Auditor 检查真实环境，只有审计证据可以更新持久状态。
  • AgentAdapter 可连接不同执行后端，形成 Manage–Execute–Audit 循环。

明确结果。

基准基线LongHorizon-Harness
WeaveBench PassRate51.8%80.7%
WeaveBench 平均分0.7020.835
Terminal-Bench 2.169.7%77.2%
OSWorld 2.0 二值完成率2.8%8.3%
OSWorld 2.0 partial score21.5%35.2%

论文摘要把 Opus 子集写为 20.0%→34.3%，正文表格和项目页则是 20.6%→35.3%；本报告保留该不一致，不自行选择性修正。

开放状态。

  • 官方代码已发布 v0.1.0，仓库标注 MIT。
  • 没有独立模型权重；它是 Harness。

编辑判断：对当前项目的帮助

最直接的迁移不是复刻桌面 Agent，而是建立座舱验收契约：

Manager: 结构化 affair / Action 计划 / 前置条件
Executor: 单个低风险动作或询问
Auditor: 只读 CAN / UI / 服务状态
Commit: 只有审计通过才更新持久状态并允许 terminate

这可以与前一日 Qwen-UI-Agent 的 typed Action、ask_user 和最终车态验证合并。短期先在 Harness C 增加结构化状态与审计门，避免把完整工具轨迹长期留在 KV。

局限与优先级

  • OSWorld 对照组主要使用 GUI，而该方法允许 GUI+CLI，提升不完全来自 Harness 拆分。
  • 在 WeaveBench 和 OSWorld 上总 token 或输出 token 可能显著增加。
  • 依赖可由环境闭合验证的验收条件，不能弥补模型本身的视觉、数学或规划能力。
  • 没有语音流、打断和真实座舱结果。
  • 建议优先级：P0。

3. Sparse Event-KV：KV 删除消融的隐藏混杂

来源：论文 / arXiv:2607.23693；官方代码仓库。

论文与官方来源事实

问题。 稀疏 KV 服务通常先对完整历史 prefill，再保留部分事件 KV。即使产生某个下游事件的源观察已经被删除，下游 KV 仍可能携带源值，因此“删掉源事件后准确率不降”不等于源事件无用。

方法。

  • 用 donor pair 构造 token 数量和位置相同、只改变已删除源值的历史。
  • 全局 prefill 后删除源事件，只服务不含答案文本的下游 root KV。
  • 将可用性拆成 trigger、landing 和 access：什么措辞触发写入、信息落在哪些行、删除源后如何读取。

明确结果。

  • Qwen3-8B 的 donor-sensitive 项目呈 99:0 跟随已删除源值；256 对复现实验中 131 对 donor-dependent，其中 130:0 跟随。
  • 主动构造不含答案的 carrier 后，donor-aligned recovery 从 6% 提高到 51%。
  • 二元紧凑状态恢复率为 0.934；四分类为 0.223、八分类为 0.156，三位数字为 0/192，说明承载能力很有限。
  • REALTALK/LoCoMo 的自然晚期提及没有显示优势；论文不支持“自然对话会自动形成可靠 KV 记忆”。

开放状态。

  • 官方仓库提供复现实验，标注 MIT。
  • 不发布新模型权重，实验使用冻结模型。

编辑判断：对当前项目的帮助

这项工作首先改变评测，不是直接提供 KV 压缩算法。针对当前“持久 KV 使严格工具能力下降约 22 个百分点”，应增加：

  1. 显式文本摘要：关键车态、权限和未完成 affair 写成可审计记录。
  2. donor-pair：只改变早期源值，检查后续工具回执 KV 是否偷偷携带旧值。
  3. 独立编码对照：比较完整 prefill 后裁剪与仅对保留片段重新 prefill。
  4. 自然轨迹对照：不要把刻意措辞 carrier 的结果外推到普通多轮对话。

局限与优先级

  • 只稳定承载紧凑状态，对措辞、checkpoint、层、readout 和共服务行敏感。
  • 自然对话结果为阴性，多跳实验还使用 oracle 行选择。
  • 不降低当前约 110 ms/token 的 MoE 解码时间。
  • 建议优先级：P0（评测口径），P1（运行时应用）。

4. JoyAI-Talker：160 ms 状态门控的共情语音系统

来源：论文 / arXiv:2608.01119。

论文与官方来源事实

问题。 系统希望同时保持文本推理、根据年龄/情绪调整表达，并区分真实打断、附和、他人说话和背景语音。

方法。

  • Thinker 是 48.9B 总参数、约 3.28B 激活的 MoE。
  • PAER 将年龄、性别和情绪信息写入推理与 TTS 表达指令。
  • Talker 使用自回归 Transformer 和因果 Diffusion Transformer 做流式合成。
  • 独立 1.7B Joy-Duplex 每 160 ms 解码转写及 partial/complete/backchannel/accept/reject；只有 accept 触发下游语音模型。

因此它的“双工”来自前置状态模型对半双工主模型的门控，不是一个统一模型同时持续听说。

明确结果。

  • Full-Duplex-Bench v1.5：用户打断 C_RESPOND=0.88、错误继续 C_RESUME=0.07。
  • 附和条件误响应/继续为 0.01/0.96；对他人说话为 0.17/0.72；背景语音为 0.10/0.85。
  • Speech-BFCL Single/Parallel 为 89.62/78.72，Speech-SmartInteract 为 80.39。
  • 论文没有报告完整端到端首包、打断停播或服务 P95。

开放状态。

  • 论文已公开。
  • JoyAI-Talker 专属代码、权重、训练数据和许可证均为未知；没有依据将其他 JoyAI 项目的开放状态沿用到本模型。

编辑判断：对当前项目的帮助

把五类状态作为 FastTurn/SoulX 之后的流式旁路标签，比直接替换主模型更现实：

partial / complete → endpoint 候选
backchannel        → 保持收音，不生成正式 Action
accept / reject    → 受话对象与打断授权

座舱回放应包含驾驶员、副驾、后排、助手扬声器回声、广播、真实打断和附和。高风险车控仍须再过说话人/座位、权限和确认门。

局限与优先级

  • 不理解警报、音乐等通用环境声；没有 AEC、阵列或真实座舱测试。
  • 模块边界可能增加时延并损失细微声学信息，论文未给完整服务开销。
  • 复杂工具调用和 Agent RL 仍未完成。
  • 建议优先级：P1。 先迁移标签和回放，不等待模型开放。

5. SpeechAgent-R：音频技能调用闭环

来源：论文 / arXiv:2608.01881。

论文与官方来源事实

命名去重。 HIU 是 Hear–Invoke–Understand 框架及 HIU-Corpus/HIU-Bench 前缀，正式模型名是 SpeechAgent-R；它们属于同一论文。

问题。 大型音频语言模型对分离、定位、说话人识别等复杂任务往往不能动态选择技能、读取处理中间结果并继续理解处理后的音频。

方法。

  • 以 Qwen3-Omni-Thinking 初始化。
  • 先用 65,492 条、507.6 小时的工具轨迹做加权 SFT，再用多轮 GRPO 联合优化格式、工具交互和答案。
  • 工具可以返回文本或处理后音频，结果重新进入上下文供下一步决策。

明确结果。

设置ToolAnswerTotal
SpeechAgent-R ID96.7478.5984.17
SpeechAgent-R OOD79.6165.8070.94
SpeechAgent-R 总体——80.05
同 Harness 基座总体——65.01
  • ID/OOD/总体耗时分别为 20.85/25.45/22.29 秒。
  • 完整轨迹 SFT 总体为 75.20，加入 RL 后为 80.05。
  • ID Oracle-tool 把总分从约 84.2 提到 91.4，说明工具输出质量仍是主要瓶颈。
  • 论文结论处把总体提升写成 15.40，但表格差值是 80.05-65.01=15.04；本报告不修饰该不一致。

开放状态。

  • 论文称发表后发布。
  • 当前代码、模型权重、HIU-Corpus、HIU-Bench 和许可证均为未知/未开放。

编辑判断：对当前项目的帮助

可借鉴强制状态机，而不是采用其模型：

skill documentation
  → typed candidate call
  → schema / 参数 / 权限检查
  → 文本或音频结果回流
  → answer / Action / verify

评测应拆成格式、工具选择、参数、工具结果利用和最终车态。论文约 22 秒的平均耗时不满足实时座舱，因此说话人验证、DOA、目标说话人提取等技能只能放在可并行或低频路径。

局限与优先级

  • 输入是完整音频，不评 endpoint、打断、附和或 TTS。
  • 训练轨迹大量来自模板和模型生成，SFT 还用真值替换错误工具输出。
  • 训练使用 24 张 A100；没有真实车控安全任务。
  • 建议优先级：P1（接口与评测），P2（模型）。

6. Model or Harness?：交互边故障归因

来源：论文 / arXiv:2607.28802。

论文与官方来源事实

问题。 最终任务失败不能说明应修模型、上下文、memory、工具适配、环境还是 grader；相同表象可能有完全不同的责任方。

方法。

  • 用“组件交互边 + fault side”表示失败。
  • 覆盖 owner、grader、第三方、context、memory、tool、其他模型以及本地/外部环境。
  • 沿因果链标记 earliest unrecovered failure。
  • 分类共 41 类，其中 36 类归于模型侧、5 类归于周边组件。

明确结果。

  • 40 个示例上，GPT-5.5 的交互类别准确率 0.80、macro-F1 0.69，与人工标签 Cohen's κ 0.76。
  • 完整失败模式准确率 0.72、macro-F1 0.64。
  • 四模型一致时类别精度 0.96，但覆盖率只有 0.68；完整失败模式精度 0.89、召回 0.60。

开放状态。

  • 论文和附录定义已公开。
  • 官方代码、数据和许可证：未知。

编辑判断：对当前项目的帮助

为每次回放新增四个字段：

interaction_edge
fault_side
earliest_unrecovered_event
recovery_action

它可以区分“context compaction 丢了约束”和“模型看见但忽略约束”，也能区分工具翻译错误、模型忽略工具回执、服务故障和恢复策略失败。自动 judge 只适合建议标签，不能替代人工根因确认。

局限与优先级

  • 40 个示例是说明性样本，不能估计生产失败频率。
  • 来源异质，部分轨迹不完整；细粒度自动归因准确率有限。
  • 类别需要随架构演进而扩展。
  • 建议优先级：P1，作为此前漏报补录。

7. OPOD v3：多教师 Omni 蒸馏的修订更新

来源：arXiv v3:2607.20918；官方代码仓库；Qwen3-Omni-30B-A3B 模型页。

论文与官方来源事实

去重。 Radar 已收录同一 arXiv ID 的 v2 和三个模型页。v3 是修订版，不建立新的论文条目。v3 将 reasoning-gain 权重从 0.1 调为 0.2，补充训练数据、单次 seed 和代码信息，并修正消融表述；主结果没有形成一篇新工作。

问题。 文本、图像和音频教师共同蒸馏时可能产生冲突梯度；对称匹配教师分布还会限制学生超过教师。

方法。

  • 按输入模态把学生 rollout 路由到对应教师。
  • 只在教师对当前 token 概率高于学生时施加单边约束。
  • 每个模态独立控制教师影响。
  • 教师同时评价答案置信度和 reasoning gain；部署时只保留学生。

明确结果。

  • 30B/7B/3B 的 12 项平均分为 70.8/51.7/46.2，分别领先最强对照 2.1/1.8/1.7。
  • 30B 相对 base 的文本/视觉/音频/Omni 分组变化为 +7.0/+1.4/+2.2/+0.8。
  • 移除单边指导、模态控制、验证奖励分别下降 1.8/2.2/2.0。

开放状态。

  • 官方仓库提供 evaluation harness 和 OPOD 训练代码，但底层框架、原始数据、日志和缓存不完整；仓库没有 LICENSE，代码许可证为未知。
  • 30B 和 7B 模型页标注 Apache-2.0；3B 标注 Qwen Research License，不能把三者统一写成 Apache-2.0。

编辑判断：对当前项目的帮助

优先做现成 30B thinker 的离线 A/B，保持候选检索、typed Action、执行器和外挂 TTS 完全一致。它可能改善音频/视觉理解和工具选择，但论文没有训练或评测 talker，因此不能视为全双工语音生成升级。

局限与优先级

  • 每个配置只跑一个固定 seed，训练使用 32 张 H20。
  • 只验证可自动判分的推理任务；自由对话、长文本、语音输出和车控安全未评测。
  • 建议优先级：P1（模型 A/B），P2（训练复现）。

8. Macer：先分模态预算，再排 token

来源：论文 / arXiv:2608.01665。

论文与官方来源事实

问题。 OmniLLM 的全局 top-K 同时决定音频/视频各留多少以及模态内留哪些 token；共享注意力可能偏向音频，从而挤占视频证据。

方法。

  • 训练无关的 Macer 先显式分配音频和视频预算，再在各模态内部归一化排序。
  • 音频和视频从不同浅层读取显著性。
  • 视频选择增加时间覆盖奖励。
  • 文本 token 全部保留，并在单次 prefill 中分阶段剪枝。

明确结果。

  • 25% token 保留率下，Qwen2.5-Omni-7B/3B 分别保留全 token 性能的 98.7%/97.3%。
  • 7B Macer 25% 对比 OmniZip 45%：三榜均分 56.85 对 55.83，估算 FLOPs 为 34.8% 对 39.2%。
  • WorldSense 单卡实验中，延迟从 10.5 秒降到 9.17 秒，显存从 41 GB 降到 25 GB。
  • OmniVinci-9B 的最大 +12.91 点来自特定 45% 保留设置；同参数在 25% 时为 -3.88，不能把最大值当普遍收益。

开放状态。

  • 论文称代码和校准配置将在发表时发布。
  • 当前官方代码、模型和许可证均为未知/未开放。

编辑判断：对当前项目的帮助

如果后续在线视觉使用可修改的共享解码器，可把“先保证模态容量，再做模态内选择”作为调度原则，并在关键视觉操作阶段提高视频预算。当前 Harness 若只能通过封闭 API 或无法访问浅层 attention/KV，则不能直接使用。

局限与优先级

  • 只验证共享解码器的音频+视频架构，参数需要按模型规模校准。
  • 收益对预算参数敏感，多数完整评测没有重复试验或误差条。
  • 没有连续流式到达、工具闭环或真实座舱时延。
  • 建议优先级：P1（离线研究），在线接入为 P2。

9. Extended DAIEN-TTS：环境感知零样本 TTS

来源：论文 / arXiv:2608.03011；作者官方项目仓库。

论文与官方来源事实

去重。 本文是 ICASSP 2026 DAIEN-TTS 的扩展版，新增混响建模、真实数据微调和 triple classifier-free guidance；应关联旧作，不当作无关新模型。

问题。 零样本 TTS 往往丢弃或混淆说话人、背景噪声和混响，不能分别控制音色与环境。

方法。

  • 基于 F5-TTS，用两阶段 speech-environment separation 分离语音、噪声和混响。
  • 帧级噪声与句级混响 embedding 通过 cross-attention 注入 DiT。
  • 跨说话人混响条件抑制音色泄漏。
  • triple classifier-free guidance 分别控制语音、噪声和混响，并进行 SNR 自适应。

明确结果。

  • 模拟噪声+混响 speaker prompt 下，DAIEN-NR 的 WER/SECS/MOS 为 2.24/0.486/3.91，F5-TTS 为 2.80/0.317/3.75。
  • 模拟环境生成的 CLAP/FAD/ESMOS 为 0.770/2.11/3.55，ground-truth ESMOS 为 3.59。
  • 真实环境微调版 SECS/CLAP/FAD/ESMOS 为 0.486/0.634/3.62/3.62，但 WER 10.65 略差于未微调 NR 的 10.05；不能写成所有指标都改善。

开放状态。

  • 官方仓库当前只有 README 和演示入口。
  • 实现、权重和许可证均为未知/未公开。

编辑判断：对当前项目的帮助

主要价值是生成带真实座舱噪声/混响风格的 ASR、打断和 AEC 压测样本，或研究口播与当前声场的自然衔接。把噪声主动加到助手输出可能降低可懂度并加重 AEC，不能默认优于干净 TTS。

局限与优先级

  • 主要验证英语，依赖大量模拟数据和 184.57 小时真实微调。
  • 噪声 guidance 从 3 提到 9 时 WER 从 13.05 恶化到 63.83，环境保真与可懂度冲突明显。
  • 没有实时、流式、首音频或端侧结果。
  • 建议优先级：P2，跟踪开放状态。

10. GROW：flow-matching TTS 的优势加权后训练

来源：论文 / arXiv:2608.03215；作者官方代码仓库。

论文与官方来源事实

问题。 flow-matching TTS 的传统策略梯度往往把确定性 ODE 改成 SDE 并记录逐步 likelihood，带来噪声和开销；普通正指数 reward weighting 又可能退化成无差别自模仿。

方法。

  • 每个 prompt 生成一组 on-policy 音频。
  • 分别标准化 WER 与 speaker-similarity reward，形成零均值有符号优势。
  • 直接重加权 flow-matching 回归。
  • 用 Wasserstein-2 velocity penalty 锚定冻结参考模型。

明确结果。

  • 三个测试集平均 WER 从 2.016 降到 1.558，SIM 从 0.676 升到 0.715，UTMOS 基本保持。
  • 10-NFE rollout、32-NFE 评测时，相对 32-NFE DiTAR-GRPO 训练快 2.9 倍；相同 NFE 下只有约 1.1 倍。
  • 有符号优势的平均 WER/SIM 改进为 0.458/0.039，指数优势权重为 0.199/-0.003。

开放状态。

  • 论文称将开源。
  • 当前官方仓库为空，代码、权重和许可证为未知/尚未开放。

编辑判断：对当前项目的帮助

它适合未来对本地 flow-matching TTS 联合优化可懂度与音色一致性，不是推理期插件，也不能降低当前外挂 TTS 的首音频时间。只有在选定可训练 TTS、准备真实座舱 reward 和独立人工听测后才值得复现。

局限与优先级

  • 只在 DiTAR 和三项离线数据集验证。
  • 训练 reward 与最终 WER/SIM 使用相同 ASR/说话人模型，存在指标定向优化风险。
  • 没有人工 MOS、真实车噪、流式延迟或 RTF。
  • 建议优先级：P2。

  5. TTS：ECCD 仍是近期更可执行的推理期 A/B；DAIEN-TTS/GROW 待实现开放后再复核。

五、建议执行顺序

第一阶段

  1. 固定 UltraEval-Audio 版本，接入已有 WAV/JSONL 和音频模型输出；新增 endpoint、barge-in cancel、Action 和最终车态 evaluator。
  2. 为 Harness C 增加外置 affair 状态、验收条件和只读车态审计；只有审计通过才允许完成。
  3. 重写长会话 KV 回归：完整 prefill 后裁剪、独立重编码、显式文本摘要和 donor-pair 四组并测。
  4. 把 partial/complete/backchannel/accept/reject 加入多座位真实回放标注，不等待 JoyAI-Talker 权重。

第二阶段

  1. 给失败回放增加 interaction edge、fault side 和 earliest unrecovered event。
  2. 将音频技能调用实现为 typed call + 结果回流 + 最终验证；高耗时技能只走并行或低频路径。
  3. 对 OPOD Qwen3-Omni-30B thinker 做保持 Harness 与 TTS 不变的离线 A/B。

第三阶段

  1. 视觉进入在线 Harness 后，再比较 Macer 式模态预算与全局 top-K。
  2. DAIEN-TTS 和 GROW 只跟踪代码、权重、许可证和实时结果，不在当前主链投入训练。

六、风险提醒

  • 论文基准结果不能替代真实车内 AEC、双讲、多乘员、回声、打断和车控安全回放。
  • UltraEval-Audio 版本与榜单持续变化，若不固定 commit、数据和 judge，日报数字不可复现。
  • LongHorizon-Harness 的部分提升混入 GUI+CLI 能力差异，且可能增加 token；必须做同模型、同工具、同预算对照。
  • Sparse Event-KV 证明的是特定模型和构造下的紧凑状态物化，不支持“KV 可以可靠代替外部记忆”的泛化结论。
  • JoyAI-Talker 没有完整端到端延迟和可用权重；SpeechAgent-R 平均工具耗时约 22 秒；两者都不能直接替换实时主链。
  • OPOD v3 不训练 talker；Macer 不适用于无法访问 attention/KV 的封闭模型；DAIEN-TTS/GROW 均无流式首包证据。
