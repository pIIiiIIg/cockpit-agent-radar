一、先说结论

本报告只把论文正文、作者项目页、官方仓库和模型页作为候选证据。Radar 中的摘要回填只用于发现条目，不作为结果或开放状态依据。下文“论文结果”是来源明确报告的事实；“对 StreamingModelHarness 的帮助”和成功门槛是项目编辑判断。

今天最直接的增量不是新的全双工模型，而是两类与最新提交正相交的记忆工作：一类证明紧凑状态可以被写进稀疏事件 KV，也证明这种隐式状态可能继续牵引后续答案；另一类把全量聚合从不可靠的 top-k 检索改成可执行的关系表操作。它们分别命中 0a1d84e 的紧凑回执、B 版约 22 点 KV 退化和聚合意图展开不全。

P0：直接命中当前工程短板

  1. Compute Globally, Materialize Locally / Sparse Event-KV：首次给“紧凑回执写入 KV 后究竟保留什么”提供了可操作的 donor-flip 实验。论文同时显示它只可靠承载紧凑状态，不能代替数字、参数和原始工具证据；这与当前上下文引力风险同等重要。
  2. AdaMM：通过物化表和 Filter/Compute/Rank 解决 top-k 无法保证全量覆盖的问题，直接适合验证聚合车控意图；但没有公开实现，且表结构仍可能继承抽取错误。
  3. 今日没有新的 MoE 单 token 内核或 TTS 首包工作。110ms/token 仍应按项目自己的 fast-path 判别实验推进，不能用内存论文或 TTS 质量数字替代。

P1：适合形成下一阶段架构

  1. Zero-Mem：把原始事件作为 source of record，以实体图和时间层级做非生成式记忆操作，可作为“短窗 KV + 外部可追溯记忆”的控制组；其 0 token 只指最终问答前不调用 LLM，不代表零计算或零延迟。
  2. AES + HDC：适合重排 52 组易混淆工具与 400 条 A/B/C 回归的覆盖和 scaffold 难度，但论文研究的是 RL 训练环境，不能把 143.2% 相对增益外推成车控收益。

P2：长期模型研究

  1. GROW：在 DiTAR 上以 signed group advantage 改善中英文 WER 和说话人相似度，适合作为 TTS 后训练研究；它不是可直接替换 Edge TTS 的模型，也没有 TTFA、RTF 或流式结果。
  2. 扩展版 DAIEN-TTS：把音色、噪声和混响解耦，适合生成座舱声学回放或研究嘈杂 prompt 的鲁棒性；在真实座舱扬声器输出中预先烘焙噪声可能与环境二次叠加，且论文没有中文、流式或首包证据。

1. Compute Globally, Materialize Locally：Sparse Event-KV 的记忆契约

来源：论文正文 / arXiv:2607.23693v1；作者官方代码仓库；官方模型与环境清单。

Radar 的 Hugging Face 论文条目、arXiv 页面和官方仓库短标题都指向同一篇 v1，不拆成多个候选。

它是什么

论文研究一种容易被 KV 裁剪方案忽略的现象：模型先看过完整事件链后，下游事件的 KV row 可能已经携带上游信息；即使服务时删掉原始上游事件，保留下来的 row 仍会影响答案。作者称其为 semantic materialization，并把“什么措辞会写入、状态落在哪个 row、删掉 source 后还能读出什么”总结为稀疏 Event-KV 的记忆契约。

核心方法

  • 对完整事件轨迹做一次全局 prefill，再删除包含真实值的 source，只服务不显式写出答案的 downstream root KV。
  • 构造 donor pair：只翻转被删除 source 的值，固定可见 token、位置和干扰项；若最终输出随隐藏 donor 翻转，影响只能来自保留的 KV。
  • 比较自然后续事件与专门设计的 answer-free carrier。carrier 不写答案本身，只以特定措辞促使模型把紧凑状态物化到 root。
  • 冻结 Qwen3-8B、Ministral-3-8B-Instruct 和 Gemma-4-12B，以 greedy decoding 测试；没有微调 reader。

论文结果

  • Qwen3-8B 的 root-only donor-sensitive 样本为 follow:anti=99:0，精确 sign test p=3.2×10⁻³⁰。该口径只统计已经对 donor 敏感的样本，不是总体任务准确率。
  • 256 对复现中有 130 follow、0 anti、125 const、1 unscorable，说明约一半样本实际没有形成可读 donor 依赖。
  • 主动 answer-free carrier 将 Qwen3-8B 的 donor-aligned recovery 从 11/192（约 6%）提高到 97/192（约 51%）；固定 query 位置后，review-only 为 0/192，加入 carrier 为 81/192，显式文本为 192/192。
  • 容量实验中，二元状态读出率为 0.934（机会率 0.5）；四元为 0.223、八元为 0.156，三位数字为 0/192。论文支持“紧凑状态可保留”，不支持“任意 payload 可隐式保存”。
  • LoCoMo 上，Gemma-4 的 harvested 与 isolated 差为 -0.011，95% CI [-0.026,+0.004]；真实长对话的被动 late mention 没有显示收益。
  • A100 上 9.2K 上下文的 append patch 为 77ms，重算为 1,033ms；这是 patch/prefill 时间，不是 decode 的 ms/token。

对 StreamingModelHarness 的帮助

将 0a1d84e 的紧凑回执分成两层：

显式 source of record：api_name、参数、最终车态、错误码、时间戳
隐式 Event-KV：成功/失败、是否需重试、事务阶段等紧凑状态

对每类回执做 donor-flip 和 serve-set 消融，检查删掉原始回执后模型究竟跟随哪一版状态。不能只测最终准确率：论文提示“删除 source 后准确率不降”可能是后续 row 已经复制了语义，而不是 source 本来无用。

局限与开放状态

  • 真实长对话的被动物化结果为阴性；carrier 的触发措辞、落点和读出方式跨模型不稳定。
  • 紧凑二元状态明显强于多值和数字，不能承载完整工具参数。
  • 隐式状态可能放大当前已有的上下文引力，新 patch 也可能劫持历史查询。
  • 代码：作者官方仓库已公开，本次未运行。
  • 模型：没有自有权重，复现实验依赖官方清单列出的外部模型 revision。
  • 数据：合成实验由脚本构造；LoCoMo 和 REALTALK 需另行取得。
  • 代码许可证：MIT；模型与外部数据许可证分别遵循各自来源。

2. Beyond Retrieval：AdaMM 分析记忆

来源：论文正文 / arXiv:2607.29440v2。

Radar 中同题 arXiv 条目是同一工作；本报告采用 2026-08-04 更新的 v2。v2 修正了 v1 中若干摘要与表格的增益算术，不建立第二条技术记录。

它是什么

普通长期记忆以 top-k 返回相关片段，但“把所有月份的某项车态列出来”“统计重复故障”“找最高频设置”等问题要求全量过滤、聚合和排序。AdaMM 同时维护检索记忆与分析记忆，把反复出现的多模态属性物化为可查询关系表。

核心方法

  • 从对话、图像和时间元数据提取 (attribute, value, provenance)。
  • 对属性共现做频繁项集归纳：支持度至少 4 轮；新 schema 的 all-confidence 至少 0.60，schema 扩展 confidence 至少 0.80。
  • 每个 schema 物化为“交互轮为行、属性为列”的表，保留时间、顺序和 provenance；schema 演化后重物化。
  • 并行维护 topic → episode → event 检索层级。
  • 提供 Lookup、Filter、Compute、Rank 四个分析工具和 SemanticMatch、EventLocate 两个检索工具。
  • planner 先生成最多三步抽象计划，再实例化参数；每个查询共享 10 单位证据预算。

论文结果

数据规模为 MemEye 221 sessions、848 rounds、438 images、742 QA；MemGallery 240 sessions、3,962 rounds、1,003 images、1,711 QA。相同 backbone 负责抽取、建表、规划和回答，temperature 为 0，结果为三次平均。

对 StreamingModelHarness 的帮助

聚合车控不应只从 top-k 候选逐项猜测。可先把重复车态和执行结果物化成 typed table，再让 Filter/Compute 在确定作用域上运行；最终执行仍经过候选授权、参数校验、幂等和最终车态验证。第一轮只做离线回放，比较“仅 RAG”与“RAG+分析表”的聚合完整率。

局限与开放状态

  • 属性抽取错误会传播到 schema、表和聚合结果；低于 4 轮支持度的字段可能被系统性漏掉。
  • 固定六工具只在记忆 QA 中验证，不能证明能消歧 52 组车控工具。
  • 未报告持久数据库、并发、删除/纠错、进程恢复、表迁移或在线时延。
  • 论文未给 Judge 的完整公式、置信区间或显著性检验。
  • 官方代码、项目页、模型权重、处理后数据和许可证：未知。

3. Zero-Mem：零 LLM-token 的记忆操作

来源：论文正文 / arXiv:2607.29377v1；作者论文所链仓库。

作者链接目前重定向到 Zero-Mem/Zero-mem，两者是同一占位仓库，不计为两个项目。

它是什么

Zero-Mem 保留原始交互 trace 作为 source of record，以实体图和时间层级组织记忆。所谓“zero-token”只表示最终问答以前的记忆操作不调用 LLM、不消耗 LLM 输入输出 token；NER、embedding、BM25、图遍历、索引和最终 reader 都仍有计算成本。

核心方法

  • 用 spaCy NER 建 entity-context 图，边包含实体共现与相邻 trace。
  • 建立 turn → window → episode → local-span 时间层级，并保留 source、session、time 和 boundary。
  • BM25 与 BGE-M3 分别建立词法和向量索引。
  • 从查询确定 subject、keyword、answer type、temporal cue 和 boundary。
  • 图路径执行实体对齐、共现传播和 Personalized PageRank；时间路径做粗到细检索。
  • 以 ρ=0.6 偏重主路径，融合、补邻居并按 provenance 去重；统一取 top-5，最后只调用一次 LLM 完成回答。

论文结果

  • LoCoMo 上，GPT-4o-mini 为 59.15 F1/52.96 BLEU-1，GAM 为 53.75/47.51；Qwen2.5-14B 为 57.57/51.41，GAM 为 52.70/46.55。
  • curated HotpotQA memory variant 上，GPT-4o-mini 在 56K/224K/448K 的 F1 为 72.07/66.43/65.04；Qwen2.5-14B 为 68.58/65.47/61.02。
  • 在 RTX 4090、GPT-4o-mini、四线程设置中，排除共享 final QA 后，Zero-Mem 为 0 LLM token、0.22s/query；LightMem 为 0.51s/query，因此论文报告记忆操作时间降低 57.6%。
  • HotpotQA 56K 消融中，完整系统 72.07 F1；graph-only 62.50，hierarchy-only 54.88，去掉 closure 为 67.90，去掉 calibration 为 70.13。

对 StreamingModelHarness 的帮助

把可弃 KV 与不可弃事实分开：车控回执、用户偏好和最终车态保留为带 provenance 的原始事件；每轮只检索当前意图需要的最小证据进入短窗 KV。它适合作为 Sparse Event-KV 的文本控制组，而不是 KV 机制的直接实现。

局限与开放状态

  • 实验是离线问答，不含在线工具状态更新、索引增长、并发或端到端车控。
  • 0.22s/query 不含最终 reader；对当前 110ms/token 链路也不是零成本。
  • 正文未报告主要结果的样本数、随机种子、置信区间或显著性检验。
  • 代码：作者仓库目前只有占位 README，承诺 peer review 后发布。
  • 自有模型和处理后数据：未发布。
  • 仓库许可证：未知。

4. Beyond Simply Environment Scaling：AES 与 HDC

来源：论文正文 / arXiv:2608.03571v1；作者官方仓库。

它是什么

该工作指出，在固定训练预算下简单增加多模态环境数量未必有效，并从能力多样性和难度结构两方面选择训练分布。它研究的是多模态 Agent 的 RL 环境，不是车控检索器或长期记忆。

核心方法

  • AES 对 200 个环境各收集 40 条轨迹，由模型和人工归纳出 72 个核心 meta-abilities。
  • 贪心选择同时奖励新能力覆盖、惩罚能力 profile 冗余和负梯度冲突，覆盖核心能力后停止，最终选择 30 个环境。
  • HDC 的外层从 H0 到 H4 逐步移除 text observation、state、hint 和 rule；内层再按网格、实体数等 state scale 加难。
  • 每个环境独立推进 curriculum；达到阈值后先扩大 state scale，再弱化 harness。

5. GROW：面向 AR-Diffusion TTS 的 on-policy RL

来源：论文正文 / arXiv:2608.03215v1；作者官方占位仓库。

它是什么

GROW 是 DiTAR 自回归扩散 TTS 的后训练算法，不是独立 TTS 服务。它在标准 flow-matching 目标上使用组内相对、带正负号的 advantage，避免把确定性 ODE 改成 SDE 和计算逐步 likelihood ratio。

核心方法

  • 每个 prompt 生成 8 个候选，以 1-WER 和 speaker embedding 余弦相似度分别作为清晰度、音色奖励。
  • 两种奖励分别组内标准化，再等权合成零均值 signed advantage；零方差组重采样。
  • 用 advantage 加权 flow-matching 回归，并以 βW2=0.025 的冻结参考速度场约束训练稳定性。
  • rollout 用 10 NFE；最终评测统一 32 NFE。反向传播仍经过完整 AR backbone。

论文结果

预训练使用约 95K 小时中英文 Emilia；RL 使用 30K prompts。测试集为 LibriSpeech-PC 1,127 条、Seed-TTS EN 1,088 对、ZH 2,020 对。

  • GROW 10-NFE 训练相对 DiTAR-GRPO 32-NFE 快 2.9 倍；这是训练速度，不是推理速度。

对 StreamingModelHarness 的帮助

短期只借鉴评测：本地 TTS 同时记录 Seed-TTS 中文 CER/WER、说话人相似度、UTMOS、人工听测、首音频 P50/P95、RTF 和打断残留。GROW 面向 DiTAR 的训练目标不能直接套到 CosyVoice，也没有证据能缩短当前约 3 秒首音频。

局限与开放状态

  • 没有 TTFA、RTF、绝对推理耗时、流式输出、推理显存或人工 MOS。
  • 奖励模型与最终 WER/SIM 评测器相同，存在对评测器优化的风险。
  • Seed EN 的 GROW-10 WER 1.763 略差于 GRPO-10 的 1.728；Seed ZH UTMOS 也略低于预训练。
  • 官方仓库目前为空；代码、checkpoint、RL prompt 清单尚未发布。
  • 许可证：未知。

6. 扩展版 DAIEN-TTS：音色、噪声与混响解耦

来源：扩展版论文正文 / arXiv:2608.03011v1；作者官方扩展版演示页；作者官方仓库。

该论文是 ICASSP 2026 DAIEN-TTS: Disentangled Audio Infilling for Environment-Aware Text-to-Speech Synthesis 的扩展工作，另立 arXiv ID。扩展版增加混响建模、cross-speaker conditioning、triple classifier-free guidance 和真实数据微调；按同一技术谱系记录，不把会议版再算一个今日候选。

它是什么

扩展版 DAIEN-TTS 基于 F5-TTS 的 masked audio infilling，将说话人、背景噪声和房间混响拆成独立条件。它既能从嘈杂 speaker prompt 中尽量提取干净音色，也能按另一个 environment prompt 合成带指定环境的语音。

核心方法

  • 两级 speech-environment separation 先分离 reverberant speech 与 noise，再分离 clean speech 与 reverb mask。
  • clean-speech mel 作为 speaker condition；noise mel 作为逐帧环境条件；reverb mask 经 ECAPA-TDNN 成为句级 embedding。
  • 用 cross-speaker conditioning 抑制环境分支泄露说话人身份。
  • 推理以 triple classifier-free guidance 分别控制 speech/noise/reverb，默认比例 1:3:6，并按环境 prompt 做 SNR 适配。
  • 24kHz、Vocos vocoder、32 NFE ODE；真实数据微调时冻结分离模块、文本编码器和 ECAPA，只更新 DiT 与环境 cross-attention。

论文结果

模拟预训练使用 LibriTTS 580 小时、DNS noise 约 180 小时和 20,248 个 DNS RIR；分离器与 TTS 各训练 600K steps、4×A100 80GB。真实数据微调使用 TITW-Hard 184.57 小时、50K steps。

  • 模拟 noisy-reverberant speaker prompt 的环境鲁棒生成中，F5-TTS 到 DAIEN-TTS-NR：WER 2.80%→2.24%，SECS 0.317→0.486，MOS 3.75±0.08→3.91±0.08。
  • 模拟环境感知生成中，F5 到 NR：CLAP 0.685→0.770，FAD 8.56→2.11，但 WER 2.80%→13.05%。环境保真和清晰度存在明显权衡。
  • 真实环境感知生成中，F5 到真实数据微调 FT：WER 12.42%→10.65%，CLAP 0.588→0.634，FAD 8.37→3.62；MOS 3.40→3.38，置信区间重叠。
  • noise guidance 从 3 增到 6 时 WER 13.05%→31.53%；reverb guidance 从 6 增到 9 时 FAD 2.11→1.48，但 WER 13.05%→25.64%。

对 StreamingModelHarness 的帮助

若目标是生成真实座舱噪声、混响和座位差异的回放数据，其条件解耦有研究价值；若目标是在真实车内扬声器播放清晰回复，则不应预先烘焙同类噪声。可先借鉴“嘈杂 speaker prompt 鲁棒性”测试，不进入在线 TTS 主链。

局限与开放状态

  • 仅英语；没有中文、CosyVoice、流式、TTFA、RTF 或绝对推理时间。
  • 32 NFE 和五路 guidance forward 带来明显部署风险，但正文没有量化。
  • CLAP/FAD 不是成熟的环境 TTS 单样本保真标准，不能替代人工听测。
  • 官方仓库只有 README、网页和音频样例；训练/推理代码、权重、处理后数据未发布。
  • 代码、模型、数据和样例许可证：未知。

今日建议路线

第一阶段

  1. 先读取 768c60e/0a1d84e 产生的 token 账本、engine time 和 phase 埋点，以“commit→search→call→车态生效→回执写回→首音频”统一 A/B/C 时钟；快照没有新数字前不更新 Pareto 结论。
  2. 对紧凑回执做 Sparse Event-KV donor-flip：显式短文本是 source of record，隐式 KV 只允许承载可枚举状态。必须加入数字、ID、近义工具和长会话反例。
  3. 为聚合意图做 AdaMM 风格的 typed table 离线对照，先测完整率，不接管在线执行。
  4. 继续 5090/H200 的无同步 MoE fast path 判别；今日论文不能替代该实验。
  5. 本地 CosyVoice2/3 先过中文 CER、首音频、RTF、显存和打断残留硬门；不运行 GROW 或 DAIEN-TTS 陌生仓库代码。

第二阶段

  1. 将 52 组近义工具和 400 条回归按能力、噪声、音色、scaffold 强度分桶，采用 AES/HDC 的覆盖思想补最弱组，而不是只看总体平均。
  2. 建 Zero-Mem 风格的外部事件对照：保留原始 provenance，比较“短窗 KV+检索文本”与“持久 KV”的 30 分钟准确率、存储和 P95。
  3. 把最终车态纳入硬门，区分 Action 产生、执行器接受和车辆真正落地，修正此前“首动作”口径。

第三阶段

  1. 若本地 TTS 的基础时延已经过门，再评估 GROW 类后训练是否值得投入；没有人工听测和 TTFA 数据前不因 WER 改善换模型。
  2. DAIEN-TTS 仅用于离线声学数据生成/鲁棒性研究；先验证噪声二次叠加和中文可懂度。

风险提醒

  • 0a1d84e、768c60e 和 22edce8 改善了观测口径，但状态快照没有给出新 P50/P90；不能把“已埋点”写成“已加速”。
  • Sparse Event-KV 同时是机会与风险：它能保存紧凑状态，也能解释为什么已删除历史仍造成上下文引力。完整参数和最终车态必须有显式、可审计的 source of record。
  • AdaMM 的全量表操作直接命中聚合意图，但抽取漏项会变成系统性表缺失；Zero-Mem 的 0 token 不等于零延迟，且代码尚未开放。
  • AES/HDC 的 143.2% 是低基线上的多模态 RL 相对增益，不能外推为 52 组工具的成功率提升。
  • GROW 和 DAIEN-TTS 都没有首音频、RTF 或在线流式结果，不能解决当前约 3 秒首音频；两者当前也没有可运行的官方实现和权重。
  • 今日仍未发现新的 AEC/降噪、真正在线语义判停、MoE 解码内核或可直接接入的全双工模型。前一日的 AEC/LMPAN→因果 NS→判停、M3 多轮回放、Cocktail-Talker 受话对象门和本地 TTS 路线继续有效。
  • Beyond Retrieval 的重复条目、Zero-Mem 的仓库重定向和 DAIEN-TTS 的会议版/扩展版已按技术谱系去重；社区 PersonaPlex .NET 封装、课程仓库、Arduino 新闻和信息不足的模型镜像不进入主清单。
