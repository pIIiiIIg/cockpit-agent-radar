方向：解码时延 — FlashDrive（当前单 token 解码约 110ms，根因是 HF MoE 每 token 约 816 次 GPU→CPU 同步；而 StaticCache 此前按“KV=2500 时只省 0.2ms 拷贝”被判定不值得；它在 10B 驾驶 VLA 上把 static KV cache + 算子融合 + 对整个解码循环做 torch.compile/CUDA Graph 作为一个不改算法的系统层捆绑，解码从 271.7ms/56.4 tok·s⁻¹ 降到 170.6ms/89.5 tok·s⁻¹、整机 716.9→513.3ms；可以尝试把 StaticCache 从“省一次拷贝”重新定位成“让形状固定、从而可被图捕获”的前置条件，顺序是先落项目既定的 index_select+bmm 无同步 fast path、再把整循环图捕获作为第二个独立变量测——两步必须分开测；同时写死三条边界：那 1.59× 是捆绑结果没单独消融图捕获，同一表里 prefill 反而从 165.3 变差到 188.3ms，而且 z-lab/Alpamayo-1.5-10B 的 expert_cfg 指的是动作专家不是 MoE 路由，本轮没有任何一篇给到项目 MoE 同步问题的证据）

方向：ASR 无损加速 — 单模型自投机解码的对齐漂移（当前 A 版 ASR 占 183/248ms 前置时延，且该段从没有过“能不能不动 WER 变快”的一手依据；arXiv:2608.12703 在贪心验证下输出与自回归一致，给目标模型挂轻量 draft 头并让它每步交叉注意冻结音频编码，Qwen 1.7B 端到端 1.41–1.55×、Voxtral-Mini 3B 1.42–1.69×，continuation 接受率因“每步能看音频”大致翻倍，晚期 draft 锚点中位误差 21 帧而验证期只有 2 帧；可以尝试的只有一件零成本的事——把 A 版 ASR 的计时口径显式写成起点终点并标注是否含预处理与音频编码，与论文“从波形开始”的口径并列，为将来任何 ASR 加速留可比基线；本轮不进候选：无公开代码权重、需训练 draft 头，且它自己的反例是完整 0.6B 识别器 draft 接受率近乎完美却只有 0.59–0.70× 自回归速度，这与项目已否决的“投机预取”不是同一件事，但同一条成本条件）

方向：判定器审计 — 处理泄漏与构念效度（当前 452 条判定链路里方案名 A/B、候选集版本、音色、SNR 档标签都可能被判定逻辑读到，而 80.49% vs 79.27%、净修 +4 这类结论全都建立在判定器可信之上；arXiv:2608.12880 自审前作发现判分器把 treatment 元数据直接接进 ATTACK_SUCCESS 的门控条件，固定住已执行行为、只改元数据就有 31 条标签翻转，按只依赖行为证据重建后 180 条请求中攻击成功由 70 条历史标签变成恰好 0 条、其中 58 条其实是授权内正常完成，作者原话“可复现没有阻止这个错误，它让错误可以被精确复现”；可以尝试对项目判定器做同样的处理不变性检查——冻结执行证据、只改无关元数据、重算判定、逐条记录是否翻转，并补一份“判定器不得读取哪些字段”的排除清单，任何翻转先修判定器再谈 +1/+4，这件事不需要 GPU 且优先级高于本轮其它一切）

方向：降噪前端选型 — HybridSB-MoE 与流式代价的量级（当前只有 clean/20dB 两档合成音频且未分桶归因，08-13 已定下“时延有界 + 状态固定 + 1 帧进 1 帧出”的前端硬要求但不知道坚持它要付多少代价；它是谱域异质 MoE 加波形域薛定谔桥的双域非对称融合，K=8 步、top-k=2，在 VoiceBank+DEMAND 上 PESQ 3.88 全表最好、RTF 0.28 自报 35ms，而 08-13 记的流式 RT-SEMamba 在同一份语料上是 8 层 3.32 / 蒸馏 1 层 3.18；可以尝试把“坚持因果流式约付 0.5–0.7 PESQ”记为量级先验，用来说明流式代价可承受、不必为排行榜放弃因果性，但四条免责一条不能少——两篇评测协议不同不可直接相减（它自己复现的 SEMamba 是 3.55），它全文没有因果性声明也没有逐帧算法时延、35ms 是整句口径，只有 PESQ 类过程量没有下游 CER，英文单通道无中文无车内无 AEC；本轮不引入前端，仍先做快照里已写明的 clean/20dB 分桶归因）

方向：TTS 候选的开放状态更正 — Luna-TTS 项目页由 404 变 200（当前 omnivoice-local-tts-16step-v1 的处置依据里包含“Luna-TTS 项目页 08-13 复核 404、无任何公开制品”这一条；2026-08-14 复核同一地址返回 200，页面含完整基准与推理表，比论文多两行——16 步 2×H20 并行 CFG 首音频 63.8ms/整句 451.4ms/RTF 0.0426，32 步全网格 419.6ms/RTF 0.0410，并在 Seed-TTS-Eval 表里把 OmniVoice 0.6B 记为 zh CER 0.84 / zh SIM 77.7 / en WER 1.60 / en SIM 74.1 且明确标注“取自该系统自己的报告”；可以尝试把“一次 404 不足以永久判定无制品”写进复核纪律并按 30 天节奏重查，但候选处置不变——整页唯一外链仍是 arXiv，没有代码、权重或许可证，而且页面自身矛盾：摘要写 Realtime 按 1.28s 块自回归，同页推理表脚注却写“首音频 = 引擎调用到第一个解码完成的 0.36s 块”，在首块时长澄清前其 41.6ms 不可用于任何跨系统首包比较）

方向：候选流程与验收协议 — AutoDesign 的单变量接受门（当前项目有 composition queue 与零退化规则，但没有“开发集分数不回传给提出候选的一方”这层隔离，+1/+4 量级收益存在被反复调到刚好越线的风险；它规定外层每次迭代只允许改五个组件中的一个，接受条件是训练集严格提升且开发集不降，且开发集分数从不展示给优化器，同时诚实报告自己的自动分与 933 条人评的 Pearson 只有 r=0.34 [0.22, 0.44]、分差 0–3 分时人机一致率仅 51.9%（约等于抛硬币）、要到分差 ≥20 才升到 74.4%；可以尝试从 452 条切出一个只用于最终验收、从不用于挑选调参、且分数不进入候选生成上下文的固定留出片——它的 r=0.34 与 08-13 从 DuplexWorld 得到的“harness 旋钮与换系统同量级”是互补的两条，合起来的结论是 +1/+4 不得单靠总分判定、必须靠逐条零退化比对，这正是项目 414 canary 规则的外部背书）

方向：组合验证的纪律 — Capability Sheaves 的自报失败（当前项目规定组合前必须做 interaction/zero-regression、不能把局部数字相加，但缺一个可引用的失败模型与“多大差异才算证据”的量级；它把“各子系统看起来都称职、但对共享状态（文件路径、API 版本、源提交、测试标识）的取值对不齐”建模成有限层的局部到整体失败，然后在 20 个真实仓库、160 个 issue、875 个候选补丁上诚实宣布失败——解决 118 个 vs 匹配基线 116 个但跨仓库符号翻转检验 p=0.75，弃权门 127/160 只比匹配门多 1 个、p=1.0，据此宣布发现门未通过并封存确认集；可以尝试借用“预先声明门槛 + 未通过就封存、不做事后挑选、不换分层重看”这套纪律，并把“+2 不构成证据”当作具体量级参考——项目对应的共享状态是 RAG 候选、模型 typed call、执行器参数校验与最终车态四者对“哪块屏/哪个座位/哪个温度目标”必须一致；不引入层上同调，不进候选）

方向：KV 服务优化的边界 — vToken 判为不适用（当前容易把 KV 相关的加速工作默认为可用；它在 vLLM 里加一层 token 级虚拟化打通 token 级驱逐与块级管理之间的碎片，相对配对基线把满足 SLA 的吞吐提升最多 1.37×，但论文自己写明“当 KV 显存不是瓶颈时原生路径仍更可取”；项目是 batch=1、KV 约 2500 的单请求场景，快照已判定该规模下影响可忽略，且它优化的是吞吐而项目的门是单请求 ms/token 与首音频，与 08-12 记的 OasisKV 属同一类反例，直接判不适用；唯一可转移的一点是它把“保持 PagedAttention kernel 与 CUDA Graph 兼容性”写成硬性设计约束，与 FlashDrive 同向，可归纳出一条筛子——推理侧任何改动先问“它是否破坏图捕获兼容性”，而项目的 .nonzero() + GPU 标量比较 + torch.where 正是破坏项）

方向：流式长时记忆 — StreamTTT（当前项目没有跨轮长时段座舱上下文的设计方向；它在 Qwen3-VL 每层并联一条测试时训练的快权重分支承载长程历史、把历史移出注意力上下文，每层状态固定上限大小、与已处理 token 数无关、分块运行可复现单趟连续运行，OVO-Bench 两轨平均 68.59 对 SimpleStream-4B 的 66.06；可以尝试把这个形状记为长时记忆的设计方向——它与 08-13 从 RT-SEMamba 归纳的前端形状一致，说明不是降噪领域特例；但强否定同样明确：一篇标题写“实时感知”的论文全文没有任何时延、首 token、逐帧耗时或吞吐数字，连 GPU 型号、chunk 大小与滑窗长度都没写，它的“实时”实质只是 2 fps 帧率与 4K–64K 上下文预算；作者另自报 64K 下加 TTT 反而更差 65.6 vs 纯滑窗 66.8，且首页标注“进行中的工作”、代码只有一句“将会发布”无地址）

方向：工具/Action 通道 — PIPES 的来源标注（当前 B 版把 CarSim 回执直接送进 KV，没有“这一段由谁产生、它有权断言什么”的标注，纯仿真下不构成风险；它指出工具回执里不同字段由不同信任级别的主体产生，攻击者可在自己有权填写的字段里做出超权限的环境断言从而污染 agent 感知，使后续动作在只看“动作是否与感知一致”的护栏面前显得合理，在两个模型上把平均攻击成功率由 84.7%→2.3% 与 21.6%→1.1%；可以尝试的只有一条最小预留——车控与外部回执格式里预留来源字段，并区分“可机检的确定值”与“开放词表描述”，等真正接入导航 POI、音乐元数据、充电桩这类第三方源时才需要；不进候选：无单变量、无可测预计净修数，且它全文没有任何时延或开销数字，只说明每次评估一次 LLM 调用，而项目首动作预算只有 700–1094ms P50）

方向：回声消除 — 连续第二轮无重大新增（当前 AEC 与扬声器泄漏仍完全没有一手依据；本窗口去重 45 篇里 cs.SD 只有 3 篇、eess.AS 只有 2 篇，没有任何一篇报告 AEC 或扬声器泄漏的一手结果；继续跟踪，不写任何 AEC 结论或预期）

方向：持续跟踪不重启的项目（Qwen3-Omni MoE 无同步 fast path 仍是本周期唯一的解码时延实验，本窗口没有任何针对 HF MoE 单 token 路由同步的新工作——FlashDrive 的 expert_cfg 是动作专家不是 MoE，不要误记；PACE 的 GCM-Bench 仓库最后推送仍为 2026-08-11，中间件本体仍未公开，playback-boundary-ledger-offline-v1 不受影响；RT-SEMamba 的 RoyChao19477/RT-SEMamba 2026-08-14 复核仍是空仓库（size 0）；SmartGlasses 的 ASLP-lab/Smart-Glass-Challenge 仍是 26KB、无 LICENSE；X2-Turn 代码权重仍未公开，可用的仍只有 mistralai/Voxtral-Mini-4B-Realtime-2602 与 ASLP-lab/Easy-Turn-Testset；candidate-ID/CMTF、conditional top-2 verifier、投机预取、工具清单压缩、主模型自判停的负结果不重跑；参数化本体、云监督与 SoulX 不重复启动）

今日新增 handoff 候选：1 条，decode-loop-cudagraph-static-kv-v1（仅离线、h20_request_allowed=false）。它的单变量是“在已落地无同步 fast path 之上，是否对解码循环整体做 CUDA Graph 捕获并配固定形状 KV 预分配”，依赖是项目既定的 index_select+bmm fast path 必须先单独测完，且两者不得合并成一次结论。其余六条新方向都缺“可执行单变量 + 可信预计净修数”，只留在报告：ASR 投机解码无公开代码权重且需训练 draft 头；HybridSB-MoE 无任何公开制品且先天不满足因果流式；判定器不变性检查、留出片与预先声明门槛属评测建设与流程规范；Capability Sheaves 自报真实世界优势未被支持；vToken 判为不适用；StreamTTT 与 PIPES 都没有任何时延数字且无可用制品。既有 omnivoice-local-tts-16step-v1、tool-hold-message-first-audio-v1、playback-boundary-ledger-offline-v1 全部保持仅离线、h20_request_allowed=false。
