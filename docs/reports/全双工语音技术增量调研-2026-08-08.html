全双工语音技术增量调研｜2026-08-08（补跑）

补跑与证据边界

8 月 8 日原计划精读三班均因自动化工作树脏而在 Agent 启动前失败，日报也未生成。本报告于 8 月 9 日按缺失日期顺序补跑。全文条目实际在 8 月 9 日读取并保留真实 reviewed_at； catchup_for=2026-08-08 只表示补哪一个调度缺口。摘要抓取、GitHub README 或论文列表均不计 全文精读。

本批与问题最相关的正文为 DMV-Bench、Plover、MulRobBench、UEmbed、PIMiner 与 StreamArena。它们分别支持可审计记忆、版本化计划、安全动作契约、检索表示、晚工具注入红队 和流式前台/异步记忆设计，但都没有在 StreamingModelHarness 上证明收益。

StreamingModelHarness 当前进展与问题

  • pure-audio 同口径：baseline 414/452，expected tool 进入候选 443/452。
  • 38 个失败：召回缺失 9；候选已出现但选错 25；候选已出现但 no-call 4。
  • complex122：14/122 全约束通过；序列 6.56%，最终态 21.31%。主要矛盾不是简单不调用。
  • candidate-ID/CMTF 是负结果；两次 action-safety formal452/122 与父基线准确率相同，

    • runtime trigger=0。强制 ID 既不能修召回，也会掩盖歧义与 no-call，禁止重复推荐。

  • SoulX 判停、参数化本体与云监督由独立分支运行；本闭环只消费其公开结果 manifest。

问题—证据—候选—实验门

P0：25 个候选内选错

项目证据：expected tool 已在 seen_tools，说明仅扩大 top-k 或重复检索不足以解决。MulRobBench 正文把标准动作、安全替代、禁止动作和严格解析分开；Plover 要求计划修订显式、已执行前缀不可 静默改写。

候选：条件式 Top-2 Tool Verifier。单变量是“只在低分差且属于冻结混淆族时执行二选一 verifier”；高分差、不在混淆族或证据不足时保留原选择。输入只允许音频派生文本、现有候选和 公开工具 schema，禁止 manifest 真值与强制 candidate-ID。

离线门：冻结 414 canary 零退化；25 条中至少净修 16；trigger≥16；闲聊和危险误调用零新增； P95 增量≤25ms。未满足即 rejected，不消耗 H20。

H20 门：相同 baseline、配置和 audio/tool/hash；pure_audio smoke→quick→full452→complex122；full452 净修≥16，危险误调用=0，complex122 不退化。

P0：9 个召回缺失

项目证据：expected tool 不在 seen_tools。UEmbed 表明稠密/稀疏表示可在同一因果骨干生成， 但未报告本项目工具检索收益；DMV-Bench 表明双空间保存原证据优于只保留 caption；这些是方法 启发，不是项目实测。

候选：守卫式高精度规则记忆，仅对稳定别名/同音规则做展开并保留证据指针。理论上最多修 9， 低于“净修≥16”默认昂贵门，因此即使 9/9 离线召回也先登记研究性局部结果，不进 H20。它也不 与正在运行的参数化本体或 PORTS 式训练合并。

P1：4 个候选内 no-call

不允许用“命中就强制调用”处理。应先区分闲聊/拒绝、模型犹豫、参数缺失和执行协议失败。 MulRobBench 的弃权/禁止动作分离可用于诊断；没有清晰单变量和 ≥16 修复空间，本日不生成昂贵 候选。

P1：complex122 规划

Plover 的“已完成前缀不可改、待执行后缀可重规划”和 MASS 的权威 typed state 对复杂意图有 研究价值。但参数化本体正在独立实验，本班不重复启动；先等待其结果 manifest，再决定互补的 状态/计划单变量。

P2：判停与云监督

SoulX 为 endpoint 专项且正在独立评测；本闭环只要求回写停止理由、延迟和负结果。云监督同理， 不得把不同 baseline、不同输入或组合提升归到本日报候选。

今日路线与研究价值

  1. 发布两个结构化候选；守卫式规则记忆因理论上限 9，预期离线后拒绝昂贵评测。
  2. 优先实现条件式 Top-2 verifier 的离线回放；只有 414 零退化且净修≥16 才进入动态 GPU 池。
  3. 每个负结果回写 Solutions/Negative Results，并把“召回、候选内决策、no-call、参数/最终态”

    4. 分层作为稿件章节贡献。

  4. patent 字段只发布贡献标签，不公开独立专利分支的未申请实现。
