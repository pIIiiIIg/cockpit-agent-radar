全双工语音技术增量调研 · 2026-08-03

全双工语音技术增量调研 · 2026-08-03

核心判断

最近三天最值得进入工程队列的不是又一个通用聊天模型，而是四类基础能力：

  1. 评测：M3-DuplexBench补多轮、多语言、多领域和固定上下文公平比较。
  2. 流式视觉：Mage-VL利用codec事件稀疏化持续视频，适合作为视觉事件门。
  3. 音频前端：faster-enhancer.c提供可落车CPU的常开降噪运行时。
  4. 外部记忆：Voice Memory、AdaMM、ReflectWorld-MM分别处理ASR规则、结构化分析和实体视频记忆。

M3-DuplexBench

M3-DuplexBench从连续对话中提取SHIFT、PAUSE、BACKCHANNEL和BARGE_IN事件， 覆盖英语/日语、闲聊/多轮QA，并比较三种历史条件：

  • 无上下文
  • 只有用户历史
  • 用户与系统完整teacher-forced历史

完整历史通常降低轮替延迟，但对领域和模型的效果并不一致。这说明全双工模型的 “什么时候说”不仅由当前音频决定，也会模仿历史对话节奏。

对StreamingModelHarness的落点：

  • 将现有8轮测试扩展为固定完整上下文；
  • 分别测跟随指令、指代、打断后恢复、KV裁剪和逐轮延迟；
  • 为Qwen流式KV实现M3 adapter，而不是直接照搬Moshi输入格式。

Mage-VL

Mage-VL不均匀抽取完整视频帧，而是复用H.264/HEVC等codec的信息：

  • I帧保留完整patch；
  • P帧只保留运动向量/残差表明真正变化的区域；
  • System 1轻量事件闸门决定何时唤醒System 2的Qwen3-4B推理。

论文报告视觉token减少超过75%，最高获得3.5倍墙钟加速。

对座舱：

摄像头持续流
  → codec动态区域/事件门
  → 只有乘员手势、视线、上下车、危险事件才写入视觉KV

这比固定每秒抽帧更适合长期在线助手。

faster-enhancer.c

这是FastEnhancer-Medium的固定模型专用C/int8运行时：

  • 48kHz，320样本一帧，6.67ms deadline；
  • 无look-ahead，固定约14.67ms STFT对齐延迟；
  • 启动后无堆内存分配；
  • Apple M2单核RTF 0.069，Galaxy S23+ RTF 0.096；
  • 相对fp32仅损失约0.006 PESQ。

建议链路：

扬声器参考+麦克风 → AEC/LMPAN → faster-enhancer NS
→ RMS/FastTurn/SoulX → ASR/Qwen

它负责噪声增强，不负责消除助手扬声器回声，因此不能替代AEC。

Voice Memory

Voice Memory不训练新权重，而是维护每个领域的可审计memory.md：

  • Listener按记忆判断应纠正ASR还是保留1-best；
  • Thinker异步提出有限规则修改；
  • 只有保留集分数严格改善才接受修改。

结果：十个领域加权WER从8.36%降到7.52%，ATIS命令域从8.40%降至约3.4%， 同时显著减少过度纠错。

适合把车控反复错误沉淀为受门控规则：

  • 副驾屏→副甲品
  • 吸顶屏/顶屏同义
  • 车型专有功能名
  • 座位与部件简称

AdaMM与ReflectWorld-MM

AdaMM认为相似度检索不适合回答“最近一周出现几次、趋势如何、谁最常做”。 它自动归纳重复属性并物化为表，同时保留topic→episode→event语义图。

ReflectWorld-MM围绕长期实体而非帧组织视频记忆：

  • 有界短期感知；
  • 多尺度情节记忆；
  • 演化的实体语义记忆；
  • 程序记忆；
  • 持久数据库与证据回溯。

二者可共同解决座舱KV无限增长：

短期语音/视觉 → 当前KV
重复偏好/车况 → AdaMM分析表
乘员/物品/事件 → ReflectWorld实体记忆

iFLYTEK-Embodied-Omni

该模型把VLM和视频生成作为高层“脑”，把Action Generation Model作为“小脑”， 通过共享注意力协作。其机器人动作空间不能直接用于车控，但分层思想适用：

Qwen/Omni：理解、规划、未来状态预测
确定性VAL/Executor：schema、权限、前置条件、幂等、状态提交

模型报告LIBERO-Plus零样本平均成功率89.6%，RoboTwin 2.0约93%。

OmniVideo-100K

数据引擎先生成主实体、全局摘要和分段音视频脚本，再从跨段线索生成QA与证据链， 避免声音与画面分开caption后失去对应关系。

  • 5,214个视频；
  • 100K音视频QA；
  • 505条人工核验测试；
  • Qwen3-Omni-30B微调后OmniVideo-Test提升约13.86%。

可用于构建“乘员说话+手势+车外事件+车辆状态”的座舱联合数据。

ARDena

ARDena用Prompt Construction Engine组合：

  • 持久用户上下文；
  • 当前场景约束；
  • 交互状态；
  • 当前允许工具。

适合定义驾驶、驻车、儿童在车、充电、休息等模式。需要强调：prompt控制不是安全 证明，真实车控仍需确定性Policy Gate。
