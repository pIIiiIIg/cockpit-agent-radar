项目实测事实

本轮没有任何新的项目证据。以下数字全部沿用已记载的同一批结果，不是今天产生的：

  • 2026-08-03 H20 公平对照使用 audio_index.jsonl 中完全相同的前 100 条音频（82 条车控 + 18 条日常对话）。A/B 严格工具召回/执行成功率 80.49% / 79.27%，100 条样本下置信区间高度重叠；日常对话误车控均为 0%；RAG Recall@24 为 98.78%；ASR micro CER 6.39%。
  • A/B 时延 P50/P90：ASR 完成 183/248ms（仅 A）；RAG 完成 227/315ms（仅 A）；首文本 758/1,006ms 与 131/141ms；首动作 1,094/1,440ms 与 700/850ms；首音频 2,918/3,453ms 与 3,491/4,171ms；整轮结束 2,945/4,224ms 与 3,576/4,246ms。项目结论是 Edge TTS 而非 Qwen 首 token 构成约 3 秒首音频的主要瓶颈。

  • DynamicCache.update() 的 torch.cat 在 KV=2500 时约 0.2ms，项目判定当前规模下 StaticCache 不值得；08-14 已为它补了一个不同性质的理由（图捕获前置条件），该结论本轮不变。

核心方法（仓库确认与新增的实现细节）

论文侧方法 08-13 已记录，不重复。以下是仓库公开后才可核实、论文正文未给出的实现级事实，全部来自 README 与 recipes/KD1/KD1.yaml 文本：

  • STFT 配置：sampling_rate: 16000、n_fft: 400、hop_size: 100、win_size: 400。即 25ms 分析窗、6.25ms 跳步、160 帧/秒。README 说明 STFT/iSTFT 两侧均为 center=False，算法时延因此被一个 25ms 窗界定。
  • 因果化改动逐项：卷积用非对称因果 padding（左侧补 K-1 个零、右侧不补，_get_causal_padding_2d）；InstanceNorm2d 换成沿时间因果的 ChannelLayerNorm2d；时间轴 Mamba 单向、无前瞻；频率轴 Mamba 仍是双向（README 原话：“the frequency axis is not a causal axis”，与 08-13 从论文记下的一致）；每个 cTF-Mamba 块后额外加一个 MLP。
  • 三个固定大小的推理状态被点名：帧缓冲（保存因果时间卷积所需的前 K-1 帧）、conv_state（SSM 前深度可分离一维卷积的 d_conv - 1 步）、ssm_state（循环隐状态 h_t）。切换接口是 SEMamba.set_streaming(True)，跨句清理是 reset_streaming_state()。
  • 两种流式模式：--streaming_mode realtime 为一帧一次前向，chunked 为整块一次前向；--chunk_size 默认 1600 采样（100ms @ 16kHz）。inference_KD1.sh 的默认组合是 --streaming True --streaming_mode realtime --chunk_size 1600。
  • PCS 后处理默认关闭：--post_processing_PCS False，KD1.yaml 中 use_PCS400: False。
  • KD1 模型配置：hid_feature: 64、compress_factor: 0.3、num_tfmamba: 1、d_state: 16、d_conv: 4、expand: 4、输入 2 通道（幅度 + 相位）、输出 1 通道。
  • 训练配置（用于估计迁移代价）：1,200 epoch、batch 2、segment_size: 40000（2.5s @ 16kHz）、AdamW、初始 lr 5e-4、默认 2 GPU；蒸馏 lambda_out: 0.5、lambda_feat: 0.1、ramp 为前 10% 步数、教师块输出取 8 层均值、两侧逐样本归一化，并在前 2% 步数冻结由教师初始化的 dense_encoder/mask_decoder/phase_decoder。

对 StreamingModelHarness 的帮助

这是自 08-13 定下前端硬要求以来，第一个可以真正落到离线对照上的前端。分三层说。

第一层，它同时满足了此前分开出现的两个条件。 08-13 定的形状硬要求是“算法时延有界且写明、状态为固定大小、1 帧进 1 帧出不重算历史”，RT-SEMamba 论文满足形状但没有制品；08-14 的 HybridSB-MoE 有更好的 PESQ（3.88）但先天不满足形状且同样没有制品。今天 RT-SEMamba 补齐了制品这一半：MIT 许可、两份权重直接在仓库里、inference.py 与 rt_enhance.py 都是可读的完整实现而不是占位。08-14 写下的“坚持因果流式约付 0.5–0.7 PESQ”这条量级先验因此从纸面判断变成可验证命题——项目可以在自己的音频上直接比。

第二层，CPU/MPS 推理路径改变了这个候选的部署算术。 08-13 与 08-14 都写过同一条反对意见：RTF 0.11–0.29 是在 RTX 5090 上测的，前端要与主模型抢同一张卡。仓库公开后，mamba_install_mps 提供了跳过 CUDA 编译的纯 PyTorch 路径，README 支持矩阵把 CPU 与 MPS 的推理都标为可用。编辑判断：如果 KD1（1.05M 参数、20.56 GMACs/s）能在座舱主机的 CPU 上实时跑，前端就不占用主模型的 GPU，整个候选的成本结构完全改变。但这是假设不是结论——见下方局限。

第三层，时延记账必须用三个数而不是一个。 项目若把它放进首动作/首音频预算，需要分别记：(a) 模型算法时延 25ms（设备无关，由 win_size: 400 与 center=False 界定）；(b) 管线块长，默认 --chunk_size 1600 即 100ms，可配；(c) 实测每帧墙钟耗时，取决于后端与硬件，项目必须自测。把这三个混成“25ms 前端”会低估真实增量约 100ms 量级，而项目的首动作 P50 只有 700–1,094ms。

可执行实验（本轮唯一新增候选，streaming-se-frontend-rtsemamba-kd1-v1）：在快照既定的 clean/20dB/音色分桶归因完成之后，以“是否在 ASR 前插入 KD1 流式前端”为唯一变量，冻结其余一切（模型权重、提示、RAG、候选工具集、执行器、TTS、endpoint），在 452 条上离线对照，分桶报告 ASR CER 与严格工具召回，单独报告新增时延与 414 canary 退化数。

风险提醒

  1. 不要把“RT-SEMamba 发布代码”读成“可以上前端了”。 它今天获得的是可验证性，不是有效性。全仓库没有一个下游 ASR CER 或工具正确率数字；“PESQ 3.18 能让车控更准”在今天之后依然是零证据的推测。分桶归因没做完就上前端，会同时改变噪声致错与理解致错两类误差，且无法归因。
  2. 25ms 不是它给项目增加的时延。 25ms 是由 win_size: 400 与 center=False 界定的模型算法时延；inference_KD1.sh 的默认管线块长是 --chunk_size 1600，即 100ms；实测每帧墙钟耗时另算。三个数必须分开报，混成一个会低估约 100ms 量级，而项目首动作 P50 只有 700–1,094ms。
  3. “支持 CPU/MPS”不等于“CPU/MPS 上能实时”。 README 只给了 RTX 5090 上的 RTF，并明确声明不对其它设备作保证；CPU 与 MPS 的 RTF 未知。且 MPS 上因固定约 32ms 的每次调用开销，rt_enhance.py 改为按 100ms 块整批前向，逐帧性质在该后端实际被放弃——这与 08-13 定下的“1 帧进 1 帧出”硬要求在该后端上不再成立。
  4. 它的 MIT 不是普通 MIT。 LICENSE 附带两条强制条款：所有副本必须包含指明基于 MP-SENet 与 CMGAN 的致谢声明，再分发必须保留该致谢。若日后有任何形式的分发，这是实际义务。另外 GitHub API 的 license 字段本周第三次报 NOASSERTION 而实际文件是明确许可证，一律以文件为准。
  5. 权重在 git 仓库里而不在 HF，且没有 releases/tags。 这意味着没有版本化发布，HEAD 随时可能变动而无版本号可引用。项目若要做对照实验，必须记录使用的 commit SHA（当前为 0c9e8c7c42），否则实验不可复现。
