1.6 最重要的一条限定：归并的方向是"多召回"，不是"漏召回"

必须把这条写清楚，否则本节会被过度解读。 词干归并让一个查询匹配到更多文档，从来不会让它匹配到更少。因此：

  • 此前所有记录为 totalResults = 0 的零结果，全部仍然有效。 一个被人为放宽了的查询若仍返回零，那个零比原本更强，不是更弱。08-13 以来 AEC 的十轮为零、空间听觉的连续为零、流式 ASR 的连续为零，都不受本节影响。
  • 受影响的是精度，不是召回。 此前记录的"某组返回 N 篇、N 篇全是假阳性"这一整类观察，现在有了机制解释。
  • 因此"全双工组存在系统性盲区"这个结论只有一半被解释。 该组的噪声来源清楚了（interruption 一词就带来 2,491 篇全库量级的词干污染，且 08-21 该组返回的 3 篇假阳性正是 abs:"interrupt" 族最新的 3 篇：2608.19893、2608.19887、2608.19622，逐条吻合）。但"漏掉真正的全双工进展"这件事，词干归并解释不了——归并只会多给，不会少给。两个缺陷必须继续分开记录：精度损失已归因，召回损失仍未归因。
  • 同理，interrupt 词根的三个假阳性（并行机排程、统计学 "Interrupted Time Series"、2608.19893 "Interrupting the Loop"）应从"三次巧合"改记为"一个机制的三次显形"。

五个动了的仓库，五次全是 README / 引用编辑，四次集中在同一个 34 小时窗口内。 一条以 pushed_at 前移、star 增长、或"README 里出现了 arxiv"为触发条件的流水线，本轮会报出四到五个假阳性——其中最危险的一个是把 Thinkingbox 新增的论文链接读成"发布产品不发布实验"这个形态被打破，而它的制品关键词命中数全部仍为 0。

三条配套的扫描陷阱，全部来自本轮实测：

  1. star 数可以在代码零变化时暴涨。 EnvHarness 9 → 104，11.6 倍，同期只有一次 README 标题修改。
  2. 架构支持的 grep 必须限定目录。 FlashPrefill V2 全树搜 sm_?120 有 23 处命中，23 处全部在 csrc/cutlass/include/ 下的第三方 CUTLASS 头文件里，没有一处在 flashprefill_ops/instantiations/ 下。不限定目录就会把"厂商头文件里提到过 sm120"误读成"新增了 sm120 支持"。

  1. 瓶颈不对。 项目 blocker 是每 token 约 816 次 GPU→CPU 同步，根因是主机同步。本篇对 synchroniz / cuda graph / kernel launch / launch overhead / host-side / d2h / h2d 命中数全部为 0。它优化的是卸载条件下的显存带宽与专家流量——另一个瓶颈。而在 H20 上这四个模型都不需要专家卸载，因此它所利用的机制在项目服务端硬件上根本不存在。
  2. 收益是显存饥饿的函数，且随饥饿缓解单调衰减。 平均加速比 2.500（16 GB）→ 1.926（32 GB）→ 1.718（64 GB）；唯一的"装得下对装不下"受控对照（DeepSeek/HumanEval）从 3.76× 崩到 1.65×。外推到完全不需要卸载的设备，所剩不多。5.3× 这个头条在 H20 上不可达。

  • 缓存命中陷阱在本篇清除，方向还是有利的。 唯一相关段落写明现有卸载方法"their ideal operating regime corresponds to scenarios with high cache hit rates. 3.3 2608.06718 v2 —— 既有判定不变，但措辞需要收紧，而且这次修订正好修掉了一处旧矛盾

判定不变：不得把音频语言模型当作打断/情绪恰当性的自动判定器。 证据基础完全没动。Table 7 的原生 POINTWISE / No-Cue 一档是决定性的：11 个判定器里只有 Gemini-3-Pro 一个的置信区间排除了 50%，而且只是勉强排除（55.2 [50.1, 60.1]）。 其余全部统计上等于随机，含全部开放模型；Qwen2.5-Omni-7B 恰好 50.0。Table 6 的协议差（配对 bootstrap 95% CI）显示 Gemini 家族从对照式格式获得 +21.3 到 +29.2 分，而每个非 Gemini 模型的区间都包含零。

但措辞必须收紧，因为论文比"一律禁止"要窄。 最直接支持该判定的原句是：Cueing is a diagnostic intervention, so a judge whose conclusion depends sharply on prompt wording may be useful in a scaffolded pipeline, but should not be treated as a plug-and-play evaluator. 以及 similar aggregate accuracies can hide different failure modes ... 因此被支持的判定是："不得把音频语言模型当作即插即用的判定器"，而论文明确留下了"在有脚手架的管线里可能有用"这一条——而那正是 PAIRWISE 下 Gemini 家族达到 74–91% 的地方。这条区分值得保留，因为它指向一个可用设计而不只是一条禁令。

两条不可忽略的迁移限制：审计只有英语，且作者自陈relies primarily on synthesized speech ... it limits external validity。另有一条对中文部署尤其不利的构造效度提示：最低的单轮得分来自非母语英语者，即该基准的题目对听者母语背景敏感。开放状态为第三档：只有将来时的 will be released，全文没有任何作者制品 URL（唯一裸 URL talkarena.org/cava 是第三方源数据集，30 条注解 URI 全是参考文献）。

一处残留的轻微歧义，原样并存：v2 说"nine students"，同时又说每个任务"five independent annotators"、而任务有两个（十个标注位），附录表也列 5 名标注者。九人填十位意味着有一人兼做两个任务，论文未说明；v1 的"ten"在这一点上是自洽的，即这次更正引入了该歧义。

四条可带走的原语：

  • 反事实审计的构造方式，是本轮三篇里对项目最高优先级事项最直接可用的一条。 固定转写文本不变，只改与被测行为相关的那一个通道，要求判定器随之翻转。这正是项目那个"只翻转与行为无关的元数据即改变 180 条中的 31 条"实验的正向推广版，而造一套中文的打断恰当性反事实集是一个自足、可立刻动手的后续项。
  • POINTWISE 对 PAIRWISE 的协议差本身就是一件诊断量具。 任何只在两个候选同时可见时才表现良好的判定器，都不在测量它的聚合分数所暗示的那个东西。做起来便宜，而它检出了单看准确率会被掩盖的失效。
  • (P, O, J) 三态分解，尤其是"Potemkin"这一态——感知与响应映射都过关、最终判断仍失败。这给项目一套给自己判定器失效分类的词汇，取代单一召回率。

八、方法学固化（本轮新增，建议写入长期规则）

  1. abs: 做词干归并。 任何单词探针实际匹配的是它的词干，因此：不要用"删掉某个宽泛单词"来提精度（无效）；缩略词若以 S 结尾会被剥成另一个词（TTS→tt）；短语内的成分词同样被归并（echo cancellation = echo cancel）。提精度的唯一有效手段是改用多词短语。
  2. 归并只会多召回，不会少召回。因此所有历史零结果依然有效，受影响的只有精度。 不得用本发现去回溯质疑任何一条已记录的零结果。
  3. 每次改写查询都必须做同窗口 A/B 并记录两个总数。 本轮正是靠 A/B 才发现 08-21 的建议无效——若只换写法不做对照，会把"改写生效"当成既成事实带进后续若干轮。
  4. 提出一个新查询词时，先测它的全库 totalResults。 abs:"turn-end detection" = 0 说明它永远不会命中；一个全库为零的词进了查询组，会让该组看起来比实际覆盖得更宽。
  5. 逐版复核的输入集合必须机械提取，不得人工维护。 依据是本轮 47→173 的对比。
  6. 窗口起点绑定"最后一篇实际覆盖到的投稿时刻"，而不是上一轮的时钟时刻。 本轮覆盖 0 篇，所以起点不前移。这是索引冻结日必须显式处理的一步，否则会永久丢批。
  7. 区分"方向为零"与"索引为零"。 前者是领域没产出，后者是检索源没推进；两者的后续动作完全不同（前者继续等，后者下一轮必须把窗口起点保持不动并预期回填）。
  8. 经过身份认证的 gh 返回 404，默认读法是"尚未公开"，不是"不存在"。 该类条目的后续动作是发布观察，不得设死线。本轮的 X2Streaming-TTS 是这条规则的第一个实证案例，而它恰好落在一个已按错误读法设了死线的条目上。判定私有转公开的可用线索是 updated_at 前移而 pushed_at 不动，且必须写明 GitHub REST API 不暴露可见性变更事件，因此这是推断而非官方陈述。
  9. pushed_at、star 数与"README 里出现了 arxiv"三者都不是进展信号。 本轮五个动了的仓库，五次全是 README / 引用编辑，四次集中在同一个 34 小时窗口内（论文投稿后的引用整理潮）。以这三者为触发条件的流水线本轮会报四到五个假阳性。 判断进展必须落到文件级：制品关键词在全树路径中的命中数。
  10. 架构/能力支持的 grep 必须限定到项目自己的目录。 FlashPrefill V2 全树搜 sm_?120 有 23 处命中，23 处全在第三方 CUTLASS 头文件里，实例化目录下为 0。
  11. 11,357 字节只能当作 Apache-2.0 的快速线索，不能当作硬相等条件。 X2-Turn 的 LICENSE 为 11,374 字节，但归一化空白并剥掉开头的版权行后与规范文本逐字节相同。判定靠归一化比对，不靠字节数。
