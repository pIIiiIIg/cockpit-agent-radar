DMV-Bench: Diagnosing Long-Horizon Multimodal Agents' Visual Memory with Incidental Cue Injection

论文Paper · arxiv · 2026-06-25 · ◈ 11
摘要Summary
DMV-Bench 用严格排除文本泄漏的偶发视觉线索测试跨会话记忆；DualMem 组合原图、caption 和双空间向量，在两种 VLM、全部链长上取得最高主表成绩。其双编码可迁移为声学＋转写 voice memory，但应在 endpoint 后、generation 前检索，不能视为全双工能力。 Research on agent memory has matured rapidly, but almost entirely on the text side: few existing benchmarks ask, in an interactive environment, when an agent genuinely needs to remember what it saw rather than what it could write down. We introduce DMV-Bench (Code: https://github.com/yyyujintang/DMV-Bench), the first interactive benchmark for multimodal-agent visual memory. DMV-Bench is built on a controlled home-furnishing e-commerce catalogue of 1,000 product variants in which a text-leakage contract keeps the discriminative signal of each task in the pixels alone. Across a chain of autonomous shopping sessions, every visited product image carries a unique, pre-rendered incidental cue, and the agent is later asked to recall a particular cued product and navigate to its URL. Inspired by dual-coding theory, we propose DualMem, a memory architecture that maintains a visual and a verbal code in parallel. On DMV-Bench, DualMem outperforms a caption baseline and three recent multimodal agent-memory systems at every chain length J in {5, 10, 15, 50} on both Gemini 2.5 Flash and Qwen2.5-VL-7B, with the lead surviving controls for memory-bank size and encoding-position bias, and an asymmetric dual-coding regime in which vision carries the cue end-to-end while the verbal channel plays a smaller query-grounding role.

深度讲解Deep dive

DMV-Bench 用严格排除文本泄漏的偶发视觉线索，诊断智能体能否跨会话记住真正看过的细节；DualMem 以原图和视觉向量为主、caption 和文本向量为辅，在两种 VLM 与全部测试链长上取得最高主表成绩。

它解决什么问题Problem

既有智能体记忆多把经历压缩成文本，视觉基准又常可从标题、alt-text 或 URL 猜答案，无法证明模型保留了视觉证据。论文要求智能体在任务未提示线索重要性的情况下浏览商品，跨多次上下文清空后再找回唯一视觉线索。

核心方法Core method

环境含 10 个家具品类、10 种风格和每组合 10 个变体，共 1000 个商品；每张图预渲染全局唯一的颜色—物体线索，并以 L2 契约确保线索不出现在标题、描述、alt-text、URL、元标签或评论。每轮 ReAct 浏览后清空对话与站点历史，只保留待测记忆。DualMem 同时保存原图、VLM caption、SigLIP-2 视觉向量与 SBERT 文本向量；查询进入两个空间，分数分别归一化后按 0.75/0.25 融合，再把最高项的图像与 caption 注入导航模型。

怎么工作How it works

  1. 生成 1000 个商品变体和唯一视觉线索，并执行文本泄漏审计。
  2. 让智能体完成 5、10、15 或 50 段购物会话；线索在浏览时不被特别提示。
  3. DualMem 为商品观察保存原图、caption 及视觉/文本向量。
  4. 会话边界清空模型上下文和页面历史，只保留外部记忆库。
  5. 收到线索查询后执行双空间检索，把最高项重新注入 VLM 并导航到商品 URL。
  6. 按最终 URL 精确匹配计算成功率，并按回溯距离、库大小和编码位置做分层统计。

论文报告了什么Reported findings

  • Qwen2.5-VL-7B 在 J=5/10/15/50 时，DualMem 成功率为 81.1%/77.2%/75.1%/68.3%；Gemini 2.5 Flash 为 82.7%/75.2%/71.3%/65.1%，八个主表单元均为最高。
  • 相对 M2A，J=5/10/15 的提升在 Qwen 上为 12.2/11.1/12.0 个百分点，在 Gemini 上为 17.0/10.1/12.4 个百分点，六项配对检验均 p≤0.003。
  • Gemini、J=5 消融中，视觉/文本融合得 82.7%，纯视觉 80.1%，纯文本 59.5%；把 SigLIP-2 换成 CLIP 后对应配置由 76.9% 降至 65.4%。
  • caption 仅在 16.5% 的商品图上完整写出颜色与物体；混合检索时重新注入图像得 75.9%，只注入 caption 得 65.1%。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：可把 DualMem 迁移为 voice memory 模板：原始音频或声学 embedding 保留音色、韵律和环境声，转写文本 embedding 负责语义定位；本文视觉编码器本身不能直接处理音频。
  • 编辑判断：StreamingModelHarness 应在流式输入完成 endpoint 后、generation 前检索稳定记忆，避免把助手回答反写为用户证据；晚到的记忆工具只能进入下一轮，或触发受控取消与重生成。
  • 编辑判断：检索结果可交给现有外挂 TTS 播报，但论文不含边听边说、语音打断或音频状态同步，不能作为原生全双工证据。

边界与局限Limits

  • 数据仅覆盖合成家具电商，主实验只有两个 VLM 后端，也没有人类上限。
  • 融合权重只在 Gemini、J=5 上扫描；J=50 每个后端仅五个链干，相对 M2A 的优势不显著。
  • 查询总给出全局唯一线索，没有覆盖歧义、记忆更新、冲突、遗忘策略或自然语音噪声。
  • 仓库使用多个 lite 适配器并允许上游失败时回退，完整结果日志与轨迹缓存未发布。

代码与模型开放情况Code and model availability

部分开放Partial   代码和小型目录以 Apache-2.0 开放，1000 组带线索与原始图像也在 Hugging Face 以 Apache-2.0 发布。DualMem 是训练外组合，没有专属 checkpoint；完整复现仍需 Gemini 等 API 和重新生成任务轨迹。
