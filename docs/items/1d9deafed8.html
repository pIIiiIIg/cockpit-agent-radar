StreamingClaw Technical Report

论文Paper · arxiv · 2026-03-23 · ◈ 4
摘要Summary
StreamingClaw 是面向连续视频的 Agent 框架，用增量 KV、动态滑窗、外部层次记忆、主动事件 Agent 和工具/技能构成感知—决策—动作闭环。其接口设计可启发座舱持续视觉与事件记忆，但正文没有准确率、时延、吞吐或 KV 保留率，且不能把当前判停后生成、外挂 TTS 的 StreamingModelHarness 视为原生全双工。 Emerging applications such as embodied intelligence, AI hardware, autonomous driving, and intelligent cockpits rely on a real-time perception-decision-action closed loop, posing stringent challenges for streaming video understanding. However, current agents mostly suffer from fragmented capabilities, such as supporting only offline video understanding, lacking long-term multimodal memory mechanisms, or struggling to achieve real-time reasoning and proactive interaction under streaming input. These shortcomings have become a key bottleneck for preventing agents from sustaining perception, making real-time decisions, and executing closed-loop actions in complex real-world environments, constraining their deployment and potential in dynamic, open physical worlds. To alleviate these issues, we propose StreamingClaw, a unified agent framework for streaming video understanding and embodied intelligence. Beyond maintaining full compatibility with the OpenClaw framework, it natively supports real-time, multimodal streaming interactions. StreamingClaw integrates five core capabilities: (1) It supports real-time streaming reasoning. (2) It supports reasoning about future events and proactive interaction under the online evolution of interaction objectives. (3) It supports multimodal long-term memory storage, hierarchical memory evolution, efficient memory retrieval, and memory sharing across multiple agents. (4) It supports a closed loop of perception-decision-action. In addition to conventional tools and skills, it also provides streaming tools and action-centric skills tailored for real-world physical environments. (5) It is compatible with the OpenClaw framework, allowing it to leverage the resources and support of the open-source community.

深度讲解Deep dive

StreamingClaw 用短窗增量 KV、外部层次记忆、主动事件 Agent 和工具/技能闭环，把连续视频流组织成感知—决策—动作框架。

它解决什么问题Problem

离线视频 Agent 无法持续接收不断到达的画面；把全部历史留在上下文又会导致 KV 和计算持续增长，同时难以兼顾长时记忆、主动提醒和物理动作执行。

核心方法Core method

主 Agent StreamingReasoning 对新视频块增量编码，复用 KV cache，以动态滑窗限制上下文并按注意力贡献裁剪 token；它可直接推理，也可调度 StreamingMemory 检索分层事件记忆或让 StreamingProactivity 监测并触发事件。工具和技能执行结果再回写 Agent 上下文，形成闭环。

怎么工作How it works

  1. 多端视频及查询被标准化，并带绝对时间戳写入共享流式缓存。
  2. 新视频块到达后仅编码增量内容，滑动窗口和 KV 裁剪限制在线上下文。
  3. 主 Agent 按任务选择直接推理、历史记忆检索、主动事件判断或工具/技能调用。
  4. 动作执行结果回写主、子 Agent，记忆片段逐步演化为动作和事件节点。

论文报告了什么Reported findings

  • 正文是架构技术报告，没有报告数据集、基线、准确率、消融、硬件、帧率、端到端时延、吞吐或 KV 保留率。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：可借鉴“短窗 KV + 外部层次记忆 + 主动事件 + skill”四层接口，尤其适合持续视觉输入和驾驶员监测。
  • 编辑判断：StreamingModelHarness 当前语音侧仍是流式收音、判停后生成、晚注入工具和外挂 TTS；StreamingClaw 的视觉 Agent 框架不能证明它已获得原生音频全双工能力。
  • 编辑判断：采用前需在真实座舱视频上测帧吞吐、事件误报/漏报、KV 增长、记忆检索和工具闭环成功率。

边界与局限Limits

  • 论文只描述设计，没有定量证据支持其 real-time、low-latency 或稳定吞吐主张。
  • 作者说明当前主要处理视觉和文本；音频输入、精细音视频对齐及端到端联合生成仍不充分。
  • 裁剪阈值、窗口大小、冗余判定和长期运行资源上界均未给出可复现配置。
