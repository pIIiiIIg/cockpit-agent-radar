V-Rex: Real-Time Streaming Video LLM Acceleration via Dynamic KV Cache Retrieval

论文Paper · arxiv · 2025-12-13 · ◈ 11
摘要Summary
V-Rex 通过 ReSV 的跨帧哈希聚类、逐层逐头动态 KV 检索和专用 DRE 硬件，降低模拟的流式视频反复 prefill 成本。它对未来长时舱内视觉有研究价值，但不能解决当前已定位为 HF MoE 同步的 110ms/token 或外部 Edge TTS 延迟。 Streaming video large language models (LLMs) are increasingly used for real-time multimodal tasks such as video captioning, question answering, conversational agents, and augmented reality. However, these models face fundamental memory and computational challenges because their key-value (KV) caches grow substantially with continuous streaming video input. This process requires an iterative prefill stage, which is a unique feature of streaming video LLMs. Due to its iterative prefill stage, it suffers from significant limitations, including extensive computation, substantial data transfer, and degradation in accuracy. Crucially, this issue is exacerbated for edge deployment, which is the primary target for these models. In this work, we propose V-Rex, the first software-hardware co-designed accelerator that comprehensively addresses both algorithmic and hardware bottlenecks in streaming video LLM inference. At its core, V-Rex introduces ReSV, a training-free dynamic KV cache retrieval algorithm. ReSV exploits temporal and spatial similarity-based token clustering to reduce excessive KV cache memory across video frames. To fully realize these algorithmic benefits, V-Rex offers a compact, low-latency hardware accelerator with a dynamic KV cache retrieval engine (DRE), featuring bit-level and early-exit based computing units. V-Rex achieves unprecedented real-time of 3.9-8.3 FPS and energy-efficient streaming video LLM inference on edge deployment with negligible accuracy loss. While DRE only accounts for 2.2% power and 2.0% area, the system delivers 1.9-19.7x speedup and 3.1-18.5x energy efficiency improvements over AGX Orin GPU. This work is the first to comprehensively tackle KV cache retrieval across algorithms and hardware, enabling real-time streaming video LLM inference on resource-constrained edge devices.

深度讲解Deep dive

V-Rex 用训练免除的动态 KV 检索 ReSV 和专用 DRE 硬件减少流式视频反复 prefill 的传输与注意力开销，但主要收益来自尚未流片、未开放的定制硬件。

它解决什么问题Problem

流式视频逐帧 prefill 会让视觉 KV 持续增长；旧 KV 即使卸载到 CPU/SSD，PCIe 检索和逐层 attention 仍可能主导延迟，固定 top-k 又难适应不同层、头和查询。

核心方法Core method

ReSV 用随机超平面二值哈希和汉明距离聚类相邻帧的时空相似 token，再以 WiCSum 按簇得分和簇大小动态决定各层各头要取回的原始 KV。DRE 的 KVPU/KVMU 加速位级聚类、early-exit 排序和分层缓存，并把下一层预取与当前层计算重叠。

怎么工作How it works

  1. 新视频帧生成 Q/K/V，近期 KV 留在设备、旧 KV 分层卸载。
  2. 对 Key 生成 hash-bit，跨帧聚类并更新簇表。
  3. 对代表 Key 评分，WiCSum 选择各层各头所需簇。
  4. 映射回原始 KV 并预取，只对选中历史执行 attention。

论文报告了什么Reported findings

  • 在论文的 V-Rex8 模拟配置、batch=1 下，1K到40K KV 的逐帧延迟为 121–254ms，即 3.9–8.3 FPS；生成 TPOT 为 89–97ms。
  • ReSV 的平均检索率在帧处理和生成阶段分别为 32.7% 与 2.5%，平均 Top-1 下降 0.8 个百分点。
  • 40K KV、batch=1 时纯 AGX 软件 ReSV 为 2.8×，加入 KVPU 后完整 V-Rex8 报告 8.1× 加速和 10.2× 能效提升。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 若未来持续写入舱内视频 KV 并出现长会话的分层存储/检索瓶颈，可试验 ReSV 的跨帧聚类和逐层动态检索。
  • 当前 110ms/token 已定位为 HF MoE 的 GPU→CPU 同步而非 KV 大小，论文也没有音频、工具或 TTS 实验，因此不能用 V-Rex 解释现有解码和约 3 秒首音频。

边界与局限Limits

  • 结果来自 cycle-level simulator、DRAMSim3/MQSim 和 14nm RTL pre-layout 综合，不是流片或真实部署。
  • 只评估 Llama-3 8B、SigLIP 和 COIN 五项任务；经验阈值对其他模型及音频模态的泛化未知。
  • 完整历史 KV 仍保存在 CPU/SSD，方法减少工作集与传输，并未消除总存储增长。
