PACE: A Playback-Aligned Context Engine for LLM-Based Full-Duplex Voice Dialogue

论文Paper · arxiv · 2026-08-07 · ◈ 25
摘要Summary
PACE 把全双工助手的模型上下文锚定到客户端实际播放边界，打断后剔除未播内容以修复 Generative Context Mis-anchoring；GCM-Bench 上指代锚定准确率从 25.0% 升到 96.3%。这与 StreamingModelHarness 的判停/上下文修复高度同构，应作为中间件能力而非模型内双工来接入。 LLM-based full-duplex voice services allow users to speak while the assistant is responding. Because servers can generate output and advance dialogue state faster than clients can play it, subsequent user speech may be interpreted based on content the user never heard. We call this failure Generative Context Mis-anchoring (GCM). To address GCM issues, we present PACE, a provider-independent middleware layer that anchors model-facing context to the client playback boundary, a system-observable proxy for what the user could have heard. After an interruption, PACE repairs this context to exclude assistant content that never reached playback, while preserving low-latency generation across heterogeneous voice runtimes. We implement PACE's audio-only projection path end to end in a browser-based realtime voice assistant using a black-box speech model, without modifying the model service. We also construct GCM-Bench, a new controlled benchmark dataset of 108 playback-relative referent-anchoring cases. On GCM-Bench, PACE raises Referent Anchoring Accuracy from 25.0% to 96.3% over a cancellation-only baseline. On 200 Full-Duplex-Bench v1 interruption samples, it preserves interruption response quality. These results show that grounding model-facing context in actual playback is a practical way to maintain consistency in full-duplex voice dialogue.

深度讲解Deep dive

PACE 是与模型无关的中间件：把模型侧上下文锚定到客户端实际播放边界，修复打断后“用户没听到却被当成已说内容”的 Generative Context Mis-anchoring。

它解决什么问题Problem

全双工语音服务里，服务端生成与状态推进常快于客户端播放；用户打断后，后续用户话可能被基于其从未听到的助手内容解释，论文称之为 Generative Context Mis-anchoring（GCM）。

核心方法Core method

PACE 以可观测的客户端 playback boundary 作为“用户可能已听到内容”的代理，在打断后剔除未播放的助手内容并投影到模型侧上下文，同时尽量保留低延迟生成；实现为浏览器端黑盒语音助手路径上的音频投影中间件，不改模型服务本身。

怎么工作How it works

  1. 客户端持续报告助手音频的实际播放边界。
  2. 服务端生成可继续超前，但未播放内容保持可撤销。
  3. 用户打断后，PACE 按播放边界裁剪模型可见上下文，再接入后续用户输入。
  4. 在黑盒语音模型上用音频投影路径端到端落地，并用 GCM-Bench 评测指代锚定。

论文报告了什么Reported findings

  • 在新建的 GCM-Bench（108 个 playback-relative 指代锚定用例）上，相对仅取消生成的基线，Referent Anchoring Accuracy 由 25.0% 提升到 96.3%。
  • 在 Full-Duplex-Bench v1 的 200 条打断样本上，PACE 与基线均响应每次打断；平均响应分由 4.975 变为 4.995。
  • 助手未在播放时的请求走原路径，论文称不额外引入 PACE 延迟。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 高度契合 StreamingModelHarness：可把“播放边界/已播缓冲”作为打断后上下文修复的权威时钟，而不是信任模型已生成文本。
  • 适合做成 provider-independent 中间件层：与现有“输入流式、判停后生成、外挂 TTS”一致，不必改模型权重。
  • 不要把它写成原生模型层全双工；GCM 修复依赖客户端真实播放观测，缺播放遥测时无法落地。

边界与局限Limits

  • 端到端实现主要验证音频投影路径与浏览器助手设定，覆盖异构运行时的广度有限。
  • GCM-Bench 为受控合成指代场景；真实车内混响、回声消除误差与多设备时钟漂移未充分覆盖。

代码与模型开放情况Code and model availability

部分开放Partial   官方公开 GCM-Bench/RAA 数据与基线及 P1 played-audio 注入评测脚本（Apache-2.0）；完整 PACE 中间件产品化代码与通用 SDK 未见独立发布。
