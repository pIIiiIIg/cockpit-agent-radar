Stream RAG: Instant and Accurate Spoken Dialogue Systems with Streaming Tool Usage

论文Paper · arxiv · 2025-10-02 · ◈ 11
摘要Summary
Stream RAG 在用户讲话期间按音频块提前生成、取消和执行检索查询，再在端点后融合完整问题与结果生成语音，AudioCRAG-Synthetic 准确率由闭卷 11.1% 提升至 34.2%。它直接启发 Harness 把工具调用前移到判停前，但最终回答仍在用户结束后生成，不能称为原生全双工。 End-to-end speech-in speech-out dialogue systems are emerging as a powerful alternative to traditional ASR-LLM-TTS pipelines, generating more natural, expressive responses with significantly lower latency. However, these systems remain prone to hallucinations due to limited factual grounding. While text-based dialogue systems address this challenge by integrating tools such as web search and knowledge graph APIs, we introduce the first approach to extend tool use directly into speech-in speech-out systems. A key challenge is that tool integration substantially increases response latency, disrupting conversational flow. To mitigate this, we propose Streaming Retrieval-Augmented Generation (Streaming RAG), a novel framework that reduces user-perceived latency by predicting tool queries in parallel with user speech, even before the user finishes speaking. Specifically, we develop a post-training pipeline that teaches the model when to issue tool calls during ongoing speech and how to generate spoken summaries that fuse audio queries with retrieved text results, thereby improving both accuracy and responsiveness. To evaluate our approach, we construct AudioCRAG, a benchmark created by converting queries from the publicly available CRAG dataset into speech form. Experimental results demonstrate that our streaming RAG approach increases QA accuracy by up to 200% relative (from 11.1% to 34.2% absolute) and further enhances user experience by reducing tool use latency by 20%. Importantly, our streaming RAG approach is modality-agnostic and can be applied equally to typed input, paving the way for more agentic, real-time AI assistants.

深度讲解Deep dive

Stream RAG 把检索查询从用户说完后前移到讲话过程中；模型触发版每 500ms 判断是否发起或替换查询，再在端点后融合最终问题与结果生成语音。

它解决什么问题Problem

端到端语音模型依赖参数知识，面对动态事实易幻觉；传统 RAG 又必须在端点后生成查询、检索再回答，工具延迟会形成明显静默。

核心方法Core method

系统先从累积音频生成 Web/KG 查询，再把完整音频和文本检索结果共同输入模型生成语音。Fixed-Interval 每秒并行查询并用 reflector 选最早足够结果；Model-Triggered 每 500ms 输出新查询或 NO_QUERY，新查询会取消旧调用。

怎么工作How it works

  1. 把持续到达的用户音频按固定时长切块并累积上下文。
  2. 模型依据当前音频和上一个查询输出 Web/KG 查询或 NO_QUERY。
  3. 后续信息改变意图时取消旧查询并启动新查询，工具与讲话并行。
  4. 用户结束后取最后有效结果，与完整音频共同生成最终语音回答。
  5. 用 Whisper 转写输出，再按 CRAG 答案评估准确性。

论文报告了什么Reported findings

  • AudioCRAG-Synthetic 上，Qwen2.5-Omni-7B 准确率由闭卷 11.1%、普通 Open Book 26.3% 提升至 Model-Triggered 的 34.2%。
  • AudioCRAG-Human 上，对应准确率为 13.1%→26.9%→37.4%。
  • Synthetic 的 P50 首 token 时延由普通 RAG 的 5.90 秒降至 5.32 秒，工具结果时延由 2.78 秒降至 2.20 秒；表1的 20.7%是工具时延节省，总时延实际降 9.8%。
  • Human 的 P50 首 token 时延由 5.40 秒降至 3.60 秒，表1报告相对工具时延节省 53.4%。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：它直接针对 StreamingModelHarness 等端点后才开始工具查询的缺口，可把工具意图检测和调用前移到音频块处理阶段。
  • 编辑判断：Fixed-Interval 可做无需改主模型的原型；Model-Triggered 更节省调用，但需要专门后训练和取消语义。
  • 编辑判断：最终回答仍在用户结束后生成并可接外挂 TTS，不解决持续输出、边说边听或原生模型级全双工。

边界与局限Limits

  • 只提前执行检索，未评重叠说听、自然附和、复杂打断或生成中持续输出。
  • Synthetic 延迟明确排除端点检测，完整硬件、网络和并发成本也不足以复现实测。
  • 评测集中于短事实问答和 CRAG 模拟工具，不含多轮、有副作用的真实业务工具。
  • 语音输出经 Whisper 后由单一 LLM judge 评分，没有人工金标校准。
