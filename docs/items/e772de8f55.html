Wan-Streamer v0.1: End-to-end Real-time Interactive Foundation Models

论文Paper · arxiv · 2026-06-23 · ◈ 13
摘要Summary
Wan-Streamer v0.1 在单个 Transformer 中因果交错文本、音频和视频输入输出，160ms 一步、模型侧 signal-to-signal 约 200ms，但只验证了 192p 且未报告标准质量指标。它是 StreamingModelHarness 的长期原生流式对标，不是可接入后端：代码、权重和数据均未发布。 We present Wan-Streamer, a native-streaming, end-to-end interactive foundation model designed from the ground up for real-time, low-latency, full-duplex audio-visual interaction. Wan-Streamer seamlessly models language, audio, and video as both input and output within a single Transformer, where the sequence is represented as interleaved visual, audio, and text input tokens together with visual, audio, and text outpu

深度讲解Deep dive

Wan-Streamer v0.1 用一个 Transformer 原生联合处理并生成文本、音频和 192p 视频，以严格因果流实现持续感知、同步音视频输出和可打断交互。

它解决什么问题Problem

ASR→LLM→TTS→avatar 级联系统存在模块等待、误差累积及音画/轮次不同步，工程优化也不能把非因果组件变成模型级全双工。

核心方法Core method

模型用因果音视频 VAE、block-causal attention、文本 next-token loss 和音视频联合 conditional flow matching，把多模态输入输出交错为一条序列；滚动蒸馏后以 thinker–performer 双 GPU 流水线重叠状态更新、latent 生成与解码。

怎么工作How it works

  1. 将当前用户文本、音频和视频编码为可立即消费的因果流式单元。
  2. Transformer 用完整历史更新语言/交互状态并预测文本。
  3. performer 基于共享 KV 历史联合去噪下一音视频 latent。
  4. clean latent 写回历史，thinker 解码上一单元并发出，同时继续接收用户输入。

论文报告了什么Reported findings

  • Section 2.4 与 Table 1 给出的流式单元为 160ms，视频输出为 25fps。
  • 编码、状态更新、latent 生成到解码的模型侧 signal-to-signal 延迟约 200ms。
  • 加入论文假设的 350ms 双向网络预算后，总交互延迟约 550ms。
  • Section 5 明确 v0.1 只在初步 192p 输出上验证，正文没有标准质量指标、人评或消融。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：Wan-Streamer 是模型内部持续感知与生成，当前 Harness 是流式输入、endpoint 后生成和外挂 TTS，二者不能等同。
  • 编辑判断：论文未讨论工具调用且没有可接入资产，只适合作为长期目标架构；Harness 应单列 endpoint、工具、首文本、首 TTS 音频和网络延迟。

边界与局限Limits

  • 192p 只是 proof of concept，更高分辨率仍是未来工作。
  • 实时吞吐要求 performer 加通信开销小于 160ms，200ms 结果依赖特定双 GPU 路径。
  • 论文没有公开标准化质量指标、人评或消融，并提醒竞品延迟口径并不一致。
