OpenVisTool: An Open Recipe for Synthesizing Instructive Visual Tool-Use Trajectories

论文Paper · arxiv · 2026-08-09 · ◈ 5
摘要Summary
OpenVisTool 认为“答案正确”不足以构成好的视觉工具训练轨迹，工具观察还必须对答案有可测的因果贡献。它以难度筛选、分领域轨迹合成和双重监督验证构建 OpenVisTool-42K，让模型学习何时、为何以及如何主动获取视觉证据。 Visual tool use has emerged as a fundamental capability for multimodal agents to actively acquire evidence beyond a fixed image encoding. The prevailing recipe learns this capability from teacher-generated trajectories filtered for answer correctness, implicitly assuming that every successful demonstration provides effective supervision. We argue this assumption is flawed: a strong teacher often reaches the correct answer without needing its tool calls, and imitating such trajectories teaches a student that tool calls accompany correct answers, not that tool observations ground them. We present OpenVisTool, an open framework for constructing instructive visual tool-use trajectories that provide effective supervision for tool learning. The key insight is that a trajectory should be retained only if its answer is correct (outcome validity) and its tool observations causally contribute to that answer (causal utility). The framework operates in three stages: difficulty screening to select queries that are not reliably answerable without tools, domain-specific trajectory synthesis to elicit coherent tool-use trajectories, and supervision verification to jointly test both conditions. Rather than encouraging models to imitate tool calls, the resulting supervision teaches when and how visual evidence should be acquired. Using this framework, we construct OpenVisTool-42K, a dataset spanning five visual reasoning domains, together with OpenVisTool-Bench, a benchmark covering the same domains. Across four backbones (4B-27B), fine-tuning on OpenVisTool-42K consistently improves visual tool-use performance and yields gains on two out-of-distribution benchmarks; the larger models approach leading closed-source systems. The evidence suggests that effective visual tool use is learned from causally grounded supervision rather than tool-calling patterns.

深度讲解Deep dive

关键编辑结论是：不要只保留最终答对的工具轨迹，还要做无工具反事实，确认工具观察确实提高了答题可靠性；否则学生只会模仿调用形式，而不会把返回证据用于决策。

它解决什么问题Problem

强教师即使不调用工具也可能凭参数知识、捷径推理或粗粒度图像线索答对，但在合成提示驱动下仍会生成看似合理的工具调用。仅按最终答案正确或让 judge 判断“工具结果似乎相关”，会把这种伪相关轨迹留给学生，教成“答对时伴随工具调用”，而不是“需要时用工具取得决定性证据”。

核心方法Core method

OpenVisTool 用两个条件定义有教学价值的轨迹：最终答案正确的 outcome validity，以及在固定原图和问题时、加入已记录工具调用与观察能比无工具条件提高固定 probe 模型成功率的 causal utility。流水线先筛出强模型在无工具条件下不能稳定解决的难题，再按图表、表格、GUI 定位、视觉搜索和 Web-to-HTML 五个域定制工具策略生成轨迹，最后联合验证答案与反事实工具效用，得到 OpenVisTool-42K 和对应基准。

怎么工作How it works

  1. 对候选图像问题运行强模型的无工具多次作答，剔除无需工具也能稳定解决的样本。
  2. 按任务域选择裁剪、增强、几何检测、标注或 HTML 渲染等工具策略。
  3. 让教师生成包含工具调用、返回观察、后续推理和最终答案的完整轨迹。
  4. 执行轨迹并验证最终答案，过滤不可执行、格式错误或结果错误的样本。
  5. 固定 probe 模型，比较仅给原图/问题与额外给记录工具观察时的成功率。
  6. 只保留同时满足答案正确和因果效用的轨迹，用于多骨干 SFT 与跨域评测。

论文报告了什么Reported findings

  • OpenVisTool-42K 覆盖图表、表格、GUI 定位、视觉搜索和 Web-to-HTML 五个域，并在 4B–27B 的四个骨干上评测。
  • Qwen3.5-9B 消融中，只按答案正确过滤比完整双重过滤低 1.7 分，只按因果效用过滤低 3.4 分。
  • 任一单域训练都提高了相对带工具基础模型的总体表现；其中 GUI-only 训练使 VisualSearch 提升 14.1 分。
  • 跨域迁移并非总是正向：VisualSearch-only 训练把 Web2HTML 从 42.0 降到 21.6。
  • 轨迹重放只向原始 Qwen3.5-9B probe 提供工具参数和观察、不提供中间推理或答案时，按双重条件训练的模型所生成轨迹仍优于仅按正确性训练的轨迹。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 对架构 A 的 RAG 与晚期工具注入非常有启发：评测不仅要问最终回答是否正确，还要做“移除检索/工具观察”的反事实，确认工具结果真的改变并改善了答案。
  • 对架构 B 的 search/state/call hop 同样适用，可过滤那些形式上走了多个 hop、实际上模型早已凭先验得出结论的训练轨迹。
  • 可据此建设车舱工具轨迹集：先筛选无需工具无法可靠回答的车辆状态、导航或实时信息问题，再验证注入结果的增量效用。
  • 论文处理的是视觉工具数据合成和离线微调，不提供流式音频、端点检测、外部 TTS 或 Qwen3-Omni KV 架构；适配价值在数据与评测准则。

边界与局限Limits

  • 因果效用由固定 probe 模型在有/无工具观察条件下的成功率差近似，结论会依赖 probe 能力和采样稳定性。
  • 多个任务使用 GPT-5.5 作为 LLM judge，评测仍含模型裁判偏差。
  • 五个域均为视觉任务，尚未直接验证语音、搜索结果、车况状态或电话工具。
  • 跨域迁移可为负，说明单域工具策略会发生冲突，不能假设工具使用天然通用。
  • 流水线需要多次无工具筛选、轨迹生成、执行和反事实验证，数据构建成本较高。
