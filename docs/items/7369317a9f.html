深度讲解Deep dive

TurnGuide 按自然停顿动态切分助手话轮，并在每个语音块前生成短文本块，以改善端到端双工语音模型的语义连贯性；公开推理仍是整段 WAV 离线处理。

它解决什么问题Problem

全双工模型既要保持双声道时间对齐，又要避免纯语音 token 长序列的语义退化；文本指导插得过早缺上下文，过晚则语音先行，长度也会影响发言边界。

核心方法Core method

系统用 VAD、Whisper 逐词时间戳和 0.6 秒容差建立 turn 级文本—语音对齐。以 GLM-4-Voice 为骨干，把两路语音按 5 个 token、约 400ms 分块交错；助手文本也按 5 token 分块并加 EOC，再按首词时间戳放到对应助手语音块之前，比较 1:1、2:1、3:1 文本/语音损失权重。

怎么工作How it works

  1. 双通道录音经 VAD 合并为 IPU，并获取逐词转写和时间戳。
  2. 把用户与助手语音离散化并按约 400ms 块交错排列。
  3. 将助手 turn 文本切块，在对应语音块之前插入。
  4. 微调 GLM-4-Voice，按用户输入块生成文本与助手语音 token。

论文报告了什么Reported findings

  • Table 2 的语义总分中，SCI、Moshi TS 为 5.91、5.58，TurnGuide 1:1、2:1、3:1 分别为 7.27、7.70、7.79。
  • Table 5 中标准文本插入的 Conditional-All 为 6.76；提前 4 秒和延后 4 秒分别降至 5.61、5.94。
  • Tables 7–8 中 GPT 与人工成对判断匹配 25/30；TurnGuide 的 M-MOS/N-MOS 为 3.26/3.23，高于 Moshi 的 2.69/2.75。

对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：可借鉴 turn 级短文本规划，但应在 Harness endpoint 后、晚注入工具完成后确定最终文本，再交给外挂 TTS。
  • 编辑判断：官方脚本先读取完整 WAV 再统一解码，不得把 checkpoint 或 0.69 秒理论值写成当前 Harness 的在线全双工能力。

边界与局限Limits

  • 主要只在 Fisher 英语电话对话上验证，主语义评测依赖 GPT-4o，人工实验样本很小。
  • 模型每个训练配置只跑一次，没有随机种子方差；Speech-QA 还只使用半双工模式。
  • 未做 RLHF 或安全对齐，附录明确不建议直接用于生产。
