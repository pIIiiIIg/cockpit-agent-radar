Integrating Facial Generation into Full-Duplex Spoken Dialogue Systems

论文Paper · arxiv · 2026-06-20 · ◈ 22
摘要Summary
Moshi-Face 在 Moshi 旁加入 12.5Hz 的双向 3D 人脸 token 流，联合接收用户声音/面部并生成助手语音/面部，但 UTMOS 从原始 Moshi 的 3.08 降至 1.75。其 face codec 仍非因果且无代码权重；当前判停后生成、外挂 TTS 的 Harness 最多借鉴头像方向，不能复现模型级联合生成。 Full-duplex spoken dialogue models, such as Moshi, enable natural, low-latency voice conversations. 深度讲解Deep dive

Moshi-Face 在 Moshi 的双向音频流旁加入 12.5Hz 的双向 3D 人脸 token 流，使模型连续接收用户声音与面部运动，并同步生成助手语音和面部动作。

它解决什么问题Problem

原生全双工语音模型缺少面对面交流所需的表情与口型；传统 talking-face 系统又通常依赖已经生成完的音频，不能在持续对话中联合生成。

核心方法Core method

系统先用 VQ-VAE 将 25fps FLAME 网格压成每帧 8 个离散 face token，再新增 Face Transformer，结合 Moshi 的 RQ-Transformer 隐状态、文本和音频 token 并行预测面部 token。训练先冻结语音主干预训练 Face Transformer，再联合微调语音与面部分支。

怎么工作How it works

  1. 从 Seamless Interaction 取约 180 小时双人对话，以 VHAP 提取 5,143 顶点的 FLAME 网格。
  2. 用约 70 小时数据训练 face codec，经 2 倍降采样得到 12.5Hz、每帧 8 个 token。
  3. 在用户/助手文本与音频流之外加入用户输入和助手输出的人脸 token 流。
  4. Face Transformer 读取语音主干状态并同步生成助手面部 token，最后解码为 25fps 网格。

对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：当前 Harness 在 endpoint 后才生成且使用外挂 TTS，无法提供 Moshi-Face 所需的 12.5Hz 模型内双向音频/面部流，不能据此称为模型级全双工。
  • 编辑判断：若座舱需要虚拟形象，短期更现实的是让外挂 TTS 驱动级联动画；这不等同于论文利用语音主干隐藏状态联合生成面部动作。

边界与局限Limits

  • face codec 是非因果的，论文把改用 causal streaming codec 列为未来工作。
  • 未做真人感知评测，音频与面部同步也只能渲染成 2D 视频后用 SyncNet 间接评价。
  • 在较小领域数据上联合微调明显降低了语音 UTMOS。
