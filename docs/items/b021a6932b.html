MIST: Multimodal Interactive Speech-based Tool-calling Conversational Assistants for Smart Homes

论文Paper · arxiv · 2026-05-07 · ◈ 9
摘要Summary
MIST 通过 10,000 段合成智能家居对话和可执行数字孪生，同时评测语音工具代码、状态维护、澄清、冗余与改口处理。编辑判断：其最终状态判定很适合车控回归，但公开仓库尚无完整数据或生成框架，且任务不覆盖 Harness 的在线判停、打断和外挂 TTS。 The rise of Internet of Things (IoT) devices in the physical world necessitates voice-based interfaces capable of handling complex user experiences. While modern Large Language Models (LLMs) already demonstrate strong tool-usage capabilities, modeling real-world IoT devices presents a difficult, understudied challenge which combines modeling spatiotemporal constraints with speech inputs, dynamic state tracking, and mixed-initiative interaction patterns. We introduce MIST (the Multimodal Interactive Speech-based Tool-calling Dataset), a synthetic multi-turn, voice-driven code generation task that operates over IoT devices. We find that there is a significant gap between open- and closed-weight multimodal LLMs on MIST, and that even frontier closed-weight LLMs have substantial headroom. We release MIST and an extensible data generation framework to build related datasets in order to facilitate research on mixed-initiative voice assistants which reason about physical world constraints.

深度讲解Deep dive

MIST 用带数字孪生状态的合成智能家居对话，联合测试语音理解、可执行代码、歧义澄清、冗余拒绝、纠错和跨轮设备状态维护。

它解决什么问题Problem

真实 IoT 助手不能只做单轮 intent/slot：它还要理解房间和设备约束、当前物理状态、例程、指代与改口，并在信息不足或动作冗余时选择澄清或拒绝执行。

核心方法Core method

生成器先采样房屋、房间、50 类设备、27 个能力/API 和用户画像，再以 Home State 数字孪生维护设备及例程状态。概率 orchestrator 在六类交互模式间采样并做符号合法性检查，Gemini 2.5 Flash-Lite 负责画像化改写，规则注入口吃和修订，Google Cloud TTS 合成当前用户请求；受测 MLLM 同时读取住宅配置、当前状态、历史文本和当前语音，输出 API 代码与自然语言动作。

怎么工作How it works

  1. 采样楼层、房间、设备放置约束、设备能力和用户声学/行为画像，初始化 Home State。
  2. 按执行、例程更新、纠正、歧义、冗余和状态查询六类模式生成多轮目标，并在每轮后执行代码更新状态。
  3. 用 Gemini 改写用户话语，规则注入重复和自我修订，再以三种英语口音、可变音高/语速及 Gaussian noise 合成语音。
  4. 执行模型生成代码并比较最终设备与例程字典，同时用动作分类器评价确认、澄清、冗余、未找到、状态报告和纠正等对话行为。

论文报告了什么Reported findings

  • 正文 §2 报告 10,000 段对话、88.1 小时语音、50 类 IoT 设备、27 个能力/API，平均每段含 5.6 个用户轮次。
  • Table 1 中 Gemini 2.5 Pro 的 Execution Match/Exact Match 为 79.53/65.56，Qwen 3 Omni 为 59.86/47.19；Previous State 基线已达 71.62，原因是约 71.6% 样本无需改变设备状态。
  • Table 2 中 Gemini 2.5 Pro 的对话动作 Macro F1/Accuracy 为 46.00/66.73；正文同时报告其漏掉 73.0% 应确认有效请求的样本。
  • 附录 F 对 300 个样本的专家复核中，对话动作多数票正确率为 92.33%、评审一致率 90.61%；141 个需要代码的样本中代码正确率为 92.91%、一致率 93.57%。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：最值得移植的是可执行状态模拟器与 Execution Match，可把 Harness 当前严格工具名召回升级为“参数校验后最终车态是否正确”。
  • 编辑判断：六类交互模式可直接构造车控多轮集，尤其应覆盖同名设备澄清、已完成动作拒绝、设备不存在、改口后的撤销与补偿。
  • 编辑判断：MIST 仍是按完整用户话轮评测的离线任务；当前 Harness 流式收音后等 endpoint 才生成、再晚注入工具并交给外挂 TTS，因此不能把 MIST 成绩解释成模型原生全双工或实时打断能力。

边界与局限Limits

  • 所有话语均为合成：只有 en-US、en-GB、en-AU 三类 TTS 口音，噪声是 Gaussian variance 0.01–0.08，不覆盖真实住宅或座舱回声、远场、多说话人和自然失语。
  • Execution Match 容易受大量 no-op 轮次抬高；Previous State 基线 71.62 已接近最强模型 79.53，必须与 Exact Match、动作类型和安全错误分开解读。
  • 对话动作由 Gemini 2.5 Flash-Lite 在温度 0 下判定，仍不是完全确定性的程序真值；人工复核只抽取 300 个样本，代码子集仅 141 个。
  • 截至指定时间，论文声称发布数据和可扩展生成框架，但官方仓库实际只有项目演示 HTML 和少量示例 MP3，没有完整 10,000 段数据、生成器、评测代码、模型权重或许可证。

代码与模型开放情况Code and model availability

部分开放Partial   代码：官方仓库顶层只有 `.github`、`.gitignore` 和 `demo/`，没有论文的数据生成或评测实现。数据：仅公开少量项目页示例音频，未找到完整 MIST 数据页。权重：该工作为 benchmark，没有发布专属权重。许可：GitHub API 返回 license=null，仓库无 LICENSE、tag 或 release，示例数据的再使用条款未知。
