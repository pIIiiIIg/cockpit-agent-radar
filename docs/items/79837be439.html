Activity Frames: Deterministic Screen-Activity Compilation for Agent Memory and Replay

论文Paper · hf · 2026-08-05 · ◈ 5
摘要Summary
Activity Frames 用零模型确定性编译器把屏幕活动压成带原始证据指针的 typed memory，并把重复流程编译成守卫式重放；紧凑上下文压缩 86 倍，64 题准确率为 98.4%。其记忆 sidecar 和 guard-miss 回退可借鉴到 Harness，但结果应在 endpoint 前预取，不能把系统变成原生全双工。 Computer-use agents pay full frontier inference to re-derive routines their user has already performed, because an agent's memory today records what the user said, not what the user did. We compile passively captured screen activity into agent memory with a deterministic, zero-model pipeline: it segments a local capture stream into typed activity frames, bounded episodes carrying application, site, timing, input volume, and evidence pointers back to the raw rows, with no model in the loop, so the output is byte-identical, cacheable, and mechanically auditable. On one professional's single-user corpus of 128,756 frames over 51 active days, the compiler reduces a day of raw capture to a prompt-ready context block 86x smaller in 68 ms, and an agent reading that block answers questions about the day at 98.4% accuracy (Wilson 95% CI 91.7-99.7%) against an independent oracle, versus 66-80% for an LLM summary of the same capture, a mid-tier model reading the block matching a frontier one. The same compiler doubles as a demand-side cost instrument. Read off passive, pre-delegation human activity rather than agent rollouts, it supplies two parameters that agent-cost models assume but, to our knowledge, have not measured: the Routine Overhead Ratio R and the routine recurrence h. We report first values of R, a modeled upper bound, at 60-343x, and a delegable recurrence of 9.0% in-sample and 7.7% out-of-sample, for a realistic all-fleet token ceiling near 8%; a compiled routine replays deterministically with the model out of the loop, demonstrated live at zero model tokens on a guard-matched hit. Schema, compiler, and evaluation harness are open.

深度讲解Deep dive

Activity Frames 用零语言模型的确定性编译器，把本地屏幕捕获压缩为可审计的情景记忆，并将重复操作编译成带守卫的可重放流程。

它解决什么问题Problem

计算机智能体通常只记得对话，无法利用用户已经完成的真实桌面活动；直接传入原始捕获记录成本过高，而 LLM 摘要又有非确定性、重复计费和长上下文失真。

核心方法Core method

系统按应用与站点对逐显示器快照分段，通过固定驻留计时、会话间隔和短暂切换合并规则生成 activity frames；随后校正输入事件归属、解析点击目标和 URL 实体，输出覆盖范围、盲区及原始行证据指针。推断内容只能进入有命名空间、置信度和证据链接的第二层。同一捕获还能挖掘重复动作 n-gram，编译为带元素、角色和应用守卫的参数化重放计划。

怎么工作How it works

  1. 本地捕获屏幕、应用、URL、输入事件和可访问性树并写入 SQLite。
  2. 按显示器与 application-site 分段，驻留上限 90 秒，超过 300 秒形成会话或缺口。
  3. 合并不超过 20 秒的 A→B→A 切换，同时保留 B 为可审计 interruption。
  4. 按最近快照重新归属输入事件，解析点击和 URL 实体。
  5. 输出 JSON、Markdown、紧凑上下文或 MCP 工具，并挖掘带守卫的重复流程。

论文报告了什么Reported findings

  • 代表性一天 2066 条快照需 126812 tokens；完整 frames JSON 为 34815，紧凑块为 1469，压缩 86 倍；编译中位耗时 68ms。
  • 8 天 64 题评测中，Activity Frames 在 Sonnet 4.5 和 Opus 4.5 上均为 98.4%，Wilson 95% 区间 91.7%–99.7%；LLM 摘要为 66.1% 和 80.4%。
  • 5120 个不同 URL 中 81.3% 被解析为 46 种非通用实体，18.7% 回退为通用页面引用。
  • 20 个高频流程的 operational Routine Overhead Ratio 中位数为 60 倍；可委派动作样本内复现率 9.0%，时间外命中率 7.7%。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：最适合作为 Harness 的本地 voice-memory sidecar；当前回答所需上下文应在流式输入完成、endpoint 触发 generation 前预取。
  • 编辑判断：生成开始后才返回的 Activity Frames 结果不能自然修正当前输出，只能进入下一轮或触发受控取消与重生成。
  • 编辑判断：守卫式重放可接确定性动作层，但必须保留权限、安全验证和 guard-miss 回退；外挂 TTS 只播报确认。论文不处理边听边说，因此不是原生全双工。

边界与局限Limits

  • 核心数据来自一名用户和一台机器，无法代表不同职业、平台与人群。
  • 前台驻留时间不等于真实注意力，双显示器会重复计时，线下活动完全不可见。
  • 问答只测试两个 Claude 层级各一次，且 Activity Frames 直接提供部分基线需自行计算的时长。
  • 成本比的分子为建模值，现场重放只验证一个两步流程；私人约 9.5GB 捕获库未发布。

代码与模型开放情况Code and model availability

部分开放Partial   官方仓库以 MIT 发布编译器、schema、MCP、重放器、研究脚本和 QA harness，PyPI 包及默认 nocta-recorder 也开放。编译路径不需模型；论文的私人屏幕捕获数据库未发布，只能用自有数据复跑。
