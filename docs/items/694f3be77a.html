Harness TTS: Towards Context-Aware Expressive Speech Synthesis with Harness Layer

论文Paper · arxiv · 2026-07-20 · ◈ 12
摘要Summary
Harness TTS 把多源上下文路由成有限、可审计的提示音频，再驱动现有 CosyVoice3 或 VoxCPM2；无 CoT 的 First-ID P95 为 41.2ms。它与 Harness 的外挂 TTS 形态直接同构，但不改变判停后生成，且目前没有官方代码、权重或数据。 Expressive speech synthesis for voice assistants requires flexible style control that adapts to explicit requests and broader interaction context. We propose Harness TTS, a lightweight control layer that wraps around a TTS engine to externalize and govern its expressive behavior. It reformulates style control as closed-set prompt-tool routing: offline, a compact registry of stylistic prompt tools is constructed with

深度讲解Deep dive

Harness TTS 不改造声学模型，而是在 TTS 外增加上下文感知的有限提示音频路由层，使表达风格可审计、可治理。

它解决什么问题Problem

固定参考音频无法动态适配风格，开放式自然语言指令又不稳定；系统还需整合用户画像、场景、环境、历史和显式要求，并处理彼此冲突的信号。

核心方法Core method

每段风格提示音频被注册为带离散标签和说明的工具。轻量 LLM 根据五层 observation 和固定优先级输出候选 audio_id，执行器取首选提示音频驱动 CosyVoice3 或 VoxCPM2，不修改 TTS 后端。

怎么工作How it works

  1. 离线构建轴向风格工具和场景预设工具，标注速度、音量、情绪与适用场景。
  2. 在线汇总系统默认、用户画像、场景、隐式意图和显式指令。
  3. 按显式指令到系统默认的五级优先级处理冲突。
  4. LLM planner 输出排序后的 audio_id。
  5. executor 取首选提示音频驱动现有 prompt-based TTS。

论文报告了什么Reported findings

  • 在 Gemini-2.5-Pro 教师标签上，Qwen3-4B+CoT 的 T-Exact@1 在显式、隐式和冲突集分别为 74.3%、43.0% 和 64.6%；这是教师一致率，不是人工准确率。
  • RTX 5090、vLLM 条件下，Qwen3-4B 无 CoT 的 First-ID P50/P95 为 34.4/41.2ms，完整五候选为 179.9/206.0ms；均为 planner-only 延迟。
  • 相对 instruction-only，Harness 在 CosyVoice3 参数/场景子集的 instruction-following 胜率优势为 23.1/35.6 个百分点，VoxCPM2 为 13.8/20.0 个百分点。
  • 四种合成条件的 UTMOSv2 均提高 0.11–0.38；CosyVoice3 参数子集说话人稳定性为 89.8 对 86.8，场景子集则为 90.4 对 92.9。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：最适合接在 StreamingModelHarness 文本生成与外挂 TTS 之间，用用户、场景和环境状态选择有限提示音频。
  • 编辑判断：它不会改变等待 endpoint 后生成的控制流，也不解决抢话、输入输出重叠或原生全双工；价值在外部 TTS 表达治理。
  • 编辑判断：路由可与 endpoint 后主模型生成并行，但论文只测 planner 延迟，未验证晚注入工具或完整首音频延迟。

边界与局限Limits

  • CoT 提高路由一致率，却把 Qwen3-4B First-ID P95 从 41.2ms 增至 323.6ms。
  • 路由教师和合成偏好评委均为 LLM，没有人工标注或主观听测。
  • 测试数据由 LLM 生成，不是真实用户日志。
  • 135 个合成样例只围绕显式指令，没有端到端验证隐式上下文和冲突场景。
