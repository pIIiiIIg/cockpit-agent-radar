Σ-Mem: An Online Reliability Memory for LLM-based Multi-Agent Systems

论文Paper · hf · 2026-07-29 · ◈ 6
摘要Summary
Σ-Mem 将多 Agent 记忆从保存内容扩展为保存“谁在何种任务上可靠”，并用决策后的正确性反馈持续更新。它在反事实可靠性变化和多数 OOD 测试上有效，但依赖外部标签，模型内部 steering 也不直接兼容纯 API 编排。 Memory is central to long-horizon LLM agents, yet existing memory systems primarily preserve interaction content rather than modeling which agents can be trusted and under what conditions. This limitation is particularly important in multi-agent systems, where a central model may be unable to directly verify plausible or correlated peer responses. We introduce Σ-Mem, an online reliability memory that records historical competence evidence for individual peers and peer relationship evidence across the peer set. Both forms of evidence are maintained as real symmetric states and updated from post-decision correctness feedback. By Weyl's inequality, the spectral change caused by each event-level update is bounded, enabling stable online adaptation without retraining the underlying models. Σ-Mem provides a general write-and-read interface: the same memory can be used for residual steering of a central model, response-free peer routing, or reliability-weighted voting. Across five Qwen-family models, Σ-Mem adapts to counterfactual reliability shifts and generalizes to unseen peers and task domains. Direct memory readouts also outperform majority voting and the best fixed peer over the full OOD evaluation set. Moreover, performance improves consistently as more correctness feedback becomes available, indicating that Σ-Mem progressively accumulates actionable reliability information. These results establish reliability memory as a reusable foundation for adaptive coordination in LLM-based multi-agent systems.

深度讲解Deep dive

Σ-Mem 在线记录每个 peer 的任务条件化可靠性和 peer 间正确性关系，让多 Agent 系统依据历史反馈路由、投票或选择答案。

它解决什么问题Problem

内容记忆能保存“发生了什么”，却不能显式回答不同任务下“该信任哪个 Agent”，也难处理多个 peer 的相关错误。

核心方法Core method

方法为每个 peer 维护对称矩阵 Mₚ，另维护关系矩阵 G；收到决策后的外部正确性标签后执行衰减、有界的秩一更新，并通过残差 steering、M-route 或 M-vote 读取可靠性。

怎么工作How it works

  1. 将当前任务编码为单位能力方向 φ(xₜ)。
  2. 从 Mₚ 和 G 读取历史可靠性，或把结果注入中心模型上半层残差流。
  3. 在看不到当前正确性标签时选择 peer、路由任务或加权投票。
  4. 决策完成后接收外部逐-peer 正确性反馈。
  5. 更新 Mₚ 和 G 供后续事件使用，底层 LLM 权重保持冻结。

论文报告了什么Reported findings

  • 表 1 的 CF@90 条件下，Qwen3-0.6B 从 46.22% 提升至 71.10%，增加 24.88 个百分点。
  • 六个 OOD 基准、五个中心模型共 30 个组合中提升 27 个；BBH 上 Qwen3-4B 从 20.38% 到 28.66%，Qwen3-8B 从 19.29% 到 28.17%。
  • M-route/M-vote 的总体准确率约为 60.67%–60.99%，高于多数投票的 59.12% 和最佳固定 peer 的 57.52%。
  • 在三组随机反馈掩码下，M-route 与完整 Σ-Mem 均随反馈比例从 5% 增至 100% 而持续改善。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 适合在 commit 后把工具或子 Agent 的已验证结果写成下一次决策的可靠性状态。
  • 主方法需要访问模型上层残差流，不适用于只调用外部 API 的 StreamingModelHarness；M-route/M-vote 更容易放在外部编排层。
  • 反馈只影响后续事件，没有测试向正在生成的输出注入迟到结果，也不涉及外置 TTS 或全双工。

边界与局限Limits

  • 方法必须获得逐-peer 外部正确性标签；开放式任务中这种监督往往延迟、昂贵或不可得。
  • CF@50 的历史证据刻意冲突，多数模型反而下降，例如 Qwen3.5-4B 从 66.15% 降至 63.17%。
  • 中心模型全部来自 Qwen 家族，训练只有三个 peer，扩展实验最多五个 peer。
  • 主要结果来自离线基准流和合成反事实重分配，不是持续运行的真实多 Agent 系统。
