How Should LLMs Listen While Speaking? A Study of User-Stream Routing in Full-Duplex Spoken Dialogue

论文Paper · arxiv · 2026-05-11 · ◈ 19
摘要Summary

深度讲解Deep dive

论文对比用户流直接融合进生成序列的 CF-Duplex 与独立 cross-attention memory 的 XA-Duplex：前者问答和打断更强，后者在漏停后更能隔离重叠语音污染。

它解决什么问题Problem

普通 LLM 只延展单一序列，而原生全双工模型生成时仍要接收用户音频并决定继续、停说、响应或忽略附和；不同路由会在语义耦合和上下文隔离间取舍。

核心方法Core method

共同骨架由冻结 Qwen3-1.7B、LoRA、流式 Whisper 编码器、CosyVoice2 tokenizer 和轻量 audio head 构成。CF 将用户语音、助手文本和助手音频按时间轴门控融合；XA 在偶数层插入 14 层 cross-attention，将用户流保留为独立 KV memory。WAIT 与 INT token 显式监督等待和打断。

怎么工作How it works

  1. 用大规模 ASR/TTS 和约 190 万合成轮次样本训练基础流式能力。
  2. 动态插入相关/无关打断和 backchannel，随机化反应延迟。
  3. 用户音频持续分块编码，经 CF 融合或 XA memory 注入。
  4. 主干同时预测等待/打断、文本和本地音频 token。

对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：这项权衡只在“生成期间持续把用户流送进模型”时直接成立；可作为 Harness 未来升级原生并行输入的架构依据。
  • 编辑判断：当前 Harness 在 endpoint 后才生成，用户流不会以相同方式污染生成序列；打断主要是取消生成和外挂 TTS 队列控制，晚注入工具也不在论文范围。

边界与局限Limits

  • 只比较两种路由、单一 1.7B 尺度和固定训练配方，CF/XA 参数量也不严格匹配。
  • 训练大量依赖合成 TTS、拼接和插入行为，没有端到端 RTF、显存或目标设备首音频实测。
  • XA 漏停后更连贯主要是少量定性案例，未报告完整失败样本数和量化连贯率。
