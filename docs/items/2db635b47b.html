VAmoS Bench: Voice Agent Simulation Bench

论文Paper · arxiv · 2026-07-29 · ◈ 17
摘要Summary
VAmoS Bench 用 100 个隔离银行场景、真实音频、SQL 工具和完整轨迹评估语音代理是否真正完成任务；3300 通电话连接率 98.3%，完成率只有 63.1%。其路径断言和说做交叉检查很适合改造成车控回归，但固定场景与 grader 尚未完整开放。 Production voice agents span cascaded, speech-to-speech, and hybrid architectures. Voice-agent benchmarks typically measure component quality and conversational properties such as word error rate, latency, naturalness, and turn-taking. Fewer measure whether the agent handled a phone call correctly on its own. Contact centers refer to this as ``containment'': the share of phone calls the automated system resolves without handing off to a human. On some phone calls the right outcome is refusal or a redirect. To address this gap, we introduce VAmoS Bench, the Voice Agent Simulation Bench. It measures complete voice-agent systems end to end in a stateful customer-support task. The agent is Riley, a credit-card support representative for a fictional bank who can freeze, cancel, replace, or activate a card. Each of 100 scenarios supplies a simulated caller with a private goal and a seeded PostgreSQL backend. The platform uses each scenario to populate and activate an isolated simulation in which the caller reaches Riley over audio; roughly one-third apply adversarial pressure. The agent can use five tools that execute real SQL against the backend. Each scenario also defines binary assertions. A grader evaluates them against the complete trace of what the caller and agent said and what the agent did, including tool invocations, arguments, and returned rows. This catches an agent that claims to have changed a card without updating the database, as well as one that makes the right database change while disclosing protected information. This first benchmark version focuses on financial services. Its evaluation protocol supports an evolving leaderboard: additional voice agents can be evaluated on the same version, while later versions can expand the tasks and scenarios.

深度讲解Deep dive

VAmoS Bench 用 100 个隔离银行客服场景、真实音频、PostgreSQL 工具和完整轨迹评估语音代理是否真正完成任务，而不只看对话流畅度。

它解决什么问题Problem

WER、自然度、延迟或最终数据库状态都不能单独判断代理是否正确验证用户、按政策顺序执行工具、真实完成请求且没有泄露隐私。

核心方法Core method

每个场景包含数据库初态、来电者目标、说话风格和 1–3 条二元断言。电话启动隔离 PostgreSQL，五个卡务工具执行真实 SQL；统一裁判联合检查转录、调用顺序、参数和返回行，全部断言通过才计为完成。

怎么工作How it works

  1. 为场景创建独立数据库、来电者 persona、私有目标和评分断言。
  2. 模拟来电者通过实时音频与被测代理交互并根据结果继续追问或施压。
  3. 代理执行查用户、查卡、变更状态、申请补卡和更新配送等 SQL 工具。
  4. 平台记录对话、工具顺序、参数和返回行，连接失败也保留。
  5. 裁判逐条验证断言并汇总完成率、连接率、时延、轮次、打断和成本。

论文报告了什么Reported findings

  • 11 个系统完成率从 Nemotron 的 43.0% 到 Pipecat 的 71.0%；Pipecat 与同模型栈 LiveKit 为 71.0% 对 70.3%，论文不认为已统计分胜负。
  • 3245/3300 通电话成功连接，连接率 98.3%，但只有 2081/3300 完成任务，完成率 63.1%。
  • 简单、复杂和对抗场景完成率分别为 65.8%、52.2% 和 73.4%，复杂组对 11 个系统都是最弱组。
  • 直接绕过验证场景为 33/33 通过；重复验证失败时只有 11/33 保密成功，用户要求跳过补卡前冻结步骤时只有 1/33 成功。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：它适合补充 StreamingModelHarness 系统级评测，应联合检查音频交互、工具注入时机、参数、副作用和口头陈述。
  • 编辑判断：基准对级联、混合和原生 S2S 架构一视同仁，Harness 可明确以 endpoint-gated cascaded 系统参测，无需冒充原生全双工。
  • 编辑判断：固定场景和 grader 未完整开放，当前更现实的是借鉴“隔离状态＋路径断言＋说做交叉检查”自建车控基准。

边界与局限Limits

  • 只覆盖 100 个英语银行卡务场景，不能外推到其他行业、语言、口音或真实客户。
  • 每个系统只跑三次，完成率标准误为 0.9–5.5 个百分点，接近榜首的差异不稳定。
  • 使用单一 LLM judge 且无人工金标集，模拟用户真实性也未校准。
  • 评分读取执行轨迹但不在通话后显式查询最终数据库，不能最强确认状态持久性。

代码与模型开放情况Code and model availability

部分开放Partial   MIT 仓库公开多种 Riley 实现、工具逻辑和合成 PostgreSQL schema/seed，但固定 100 场景、断言、完整 grader、轨迹和结果未发布，需 Veris 账户动态生成；该工作没有专用模型权重。
