AVOC: Enhancing Hour-Level Audio-Video Understanding in Omni-Modal LLMs via Retrieval-Inspired Token Compression

论文Paper · arxiv · 2026-06-23 · ◈ 11
摘要Summary
AVOC 把小时级音视频压缩建模为兼顾问题相关性、跨模态重要性和局部时间多样性的 top-K 检索，在 MiniCPM-o 4.5 上改善长视频准确率并缩短 prefill。它必须看到完整输入，不能压缩已写入 Qwen3-Omni 的 KV，也没有 decode、流式或首音频证据。 Multimodal Large Language Models have achieved remarkable progress in short-form audio-video understanding, yet long-form audio-video comprehension remains challenged by limited context windows and severe information redundancy. To address these bottlenecks, we propose AVOC, a framework for long-form audio-video understanding in Omni-modal Large Language Models. AVOC introduces a learnable token compression module between the modality encoders and the LLM backbone. We reframe multimodal token compression as a top-$K$ retrieval problem: given a fixed context budget, the module must retrieve a compact subset of tokens that best supports answering the user query. We draw inspiration from three classical Information Retrieval criteria for selecting informative units from a large candidate pool: relevance, importance, and diversity. AVOC instantiates each criterion as a tailored mechanism for audio-video understanding, and integrates them into a unified retrieval-style compression pipeline. Experiments show that AVOC achieves state-of-the-art performance on long-form audio-video benchmarks, surpassing the second-best model by 4.9 and 5.5 points in average accuracy on OmniVideoBench and LVOmniBench, respectively. Moreover, AVOC maintains robust performance on Audio-Video Needle-in-a-Haystack task at durations up to one hour.

深度讲解Deep dive

AVOC 在模态编码器和 LLM 之间用问题相关性、音视频交叉重要性与局部时间多样性选择 top-K token，改善小时级理解和 prefill，但它必须先看到完整音视频，并非流式 KV 压缩。

它解决什么问题Problem

小时级音视频会超过上下文预算且高度冗余；均匀稀疏采样可能漏掉短事件，而让单一模态指导另一模态又可能在主导信号稀疏时误删信息。

核心方法Core method

文本 token 对音视频 token 的 attention 形成 query-conditioned relevance，时间块内双向 audio↔video attention 形成 query-agnostic importance；各分数按模态 Z-score 后等权融合，再以只惩罚局部同模态冗余的 TA-MMR 分配独立音频/视频预算。模型基于 MiniCPM-o 4.5，两阶段微调压缩器和 LLM，训练用 straight-through Gumbel hard mask，TA-MMR 只在推理启用。

怎么工作How it works

  1. 编码完整音频和视频并按时间块交错。
  2. 由文本问题计算相关性，由跨模态 attention 计算重要性。
  3. 融合标准化分数，分别对音频和视频执行 TA-MMR top-K。
  4. 按时间重排保留 token，再执行较短的 LLM prefill 与回答。

论文报告了什么Reported findings

  • AVOC 在 WorldSense、OmniVideoBench 和 LVOmniBench 的平均准确率分别为 52.6、42.3 和 40.3；后两项比论文第二名高 4.9 与 5.5 点。
  • 单张 A800、10 分钟视频实验中，保留率 0.1 时 prefill 从 MiniCPM-o 4.5 的 4.453s 降至 0.497s，但压缩器另耗 0.260s，TTFT 为 22.549s。
  • 正文的 AV-NIAH 热力图覆盖最长 3,600s，但只用一个源视频和 5 个随机六位数字，未给统一汇总准确率。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 更适合在 faster-whisper+RAG 路径试验“问题相关性+局部 MMR”，或未来在 endpoint 后对尚未写入 LLM KV 的编码器 token 重建短上下文。
  • AVOC 不能回收已持续写入 Qwen3-Omni 的 KV，也没有 decode ms/token、流式或 TTS 证据，不能解决当前 110ms/token 和约 3 秒首音频。

边界与局限Limits

  • 附录明确说明必须等待完整音视频，不能直接增量 streaming。
  • 只在一个 MiniCPM-o 4.5 规模和固定音视频预算比例上验证，迁移 Qwen3-Omni 需要重训。
  • 普通长视频评估对超过 320 秒的视频只均匀取 320 帧，且效率实验未报告 KV 显存、decode 吞吐或首音频。
