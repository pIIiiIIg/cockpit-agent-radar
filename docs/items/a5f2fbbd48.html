OmniScope: Modality-Decoupled Token Compression for Omnimodal Large Language Models

论文Paper · hf · 2026-07-27 · ◈ 10
摘要Summary
Existing token compression methods for omnimodal large language models typically rely on one modality to determine what to retain in the other. We show that this assumption often breaks down: for the same query, audio and video relevance often peaks at different moments. This cross-modal salience mismatch makes unidirectional guidance prone to discarding answer-critical cues under aggressive compression. We propose OmniScope, a training-free token compression framework that uses the query as a shared semantic anchor while estimating relevance separately for audio and video. OmniScope allocates modality-specific token budgets, prunes visual tokens with an anchor-delta strategy that preserves both global context and temporal changes, and merges audio tokens within each second to reduce redundancy while maintaining temporal continuity. Across four audio-video benchmarks and two Qwen2.5-Omni model scales, OmniScope achieves the best average accuracy across all compression settings. At 25% overall token retention, it delivers up to 3.53x prefill speedup and more than 15% GPU memory reduction, with only a 0.35-point drop in average accuracy. These results suggest a simple design principle for OmniLLM inference: share the query across modalities, but not the salience estimates. The code is available at https://github.com/MAC-AutoML/OmniScope. 深度讲解Deep dive

OmniScope 是免训练的音视频 token 压缩方案：共享查询语义，但分别估计视频与音频显著性；7B 模型约保留 25% token 时平均准确率只降 0.35 点，prefill 加速 3.53×。

它解决什么问题Problem

已有 OmniZip/OmniSIFT 类方法让一个模态指导另一个模态压缩，但同一查询下音频和视觉关键时刻经常错位，激进压缩时会误删答案线索。

核心方法Core method

视觉侧以 CLIP ViT-L/14@336 编码帧和查询并计算余弦相关性；音频侧复用 Qwen2.5-Omni 音频 encoder 投影 token，与查询 embedding 计算门控相似度并按秒聚合、向邻秒传播。两模态按各自分数独立分配预算。AD-STC 对视频采用 Anchor–Delta：偶数帧以 DPC-KNN 保留低密度独特 token，奇数帧按帧内/跨帧可替代性或相对 Anchor 的变化剪枝；音频在每秒窗口内执行 bipartite soft matching，融合最相似 token。

怎么工作How it works

  1. 用查询分别计算视觉帧和音频秒级相关性。
  2. 在每个模态内部独立分配保留预算。
  3. 对视频执行 Anchor–Delta 空时剪枝。
  4. 对音频逐秒合并 token，再送入 OmniLLM。

论文报告了什么Reported findings

  • DailyOmni 的 1,197 个 query-video 对中，78.3% 的音频/视觉显著性 Spearman 相关满足 |ρ|<0.3。
  • 7B、25% 保留时 Full Tokens 平均 51.35，OmniScope 51.00（-0.35），OmniZip 49.80（-1.55）；3B 为 50.15→48.65。
  • 7B、45% 保留时平均准确率由 51.35 升至 51.65；3B 为 50.15→50.18。
  • 7B、25% 保留时峰值显存 28.31→24.00 GB，prefill 6299.90→1784.45 ms（3.53×），E2E 10.965→4.792 秒。
  • 查询引导消融中完整方案平均 52.70，音视频统一预算 51.05，最佳单向引导变体 52.40。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：音频分支有参考价值，但 OmniScope 假设压缩前已知 query；Harness 先把流式音频写入 KV、endpoint 后生成且工具晚注入，已有 KV 无法随新 query 自动重排。
  • 编辑判断：Harness 当前没有连续视频输入，AD-STC 不是现成能力，更不能据此描述为原生音视频全双工。
  • 编辑判断：论文只证明离线 MCQ 的 prefill 压缩，未覆盖多轮持久 KV、迟到工具或长生成，因此不能证明改善持久 KV 准确率。

边界与局限Limits

  • 只验证 Qwen2.5-Omni 3B/7B 和四个离线 QA benchmark。
  • 依赖 query 预先存在，未评估查询后到达、持续更新或真实在线场景。
  • 外部 CLIP 有固定成本：7B、45% 时 E2E 5.284 秒，慢于 OmniZip 的 4.508 秒。

代码与模型开放情况Code and model availability

已开放Open   Apache-2.0 代码已公开；方法免训练，无专用权重，依赖外部 Qwen2.5-Omni、CLIP 和多个 benchmark。仓库仅含 WorldSense 格式 JSON、不含完整媒体，外部模型与数据许可需分别遵守；README 的 Project Page 错指 Video-RAG。
