DCAS: Decoupling CLI Agent Scaffolding to Internalize Planning across Scaffolds

论文Paper · hf · 2026-08-05 · ◈ 4
摘要Summary
DCAS 发现，CLI 编码模型在 OpenHands 轨迹上微调后会学习该 scaffold 的规划惯例，换到 Claude Code、OpenCode 或 mini-swe-agent 时性能明显分化。它通过 API 后端替换层做受控跨 scaffold 路由，并显示少量同时包含规划与执行的轨迹能把部分规划能力内化到模型中。 CLI-based software-engineering agents have matured rapidly, yet the open ecosystem has converged on a single training environment: trajectory datasets used to fine-tune open models are collected almost exclusively under OpenHands. Models fine-tuned on this data score well under OpenHands but degrade substantially when deployed under any non-training scaffold. Untrained base models do not show this divergence, indicating the gap is fine-tuning-induced and tied to the conventions of the training scaffold. We argue that a load-bearing scaffold-specific behavior is planning structure, in two senses this paper distinguishes: explicit planning, a pre-execution plan produced as a first-class artifact, and implicit planning, the structural conventions that shape execution throughout the agent loop. Under this hypothesis, closing the gap requires moving planning from a fixed scaffold artifact to a learned model capability. We introduce Decoupling CLI Agent Scaffolding (DCAS), a backend-substitution interception layer that routes API traffic between any CLI scaffold and any backend model without modifying the scaffold, enabling cross-scaffold evaluation and planning-aware trajectory collection. Using DCAS, a controlled plan-source intervention confirms planning quality is a high-leverage component, with gains exceeding the cross-scaffold drops we observe. A model fine-tuned on a small set of DCAS-collected planning-aware trajectories under a single scaffold gains consistently across non-training scaffolds, and the two senses of planning are empirically separable in training data.

深度讲解Deep dive

把 scaffold 与模型后端解耦后，论文把显式“先写计划”和隐式“如何分解、调用工具、失败后重规划”分开测量，并用 576 条规划感知轨迹训练出更可迁移的执行器。

它解决什么问题Problem

开放编码模型的训练轨迹几乎都来自 OpenHands，微调模型在同一 scaffold 下得分高，却在未见 scaffold 下退化；基础模型反而没有同样大的分化。这说明单一分数混合了模型能力和 scaffold 习惯，但既有工具难以在不改 scaffold 的情况下替换后端、采集不同规划结构的轨迹并公平评测。

核心方法Core method

DCAS 是一个后端替换拦截层，把任意 CLI scaffold 的 API 流量路由到指定模型，同时保留 scaffold 自身提示、工具 schema 和 turn 管理。论文先做计划来源干预，在同一执行器和 scaffold 下比较无计划、自规划、开放权重规划器和 frontier 规划器；再采集 Claude Code 中的 planning-aware 成功轨迹，构造仅计划（PlanOnly）与计划加执行（Plan+Exec）两种 SFT 数据，最后跨版本和跨 scaffold 测试。

怎么工作How it works

  1. 通过 DCAS 拦截目标 CLI scaffold 的后端请求，将其转换并路由到受控模型而不修改 scaffold。
  2. 固定 Qwen3-Coder 执行器、Claude Code 版本和 SWE-bench Verified，替换显式计划来源以隔离计划质量的贡献。
  3. 对成功轨迹做保留与拒绝采样，分别形成 PlanOnly 和 Plan+Exec 训练集并进行监督微调。
  4. 在训练版本、新版 Claude Code、OpenCode 和 mini-swe-agent 上分别测试无计划与自规划条件，比较显式和隐式规划的迁移。

论文报告了什么Reported findings

  • Qwen3-Coder-30B-A3B-Instruct 在 Claude Code 无计划时 Pass@1 为 42.8%；自规划提高到 48.2%（+5.4 个百分点），Qwen3-Coder-480B-A35B 计划提高到 49.2%（+6.4 个百分点）。
  • Claude Sonnet 4.5 提供计划时达到 57.8%，比无计划高 15.0 个百分点；Claude Opus 4.5 为 54.2% 至 56.0%。
  • PlanOnly 微调后，无计划达到 53.8%，而自规划为 53.2%；Plan+Exec 无计划为 52.8%，自规划进一步达到 55.8%。
  • Plan+Exec 在新版 Claude Code 2.1.73 上无计划与自规划分别为 54.6% 和 57.2%，均高于训练版本 2.0.76 的 52.8% 和 55.8%。
  • Plan+Exec 自规划在 OpenCode 达到 49.4%，相对基础模型无计划的 46.0% 提高 3.4 个百分点；在 mini-swe-agent 达到 42.4%，相对 35.4% 提高 7.0 个百分点。
  • DCAS 训练使用 576 条保留轨迹，论文称其规模比常见的数千到数万条 OpenHands 轨迹集小一个数量级或更多。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 这篇论文对 StreamingModelHarness 的架构思考高度相关：应把底层模型能力与 EOU、工具 schema、晚期工具注入、状态管理等 harness 约定分开评测，避免把单一编排下的结果当成模型固有能力。
  • 可借鉴 DCAS 的后端替换与跨 scaffold 矩阵，为相同语音模型比较不同话尾策略、工具注入时机和 TTS 编排，并把配置随成绩一起报告。
  • 实证只来自 CLI 软件工程 agent，不能直接推出语音场景同样受规划惯例支配；它也没有把分阶段 Harness 变成模型层原生全双工系统。

边界与局限Limits

  • 核心因果干预集中在一个 Qwen3-Coder 执行器、SWE-bench Verified 和少数 CLI scaffold，跨模型与跨任务外推仍有限。
  • 最强显式计划结果依赖 proprietary frontier planner，且 Sonnet 优于 Opus 表明 planner—executor 校准会混入“规划器更强”的简单解释。
  • 576 条训练轨迹来自成功运行并经拒绝采样，可能偏向较易任务或特定 Claude Code 行为。
  • 跨 scaffold 增益幅度差异明显，在最接近训练结构的 Claude Code 上最大，因此“完全 scaffold 无关”并未被证明。
