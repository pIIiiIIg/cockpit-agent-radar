FastTurn: Unifying Acoustic and Streaming Semantic Cues for Low-Latency and Robust Turn Detection

深度讲解Deep dive

FastTurn 融合 streaming CTC 部分转写、Conformer 声学表示和 Qwen3-0.6B 语义状态，判断 Complete、Incomplete、Backchannel、Wait；它是判停器，不是语音生成模型。

它解决什么问题Problem

纯 VAD 不懂停顿与语义，完整 ASR→文本模型级联又增加延迟并在重叠和噪声下退化；判停器需要同时利用尽早出现的转写前缀和韵律声学线索。

核心方法Core method

约 80M 的 12 层 Conformer 运行流式 CTC，部分转写被包装为 prompt 送入 Qwen3-0.6B。四层 LLM adapter 将声学表示映射到语言 embedding，另一个 acoustic adapter 保留细粒度声学状态，两路融合后由三层 MLP 分类；训练依次进行语义预训练、模态对齐、联合训练和模态融合。

怎么工作How it works

  1. 对流式音频运行 Conformer 和 greedy CTC，尽早产生部分转写。
  2. 将 CTC prompt 与映射后的声学 embedding 输入 Qwen3-0.6B。
  3. 用 prompt dropout 降低模型对错误转写的依赖。
  4. 融合声学与语言隐藏状态，输出 Complete、Incomplete、Backchannel 或 Wait。

对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：与 Harness 的生成前 endpoint 最匹配，可把二元 speech/silence 扩为四状态，仅 Complete 触发生成，late tool injection 仍留在下游。
  • 编辑判断：无代码和权重，120.1ms 的计时定义与硬件也不完整；采用其思路不会让判停后生成、外挂 TTS 的 Harness 变成原生模型级全双工。

边界与局限Limits

  • 训练混入内部会话数据；Wait 类全由 DeepSeek V3 与 IndexTTS2 合成，且类别和时长高度不均衡。
  • 平均延迟没有定义计时起止、batch、音频长度或推理硬件，正文也没有噪声强度和 overlap 分层结果。
  • 未报告标注者一致性、置信区间或多次运行方差，英文子集也没有稳定超过基线。
