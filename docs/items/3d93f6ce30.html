Stockmark-Nemotron-3-Nano-Omni-JapanDocReader: Structured Document Parsing via Capability Injection and Forgetting Control

论文Paper · arxiv · 2026-08-07 · ◈ 8
摘要Summary
Stockmark-Nemotron-3-Nano-Omni-JapanDocReader 通过混合 SFT 与 DAPO 解析向强化学习，把日文结构化文档解析注入推理型多模态基座，并把 DocParse-Overall 从70.43提升到87.67。对 StreamingModelHarness 几乎无直接接口，仅在“能力注入 vs 遗忘控制”的后训练取舍上有弱相关。 We present Stockmark-Nemotron-3-Nano-Omni-JapanDocReader, a Japanese document understanding model built from Nemotron-3-Nano-Omni-30B-A3B-Reasoning-BF16. The central goal of this work is structured document parsing via capability injection and forgetting control: we inject Japanese structured document parsing capability into a reasoning-oriented multimodal model while preserving its document VQA capability as much as possible. We study parsing-centric SFT, which uses only structured document parsing data; mixed SFT, which combines structured document parsing and VQA data; and parsing-centric RL, which optimizes structured parsing with a task-level reward. Our experiments show that parsing-centric SFT substantially improves structured document parsing performance but causes measurable VQA forgetting. Mixed SFT mitigates this forgetting while preserving nearly the same structured parsing performance. Applying DAPO-based parsing-centric RL on top of the mixed SFT checkpoint further improves structured document parsing beyond the SFT ceiling, producing the final released model. The training data is constructed with a data engine consisting of two complementary synthetic streams: a Japanese Document VQA Stream and a programmatic structured document parsing stream. We also discuss reward design and variance-based prompt filtering for continuous structured document parsing rewards, highlighting their importance for making RL effective in long-reasoning structured document parsing tasks.

深度讲解Deep dive

该报告用混合 SFT 控制遗忘，再用 DAPO 解析向 RL 把日文结构化文档解析注入 Nemotron-3-Nano-Omni，最终 DocParse-Overall 达87.67。

它解决什么问题Problem

要把结构化文档解析能力注入以推理为导向的多模态基座，同时又尽量保留原有日文文档 VQA，避免解析中心微调造成明显遗忘。

核心方法Core method

构建日文文档 VQA 与程序化结构化解析两条数据流；比较解析中心 SFT 与混合 SFT；再在混合 SFT 检查点上做 DAPO/GSPO 解析向 RL，奖励含文本编辑、表格 TEDS、公式 CDM 等元素匹配分量。

怎么工作How it works

  1. 用数据引擎生成日文文档 VQA 与结构化解析样本。
  2. 先做能力注入式 SFT，重点比较纯解析 SFT 与混合 SFT。
  3. 以混合 SFT 为参考策略，进行解析向强化学习并过滤高方差提示。
  4. 按 DocParse-Overall 与 VQA-Overall 选择最终发布模型。

论文报告了什么Reported findings

  • 解析中心 SFT 把 DocParse-Overall 从70.43提到86.56，但 VQA-Overall 从0.863降到0.826。
  • 混合 SFT 的 DocParse-Overall 约86.60，同时把 VQA-Overall 恢复到0.844量级。
  • 混合 SFT + DAPO 进一步把 DocParse-Overall 提到87.67，公式 CDM 从89.48到92.87；GSPO 反而降到84.01。
  • 最终模型 Table TEDS 87.25，Reading Order Edit 0.2366，并在开放权重对比中报告领先。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 与座舱语音双工主链关系很弱；不应用于改写 StreamingModelHarness 的判停/TTS 路径。
  • 可借鉴其“混合数据缓解遗忘、再 RL 推高专项能力”的后训练次序，若未来要给 Harness 侧车视觉文档能力做增量注入。
  • 发布模型面向日文文档 JSON 结构化输出，不是实时语音交互系统。

边界与局限Limits

  • 评测以文档解析/VQA 为主，无车载噪声、打断或工具调用指标。
  • 能力与遗忘的平衡仍存在：最终 RL 后 VQA-Overall 会相对混合 SFT 有所回落。
  • 依赖较大多模态基座与专用数据引擎，部署成本高。
