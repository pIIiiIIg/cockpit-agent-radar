Sema: Semantic Transport for Real-Time Multimodal Agents

论文Paper · arxiv · 2026-04-22 · ◈ 19
摘要Summary
Sema 在客户端把音频和截图压成离散语音、结构化 UI 文本与视觉 token，论文仿真把三秒语音和截图分别压缩 64× 与 130–210×。它可作为 Harness 判停前的语义传输层，但 v1 不是端到端实现，也不处理生成、晚注入工具或原生全双工。 Real-time multimodal agents transport raw audio and screenshots using networking stacks designed for human receivers, which optimize for perceptual fidelity and smooth playout. Yet agent models act as event-driven processors with no inherent sense of physical time, consuming task-relevant semantics rather than reconstructing signals in real time. This fundamental difference shifts the transport goal from the technical problem of signal fidelity (Shannon-Weaver Level A) to the semantic problem of meaning preservation (Level B). This mismatch imposes significant overhead. In visual pipelines, screenshot upload accounts for over 60% of end-to-end action latency on constrained uplinks, and in voice pipelines, conventional transport carries massive redundancy, sending 43-64x more data than needed to maintain task accuracy. We present Sema, a semantic transport system that combines discrete audio tokenizers with a hybrid screen representation (lossless accessibility-tree or OCR text, plus compact visual tokens) and bursty token delivery that eliminates jitter buffers. In simulations under emulated WAN conditions, Sema reduces uplink bandwidth by 64x for audio and 130-210x for screenshots while preserving task accuracy within 0.7 percentage points of the raw baseline.

深度讲解Deep dive

Sema 在客户端先提取模型需要的离散语音、结构化 UI 文本和视觉 token，再突发传输；v1 证明的是 WAN 仿真潜力，不是已部署全双工系统。

它解决什么问题Problem

现有实时多模态系统沿用面向人类的 Opus、WebP、连续播放和抖动缓冲，优化感知保真度；模型真正消费的是语言、UI 元素和空间关系，原始媒体传输因此造成冗余带宽与等待。

核心方法Core method

语音只传 SpeechTokenizer 或 EnCodec 第一层 RVQ 的离散索引；截图用可访问性树/DOM/OCR 的无损文本加视觉 token 混合表示。服务端重构媒体并送入 Whisper 或 Qwen2.5-VL，下行语音 token 则交给客户端声码器。

怎么工作How it works

  1. 客户端捕获一轮音频或截图。
  2. 执行语音离散化，或提取 UI 文本并编码视觉 token。
  3. 通过带模态、码本和序列信息的帧突发上传。
  4. 服务端重构媒体并调用下游 ASR 或 VLM。
  5. 返回紧凑动作文本，或把语音 token 交给客户端声码器。

论文报告了什么Reported findings

  • 三秒语音由 Opus 的 12KB 降至 188B，为 64×；截图由 WebP 的 700KB 降至 3–5KB，为 130–210×。
  • 在 5Mbps 上行，截图基线约 1.1 秒；Sema 使用可访问性树约 75ms、OCR 回退约 105ms。在 1Mbps 时基线约 5.6 秒，主路径低于 100ms。
  • 视觉文本任务中，仅视觉 token 为 75.5%；加入结构化文本后为 93.3%，原始输入为 94.0%。
  • 语音 WER 由 2.7% 增至 4.1%；导航动作准确率与原始输入相差不超过 2 个百分点。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：Sema 最适合放在 StreamingModelHarness 输入采集与语义判停之前，作为客户端语义压缩和传输层，而不是替换生成模型。
  • 编辑判断：Harness 判停后生成并使用外挂 TTS，与 Sema 假设的服务端语音 token 和客户端声码器不同，不能据此宣称原生全双工。
  • 编辑判断：Sema 不解决晚注入工具、工具调度或生成中工具交互，主要价值是降低输入上传成本和抖动敏感性。

边界与局限Limits

  • v1 明确是按组件实测参数拼接的仿真，端到端实现、异构客户端、真实尾延迟和丢包恢复均未验证。
  • 视觉收益在约 80Mbps 以上趋于边际，语音净延迟收益主要出现在约 2Mbps 以下。
  • 视觉 token 单独处理小字明显退化，系统依赖可访问性树或 OCR，画布、游戏和远程桌面仍困难。
  • 摘要“准确率在 0.7 个百分点内”只直接对应视觉文本结果，语音 WER 不满足同一差值。
