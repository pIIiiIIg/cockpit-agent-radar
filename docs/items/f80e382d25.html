ContinualSkillBench: Can LLM Agents Truly Evolve Their Capabilities?

论文Paper · hf · 2026-08-03 · ◈ 5
摘要Summary
ContinualSkillBench 表明顺序交互通常能提升 Agent 表现，但平均增益大多可由保留上下文和反馈解释，不能直接等同于技能能力扩展。显式技能在严格格式和可重复程序上有选择性价值，当前系统仍难稳定压缩可迁移经验。 Modern agent frameworks equip large language models with external skill libraries to solve complex tasks. However, it remains unclear whether these systems can effectively evolve their skills and whether the resulting skills improve task-solving capabilities. To bridge this gap, we introduce ContinualSkillBench, a dynamic evaluation framework for in-context continual skill learning. It covers five representative domains, each containing 100 interconnected subtasks ordered by increasing difficulty and opportunities for cross-task skill reuse. Our experiments show that sequential execution generally improves performance, but the gains vary substantially across models and domains. Moreover, in-context learning performs comparably to explicit skill maintenance on average, suggesting that much of the improvement arises from adaptation to prior context and feedback rather than reusable skill abstraction alone. Explicit skills nevertheless provide selective benefits for tasks requiring reusable procedures or precise outputs. We further find that less capable models tend to accumulate larger, more fragmented collections of task-specific skills. These findings show that current in-context skill evolution mechanisms can support continual adaptation, but still struggle to consistently consolidate experience into robust and transferable skills.

深度讲解Deep dive

ContinualSkillBench 用五条各含 100 个递进任务的领域序列，区分“保留上下文带来的适应”与“显式技能库真正带来的能力扩展”。

它解决什么问题Problem

Agent 顺序执行任务时的提升究竟来自可复用技能，还是只来自保留上下文、反馈和输出格式适应，此前缺少系统评测。

核心方法Core method

作者从约 3 万个候选任务构造 Finance、Healthcare、Law、Math、Office 五条技能依赖序列，比较 independent、纯 ICL、显式 skill-maintaining sequential 和 RAG 条件。

怎么工作How it works

  1. 汇集多层难度的领域 benchmark 任务。
  2. 由 LLM 标注技能与难度、判断成对迁移方向并图排序，再人工审核。
  3. Agent 接收任务和当前技能库，执行后由外部 evaluator 评分。
  4. 将评分反馈注入反思回合，创建或修改技能。
  5. 新技能从下一子任务开始可用，并与独立执行和 ICL 基线比较。

论文报告了什么Reported findings

  • 顺序执行在 15 个模型×领域组合中提高了 13 个 raw reward 和 14 个 normalized reward；宏平均绝对增益为 +0.071/+0.078，相对增益为 16.2%/16.9%。
  • GPT-5.3-Codex 平均 normalized 增益最大，为 +0.098；Healthcare 跨模型平均增益最大，为 +0.149。
  • 三个消融领域中，Independent、纯 ICL、显式技能 Seq 的平均 normalized reward 分别为 0.466、0.605、0.602，显式技能没有稳定超过 ICL。
  • GPT-4o 生成 384 个技能、平均质量 5.68；GPT-5.3-Codex 只生成 205 个，但平均质量为 7.94。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 最直接的 Harness 实验是按 commit 边界比较 Independent、保留上下文 ICL 和显式技能库；应先证明技能库超过简单上下文保留。
  • 三回合协议可映射为“提交—执行—迟到工具/评分结果注入—下一次提交”，不要求输入流期间生成。
  • benchmark 不涉及语音、外置 TTS 或模型级全双工，只能支持跨回合持续适应。

边界与局限Limits

  • 任务来自固定来源，只测试三种模型和有限 harness，未覆盖长尾分布和更多 Agent 框架。
  • ICL 对照只测试 GPT-5.3-Codex 的三个领域，RAG 消融只报告 Opus 4.7/Healthcare。
  • 评测混用 exact、numeric、程序测试和 LLM rubric；normalized reward 只计算双方都有有效输出的交集。
  • 公开仓库还含论文五领域实验未报告的 science-100，论文与仓库数据范围缺少清晰版本标记。
