Discourse-Aware Dual-Track Streaming Response for Low-Latency Spoken Dialogue Systems

论文Paper · arxiv · 2026-02-26 · ◈ 11
摘要Summary
DDTSR 让小模型根据 partial ASR 提前说低承诺连接词，同时由大模型生成主体回答，SD-Eval、8B 条件下平均等待由 1003ms 降至 548ms。它与 Harness 的级联加外挂 TTS 路线相容，但收益要求端点前发声，工具结果确定前只能使用无命题开场。 Achieving human-like responsiveness is a critical yet challenging goal for cascaded spoken dialogue systems. Conventional ASR-LLM-TTS pipelines follow a strictly sequential paradigm, requiring complete transcription and full reasoning before speech synthesis can begin, which results in high response latency. We propose the Discourse-Aware Dual-Track Streaming Response (DDTSR) framework, a low-latency architecture that enables listen-while-thinking and speak-while-thinking. DDTSR is built upon three key mechanisms: (1) connective-guided small-large model synergy, where an auxiliary small model generates minimal-committal discourse connectives while a large model performs knowledge-intensive reasoning in parallel; (2) streaming-based cross-modal collaboration, which dynamically overlaps ASR, LLM inference, and TTS to advance the earliest speakable moment; and (3) curriculum-learning-based discourse continuity enhancement, which maintains coherence and logical consistency between early responses and subsequent reasoning outputs. Experiments on two spoken dialogue benchmarks demonstrate that DDTSR reduces response latency by 19%-51% while preserving discourse quality. Further analysis shows that DDTSR functions as a plug-and-play module compatible with diverse LLM backbones, and remains robust across varying utterance lengths, indicating strong practicality and scalability for real-time spoken interaction.

深度讲解Deep dive

DDTSR 让小模型根据 partial ASR 提前说低承诺连接词，同时由大模型处理实质回答，以跨模态并行压缩级联语音助手的等待。

它解决什么问题Problem

严格串行的 ASR–LLM–TTS 必须等待转写、完整推理和合成启动；单纯加速某个组件无法解除整个链路的时序依赖。

核心方法Core method

Qwen3-0.6B 在部分转写上生成连接词和 commit 信号，Qwen3-8B/32B 在最终转写上生成主体回答；课程学习、连贯性损失和置信度阈值用于降低提前发声与后续答案不一致的风险。

怎么工作How it works

  1. 用 POS 规则和 LLM 构造“输入—连接词—回答”数据并以课程学习微调小模型。
  2. 流式 ASR 持续产生 partial transcript，小模型在每次更新预测连接词和 commit。
  3. 置信度首次过阈值时由 CosyVoice2 立即合成连接词，可能早于用户说完。
  4. 最终转写到达后，大模型生成主体回答并执行增量 TTS。
  5. 连接词音频结束后顺序衔接主体回答音频。

论文报告了什么Reported findings

  • SD-Eval、8B 条件下，平均 waiting latency 由 SSC 的 1003ms 降至 548ms，降低 45.4%；有连接词的最优条件为 515ms。
  • SpokenNativQA、8B 条件下表格值为 931→741ms，32B 为 1022→828ms；正文称前者降低 17.5%，但按数值计算约 20.4%。
  • SD-Eval、8B 上，DDTSR 的一致性/连贯性为 4.77/4.49，SSC 为 4.76/4.54；UTMOSv2 为 3.12 对 3.16。
  • SD-Eval 输入变长时 waiting latency 降幅由 38.3% 增至 58.3%，perception latency 约维持 100ms。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：它直接挑战 Harness 等待 endpoint 的规则；主要收益要求小模型消费 partial ASR 并允许端点前播放低承诺连接词，不是即插即用。
  • 编辑判断：方案仍是级联架构并使用外挂增量 TTS，适合组件化方向，但属于双轨时序编排而非原生全双工模型。
  • 编辑判断：晚注入工具时只能提前播放无命题连接词，不能承诺答案；论文未评工具失败、取消、抢话或回滚。

边界与局限Limits

  • 实验只覆盖 SD-Eval 和 SpokenNativQA，文本和语音质量由 G-Eval 与 UTMOSv2 自动评估，没有人工听测。
  • 收益依赖连接词机会：SD-Eval 连接词比例为 94%，SpokenNativQA 只有 38%，更适合休闲口语场景。
  • 回答正确性因共用大模型而被假定受控，没有直接测量。
  • SpokenNativQA 的正文百分比与表格数值不一致。
