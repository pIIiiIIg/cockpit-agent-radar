OPOD: On-Policy Omni Distillation

论文Paper · arxiv · 2026-07-23 · ◈ 9
摘要Summary
OPOD 通过单边 token 指导、按模态独立控制和教师轨迹验证，将文本、图像与音频专家蒸馏为一个 omni-modal student，30B/7B/3B 在十二项 accuracy 简单平均上分别达到 70.8/51.7/46.2。它可作为 StreamingModelHarness 判停后的推理模型候选，但不提供增量音频、全双工、工具编排或已验证的语音生成能力。 Omni-modal models provide a unified interface for text, images, and audio. However, improving these abilities together remains difficult, as post-training on pooled multimodal data often fails to preserve the strengths of modality teachers. On-policy distillation (OPD) has recently become popular in model post-training. It samples responses from the current student and compares the teacher's and student's next-token distributions along those responses, yielding dense supervision while reducing the mismatch between training and inference. Despite these advantages, standard OPD does not readily extend to several modality teachers. Their guidance may favor conflicting changes to the shared model, while matching each teacher's next-token distribution can prevent the student from moving beyond that teacher. To address these challenges, we propose On-Policy Omni Distillation (OPOD), which consolidates text, image, and audio teachers into one omni model. OPOD routes each response to the corresponding teacher, controls the teachers independently, and applies guidance only when the teacher assigns a higher probability to the generated token. The selected teacher also evaluates answer confidence and whether the reasoning increases support for the answer. Extensive experiments on twelve benchmarks show that OPOD achieves the best average at three model scales, reaching 70.8, 51.7, and 46.2 and outperforming the strongest comparator by 2.1, 1.8, and 1.7 points. At 30B, it surpasses the base model and pooled RL training on all twelve benchmarks, and ranks first or second on eleven even when the teachers are included. Only the student is retained for deployment.

深度讲解Deep dive

OPOD 用单边 token 指导、按模态独立的约束控制和教师轨迹验证，把文本、图像与音频专家蒸馏为一个 omni-modal student；它改善端点后的多模态推理，但不提供流式语音或工具调度。

它解决什么问题Problem

把多模态数据直接混合做 GRPO 难保留各专家优势；标准 on-policy distillation 又会产生教师冲突，并在学生已超过教师的 token 上仍把分布拉回，形成 teacher ceiling。

核心方法Core method

Student 先按当前策略 rollout，再按输入模态路由给固定教师在同一 prefix 上评分。OPOD 只保留教师概率高于学生的正 margin，各模态分别维护约束预算和 β；教师还评估正确答案区域的置信度，以及学生 reasoning 是否提高对 gold answer 的支持。任务/过程奖励组内标准化后与 reference KL 共同更新 student，部署时丢弃教师。

怎么工作How it works

  1. 从同一 backbone 分别训练文本、图像和音频教师。
  2. Student 每个 prompt 采样 8 条 rollout，并按模态送给对应教师。
  3. 计算单边 token 约束、答案置信度和 reasoning gain。
  4. 按模态更新约束权重，合并奖励与 reference KL 更新共享 student。
  5. 训练后仅部署 student。

论文报告了什么Reported findings

  • 12 项 accuracy 简单平均中，30B、7B、3B OPOD 分别为 70.8、51.7、46.2；对应 Base 为 67.0、46.9、40.7。
  • 30B 相对 Base、混合 GRPO、Native OPD、ExOPD 和最强教师分别高 3.8、3.5、2.9、2.2、2.1 点；逐 benchmark 教师 oracle 平均 70.3。
  • 完整模型 70.8；移除单边指导、模态控制或验证奖励后分别为 69.0、68.6、68.8。所有配置只跑一个固定 seed。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 公开 student 可作为 endpoint 后的多模态 reasoning backend 候选，部署时不需要教师 ensemble，仍可保留现有确定性执行器和外部 TTS。
  • 论文没有增量音频、首包、barge-in、late tool schema 或工具时序实验；官方卡也说明 talker 未优化和未评测，不能称原生全双工或据此替换 TTS。

边界与局限Limits

  • 每个配置单次运行，没有方差、置信区间或显著性；异构 benchmark 的简单平均不代表统一任务分布。
  • v3 两次引用的补充材料不在 PDF 或 arXiv source 中，训练数据来源、过滤和逐项许可无法从论文附件核验。
  • 训练依赖在线教师 logits 和约 32×H20，教师校准偏差也可能进入 answer confidence 与 reasoning gain。
