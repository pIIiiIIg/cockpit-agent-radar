MECoBench: A Systematic Study of Multimodal Agent Collaboration in Embodied Environments

论文Paper · arxiv · 2026-06-30 · ◈ 12
摘要Summary
MECoBench 在视觉具身环境中系统控制团队规模、通信协议和空间依赖，显示协作收益呈倒 U 型，通信可增益也会放大冲突和错误信念。它适合作为 StreamingModelHarness 多 agent 消息与工具编排的离散回归基准，而非实时语音或模型层全双工证据。 Recent multimodal large language models (MLLMs) have strong potential as embodied agents, but their ability to collaborate in visually grounded environments remains underexplored. To address this gap, we introduce MECoBench, a multimodal embodied cooperation benchmark with an evaluation platform spanning diverse real-world tasks, two cooperation structures, and three collaboration modes. Through extensive experiments across various MLLMs, we summarize three key findings: (i) Collaboration generally improves embodied task completion, but its benefits depend on balancing collaborative gains against coordination complexity. (ii) Communication is essential to collaboration gains, while the best collaboration mode depends on team size and model capability. (iii) Moreover, collaboration improves robustness under noisy priors and exploration conditions. Generally, MECoBench provides a systematic testbed for understanding the mechanisms and limits of multimodal embodied collaboration. Code and dataset are available at https://github.com/q-i-n-g/MECoBench.

深度讲解Deep dive

MECoBench 在 VirtualHome 中用 192 个视觉具身协作案例系统改变协作结构、团队规模和通信协议，发现协作收益呈倒 U 型，通信既是主要驱动力，也会传播冲突和错误信念。

它解决什么问题Problem

既有多 agent benchmark 常用文本化或共享符号状态，难以同时测量第一视角视觉感知、探索、空间约束、通信和实体动作之间的耦合。

核心方法Core method

96 个任务来自 8 种家庭活动模板，每个任务分别构造 parallel 和 sequential 设置，共 192 个案例；支持 isolated、decentralized、centralized 三类模式，以及 no communication、broadcast、discussion、leader-worker 协议。每步 agent 读取四视角第一人称图像、目标、先验、历史与记忆，先通信再生成语义动作，decoder grounding 到 simulator object ID 后并发执行，并以 SR、CR、Step-CR AUC、成本、分工和冲突指标评估。

怎么工作How it works

  1. 从任务模板采样目标并实例化合法场景。
  2. 指定 parallel 或区域隔离且需 handover 的 sequential 结构。
  3. agent 获取全景视觉、目标、先验和记忆。
  4. 按协议通信，再规划、grounding 并执行动作。
  5. 更新环境与记忆，循环到成功或步数耗尽并计算协作指标。

论文报告了什么Reported findings

  • 论文表 8 报告：parallel 中 Qwen3-32B-VL 的 SR 从单 agent 0.583 升至双 agent 0.802，但 InternVL-3.5-241B 从 0.833 降至 0.719。
  • 论文表 9 报告：Qwen3-32B-VL 在 1–5 agent 时 SR 为 0.583/0.802/0.833/0.844/0.740，显示团队扩大后的倒 U 型。
  • 论文表 11 报告：移除通信后，sequential SR 在 Gemma4-31B 上从 0.823 降至 0.177，在 Qwen3.5-9B 上从 0.615 降至 0.062。
  • 论文表 22 报告：Qwen3-32B-VL 扩到 5 agent 时 duplicate-grab rate 达 57.4%；少量错误完成信念对应显著 SR 下降。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：每轮 observe→communicate→act 可映射为 StreamingModelHarness 中 endpoint 后的一次生成，晚注入工具或消息可承载其他 agent 报告、共享记忆和 leader 指令。
  • 编辑判断：MECoBench 使用离散同步 timestep 和 simulator 动作，不测试输入未提交时的并行生成，也没有语音、打断、实时音频或模型层全双工。

边界与局限Limits

  • 实验只覆盖 VirtualHome 室内家庭任务，缺少户外、开放世界、导航和更长探索。
  • 只有 96 个基础任务、8 个模板，团队最多 5 个 agent；默认位置先验也弱化真实探索。
  • 总步数固定为 60/n，大团队的个人预算更少，倒 U 型同时受到协调开销和预算分配影响。
  • 任务生成脚本、中间 task-knowledge 资产和部分内部运行脚本未公开。

代码与模型开放情况Code and model availability

已开放Open   基准数据、评测与通信代码、修改版 VirtualHome API 和跨平台 simulator 均已发布，代码与数据采用 MIT；未发布任务生成脚本和部分中间资产，但不影响使用现有基准。
