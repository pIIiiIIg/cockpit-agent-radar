Resume Means Resume: A Machine-Checked Conformance Contract for Checkpoint, Interrupt, and Resume Semantics in Workflow Persistence Layers

论文Paper · hf · 2026-08-03 · ◈ 4
摘要Summary
Resume Means Resume 用六项机器可检契约揭示五个工作流框架互不兼容的恢复语义；跨进程扫描中本应发生 400 次的副作用实际触发 2628 次。它直接关系到 Harness 在 endpoint 后恢复 late tools、车控和外挂 TTS 时的 exactly-once 与 consume-once 安全。 A framework that persists execution state so a run can be interrupted, survive a crash, and continue must decide what a resume means for effects that already fired. Five widely deployed agent workflow frameworks answer differently, none exposes a machine-checkable contract, and behavior violates even the fragments they state. The RESUME CONTRACT states six properties over the persistence API (prefix continuation, effect exactly-once, fork determinism, checkpoint validity, consume-once, recovery determinism), plus fork-intent and liveness obligations. A TLA+ model checks a reference semantics exhaustively, unchanged at scaled bounds (7.4 million states); a 39-cell fault matrix yields the separating models independence requires, and consume-once splits, its consumption clause independent of all six others. A deterministic, LLM-free harness measures them at pinned releases. LangGraph 1.2.9 durably records a second resume value and never consults it, persists schema-invalid state silently, and re-executes durably recorded work after a real SIGKILL: exactly-once across interrupts, at-least-once across crashes, on one API. CrewAI 1.15.2 re-executes completed effect-bearing methods against its written claim; pydantic-graph 1.x cannot resume after a mid-node crash; no two probed frameworks share a conformance profile. Consume-once holds sequentially and fails under concurrent delivery: k processes resuming one parked interrupt fire the gated effect k times, saturation 1.0 in 36 of 40 cells, and the failure crosses hosts. REMIT, a reference sequencer whose Verus-verified recovery core is line-identical to the shipped executable, repairs the fork and validity cells. The cross-process cell is repaired at the read path, and that repair ships: an opt-in gate claims consumption in the shared store, serving one racer and refusing the rest before any node executes.

深度讲解Deep dive

五个智能体工作流框架对“恢复执行”具有互不兼容、甚至违反自身文档的语义。论文提出六项 Resume Contract 属性，用 TLA+、无 LLM 故障探针和外部副作用账本测量它们，并以 Remit 修复分支、状态有效性和跨进程重复消费。

它解决什么问题Problem

检查点、人工审批和崩溃恢复决定已经执行的付款、消息、文件写入或工具调用会不会再次发生，但现有框架没有统一、可机器验证的契约。相似 resume API 可能分别提供恰好一次、至少一次、静默重放或无法恢复。

核心方法Core method

作者把恢复平面抽象为任务、持久前沿、检查点、带值中断和恢复，定义 prefix continuation、effect exactly-once、fork determinism、checkpoint validity、consume-once、recovery determinism 六项安全属性，以及 fork-intent 和活性义务。TLA+ 检查参考语义及故障变体；47 个探针、11 个 campaign、SIGKILL、SQLite/PostgreSQL 与独立效果账本测量真实框架。Remit 的 Rust/PyO3 shim 在读取路径声明消费、过滤旧 resume 写入并校验状态。

怎么工作How it works

  1. 把 checkpoint、interrupt、resume 与外部副作用映射为统一可观察接口。
  2. 将参考语义、六类故障和消费竞态编码为 TLA+ 并用 TLC 穷举。
  3. 在固定版本上运行 LLM-free 探针，以独立账本记录副作用。
  4. 通过异常、SIGKILL、多后端、多进程和跨主机竞态区分恢复语义。
  5. 以 Remit 在读取路径声明消费、过滤旧值并校验状态，再做形式与压力验证。

论文报告了什么Reported findings

  • 扩展 TLA+ 配置遍历约 1470 万个生成状态、740 万个不同状态，六项属性结论不变。
  • 五个框架没有任何两个共享相同合规画像，十个框架配对全部可区分。
  • 跨进程扫描覆盖 40 个单元、400 次协议执行，本应发生 400 次的副作用实际发生 2628 次；36 个单元 racer 饱和率为 1.0。
  • 两主机同时恢复时，原始路径 10/10 次均执行两次副作用；Remit 门控 10/10 次均只允许一名竞争者执行。
  • Remit 的 6400 次并发端到端执行全部保持逐协议恰好一次，完整中断微基准相对原生 SQLiteSaver 开销低于 5%。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：Harness 的 endpoint-before-generation 是明确检查点；late tools、真实车控和外挂 TTS 都可能产生非幂等副作用，应纳入 exactly-once、consume-once 和幂等键设计。
  • 编辑判断：流式输入状态跨崩溃恢复时不能重放已经提交的车控或播报；必须区分中断恢复与进程崩溃恢复。
  • 编辑判断：Harness 不是原生全双工，反而使 endpoint、生成、工具和 TTS 阶段边界更清楚；本文是恢复语义规范，不评价实时理解能力。

边界与局限Limits

  • 只覆盖五个框架的固定版本和有限公开路径，部分矩阵单元尚未测试。
  • 副作用主要以计数器或 SQLite 账本代理，不含真实支付、网络分区、掉电或 torn write。
  • TLC 只在有限常量范围内穷举，没有无界证明；模型到 LangGraph 的映射也非机械提取。
  • Verus 未覆盖 PyO3、Python shim 和跨进程 gate 的完整端到端 refinement。

代码与模型开放情况Code and model availability

部分开放Partial   Remit v0.1.2 以 MIT 发布 manylinux wheel 和源码包，不需要模型权重；PyPI 所列源码仓库和论文制品仓库当前均不可访问，完整探针、TLA+ 配置、原始结果和复现脚本仍为私有，因此不能独立复算全部结果。
