Router-Suggest: Dynamic Routing for Multimodal Auto-Completion in Visually-Grounded Dialogs

论文Paper · arxiv · 2026-01-09 · ◈ 8
摘要Summary
Router-Suggest 在视觉对话补全中按前缀选择字符模型或 VLM，形成可测的补全质量—平均延迟折中，但论文指标和官方实现存在影响复现的偏差。对 StreamingModelHarness 更可取的是借鉴成本敏感的可撤销预取，而不是让该路由器决定不可逆工具 commit。 Real-time multimodal auto-completion is essential for digital assistants, chatbots, design tools, and healthcare consultations, where user inputs rely on shared visual context. We introduce Multimodal Auto-Completion (MAC), a task that predicts upcoming characters in live chats using partially typed text and visual cues. Unlike traditional text-only auto-completion (TAC), MAC grounds predictions in multimodal context to better capture user intent. To enable this task, we adapt MMDialog and ImageChat to create benchmark datasets. We evaluate leading vision-language models (VLMs) against strong textual baselines, highlighting trade-offs in accuracy and efficiency. We present Router-Suggest, a router framework that dynamically selects between textual models and VLMs based on dialog context, along with a lightweight variant for resource-constrained environments. Router-Suggest achieves a 2.3x to 10x speedup over the best-performing VLM. A user study shows that VLMs significantly excel over textual models on user satisfaction, notably saving user typing effort and improving the quality of completions in multi-turn conversations. These findings underscore the need for multimodal context in auto-completions, leading to smarter, user-aware assistants.

深度讲解Deep dive

Router-Suggest 为每个文本前缀在字符 n-gram 模型和三种 VLM 间选择一次，以补全质量标签和平均推理成本学习路由；它启发可撤销预取，但任务与安全工具 commit 差异很大。

它解决什么问题Problem

同一未完成文本会因共享图像而需要不同补全，VLM 虽更准却更慢；交互式系统需要在单条内联建议的质量、打字节省和延迟之间取舍。

核心方法Core method

研究把视觉重要的 MMDialog/ImageChat 对话逐轮展开，并随机切分最后一句为 prefix/completion。所有候选模型先生成，最长公共前缀 PR-F1 最高者成为 oracle route；轻量 MLP 根据前缀 embedding 预测模型，并以分类损失和归一化平均延迟共同训练。Router-4 在 QB、Qwen2-VL、PaliGemma、MiniCPM-V 间选，Router-2 只选 QB/Qwen2-VL。

怎么工作How it works

  1. 过滤视觉相关对话并构造未完成前缀与目标补全。
  2. 运行所有候选模型，以 PR-F1 产生每样本 oracle 标签。
  3. 用前缀 embedding 训练成本敏感 MLP。
  4. 线上每个前缀选择一个候选模型生成补全。

论文报告了什么Reported findings

  • 未见前缀时，MMDD 上 MiniCPM-V/QB PR-F1 为 0.2800/0.1892，ImageChat 为 0.2586/0.1755。
  • MMDD 上 Router-4-P 的 PR-F1/平均时延为 0.281/0.832s，Router-2-L 为 0.240/0.170s；MiniCPM-V 为 0.247/2.080s。
  • ImageChat 上 Router-4-L 为 0.212/0.966s，Router-2-L 为 0.196/0.288s，MiniCPM-V 为 0.223/2.080s；表格与摘要的 2.3–10× 区间不能完全对应。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 可借鉴“离线 oracle 标签+成本敏感策略”，把动作改成 wait、只读 prefetch、commit，并让错误 commit 的代价远高于预取浪费。
  • Harness 已持续维护单个 Qwen3-Omni KV，切换独立模型需重放或并行状态；路由器也看不到晚注入候选工具，因此不能直接降低当前工具 commit 延迟，确定性执行门必须保留。

边界与局限Limits

  • 论文路由器只看文本前缀，不看图像或完整对话，并假设 300M embedding 路由开销约为零。
  • 官方代码默认 embedding、训练特征和成本打分与论文描述存在偏差，其中使用 oracle 预测文本作 embedding 会造成不可部署的结果泄漏。
  • 只评估英语单图对话；用户研究未给均值、方差、参与者数或显著性。

代码与模型开放情况Code and model availability

部分开放Partial   MIT 仓库和六个公开 LoRA adapter 已发布，但没有 Router-2/4 MLP 权重或清晰线上入口。OSF 资源虽标 MIT，上游 MMDialog 限学术非商业，PaliGemma/MiniCPM 等基础权重也有各自条款，不能按统一 MIT 处理。
