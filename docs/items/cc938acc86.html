RoMeRL: Balancing Feedback Coverage and the Memory-Reward Trap in Self-Evolving Agent Memory via Reduced-Order Utility States

论文Paper · hf · 2026-08-03 · ◈ 5
摘要Summary
RoMeRL 针对自演化 agent 记忆中的“反馈越来越稀”和“无关记忆被共享奖励误强化”问题，把随轨迹增长的效用表压缩为每任务固定维度的语义坐标。坐标同时按成功/失败与巩固/自适应两轴分解，新经验更新或替换代表内容，而效用反馈始终集中在有界状态上。 Learning-based memory systems for self-evolving LLM agents face two tightly coupled challenges. First, trajectory-indexed utilities grow with the interaction history, thereby dispersing limited feedback over an ever-expanding state space. Second, because trajectory-level rewards are jointly assigned to co-retrieved memories, irrelevant experiences may receive misleading utility updates and consequently enter the memory-reward trap. To address these challenges, we introduce Reduced-Order Memory Reinforcement Learning (RoMeRL), which represents the growing trajectory-indexed utility space using a fixed-dimensional per-task memory state factorized by outcome polarity and memory dynamics. RoMeRL incorporates new experiences through a fixed set of semantic coordinates whose contents are updated or replaced over time, thereby concentrating feedback over a bounded utility support. Theoretically, we show that this reduced-order parameterization increases the average feedback received by each utility coordinate and characterize the steady-state occupancy of erroneous coordinates under a generic coordinate-transition model. Empirically, across ALFWorld and LifelongAgentBench, RoMeRL improves task performance, reduces the Cold-Q ratio by 80.0%, increases feedback density by approximately 6.0 times, reduces the maintained memory size by 84.4%, and cuts LLM calls by 21.1%. These results show that reduced-order utility states support efficient self-evolving agent memory while limiting persistent reward contamination. Code is available at: https://github.com/YOUNG-fnxm/RoMeRL

深度讲解Deep dive

RoMeRL 不再为每条历史轨迹维护一个不断冷启动的 Q 值，而是每任务最多维护四类语义记忆槽，使反馈更密、内存更小，并降低无关经验因共同成功而被错误奖励的长期污染。

它解决什么问题Problem

轨迹级记忆强化学习每加入一条经验就新增一个效用变量，但任务反馈数量并不会同比增加，导致大量记忆从未被更新。用 UCB 加强探索虽能覆盖冷门记忆，却会让弱相关、过时或失败经验与有效经验一起被检索，并共享整条轨迹奖励，从而形成 memory-reward trap。

核心方法Core method

RoMeRL 为每个任务建立固定维度状态，把 outcome polarity（正/负）与 memory dynamics（consolidated/adaptive）做笛卡尔积，形成 PCC、PAC、NCC、NAC 四类语义坐标。新经验不再无限追加效用变量，而是按语义和状态转移更新或替换坐标中的代表轨迹；替换者继承已有效用作为 warm start，运行时仍以任务结果对被检索坐标做标准 Q 更新，并与语义相似度共同决定后续检索。

怎么工作How it works

  1. 按任务建立正/负 × 巩固/自适应的固定语义坐标，而非为每条轨迹新增槽位。
  2. 执行任务并获得成功或失败结果，生成可复用经验表示。
  3. 根据结果极性和前后状态，把经验写入、更新或替换相应坐标的代表内容。
  4. 检索时综合查询语义相似度与坐标效用，选择少量代表经验供冻结的基础 LLM 使用。
  5. 任务结束后用结果奖励更新本轮检索坐标的 Q 值。
  6. 持续交互中保持坐标数固定，让反馈集中在被反复更新的有界支持上。

论文报告了什么Reported findings

  • 在 LifelongAgentBench、ALFWorld 与 AppWorld 的 10 个评测单元上，RoMeRL 的总体平均分为 0.753，MemRL 为 0.724。
  • LifelongAgentBench OS 上，RoMeRL 的 Last SR/CSR 为 0.824/0.838；DB 上为 0.680/0.952。
  • AppWorld 上，RoMeRL 的 TGC 为 0.306、SGC 为 0.326；MemRL 分别为 0.313 和 0.286。
  • 噪声实验中，RoMeRL 的 Round-10 SR 为 82.0%、正向噪声更新为 2.4、最终噪声比为 0.15%；MemRL 为 79.2%、3.7 和 1.02%。
  • 与每任务同样限制四条记忆的 MemRL-4 相比，RoMeRL 在 OS 上把 Cold-Q 从 27.05% 降到 9.06%、反馈密度从 11.21 提升到 29.93；在 DB 上分别从 19.60% 降到 9.73%、从 8.02 提升到 16.07。
  • 冻结记忆跨模型迁移时，GPT-5.4-mini 在 OS 上由 67.0 提升到 81.6，Gemini-3.5-flash 由 74.0 提升到 81.4。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 对架构 A 可作为 RAG/经验记忆层的有界替代：把成功与失败、稳定规则与恢复路径分槽，避免每次车舱交互都无限追加轨迹。
  • 对架构 B 的 search/state/call hop 更直接，可在长 KV 之外维护少量跨会话状态代表，尤其保留“失败后首次成功”的恢复经验。
  • 该方法不更新基础 LLM，适合把记忆策略独立放在 StreamingModelHarness 层；但其结果不能证明模型层全双工或改善 ASR、端点检测、TTS 延迟。
  • 车舱应用需要把任务结果奖励改造成安全敏感、可审计的多维反馈；若只用整轮成功/失败，错误拨号或误控场景中的信用分配风险仍然存在。

边界与局限Limits

  • 仍使用结果级奖励，不能完全解决同轮多条记忆之间的因果信用分配。
  • 论文指出，估计部分坐标转移量需要成对反事实 rollout 或等价的坐标级因果标签。
  • 四坐标分解是一个最小的双时间尺度归纳偏置，并未证明对所有开放任务都完备。
  • 论文未来工作仍需评测更开放、更长时程的环境及更细粒度奖励。
