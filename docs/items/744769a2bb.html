OasisKV: Scaling In-Decode KV Cache Beyond HBM with Lookahead Sparse Prefetching

论文Paper · hf · 2026-08-07 · ◈ 7
摘要Summary
OasisKV 是一个面向长上下文 LLM 解码的分层 KV 缓存系统，只把下一步注意力最需要的 KV 块暂存到 GPU HBM。它利用推测解码产生的前瞻 token 预测未来重要块，并在后台从主机或远端内存预取，以减少 HBM 容量压力和关键路径上的传输。 Large language model (LLM) inference serving is increasingly constrained by memory rather than compute. As long-context and long-form reasoning workloads become more prevalent, the key-value (KV) cache dominates both memory footprint and memory traffic during LLM token generation, i.e., decode. In particular, HBM capacity has become a scarce and costly resource that heavily limits inference batch size and system throughput. This paper presents OasisKV, a memory-centric LLM inference system design that alleviates HBM capacity pressure by decoupling full KV-cache storage from HBM during LLM decoding. Because decode-time attention is naturally sparse, OasisKV keeps only the KV entries of the most relevant tokens in HBMs for attention computation. We observe that future important tokens can be predicted accurately in advance using lookahead tokens drafted by speculative decoding (SD). OasisKV employs an efficient attention background pipeline to identify important KV blocks. They are then prefetched from higher-capacity memory tiers (e.g., host or remote memory) and staged in HBMs before being used in the next decode step. We implement OasisKV based on vLLM. The lookahead prediction is accurate enough to keep accuracy within 0.7 points of full attention under a 2,048-token KV budget. This lets OasisKV turn sparsity into throughput gain: 1.69times over dense vLLM on the reasoning workload at 0.1 points of accuracy loss, and up to 2.1times on multi-GPU long-context serving. Under prefill--decode disaggregation, OasisKV reaches about 2times dense throughput while admitting each request with 6.5--9.7times less KV and holding 2.2-2.6 less decode-node host memory than full KV transfer.

深度讲解Deep dive

OasisKV 把“完整 KV 必须常驻 HBM”改为“完整 KV 留在大容量层、下一步需要的稀疏块提前搬入 HBM”，适合长会话和 agent 多 hop 解码，但它是推理基础设施优化，不是语音全双工架构。

它解决什么问题Problem

长上下文和长推理使 KV cache 同时占据大量 HBM 容量与带宽，限制解码批量和吞吐。仅做稀疏注意力仍需把完整 KV 留在 HBM；按需从 CPU 或远端取 KV 又会把低速 I/O 放到逐 token 解码的关键路径，即使重叠传输也可能来不及。

核心方法Core method

OasisKV 基于 vLLM，把完整 KV 存放与 HBM 中的活跃 KV 解耦。系统用 EAGLE-3 一类多 token 预测/推测解码草拟未来 token，再通过后台注意力流水线预测下一解码步的重要 KV 块，经多层内存管理从主机或远端内存预取到 HBM，最终只对稀疏的活跃块执行注意力；设计同时覆盖多 GPU、prefill–decode 分离和远端 KV 访问。

怎么工作How it works

  1. prefill 产生完整 KV，并把其主体保存在主机或远端高容量内存层，而非全部常驻 HBM。
  2. 多 token 预测模块为当前请求草拟一组前瞻 token。
  3. 后台注意力流水线利用这些前瞻 token 估计下一步最重要的 KV 块。
  4. 多层缓存管理器在当前解码计算期间预取缺失块，并把它们暂存到 GPU HBM。
  5. 下一步解码只读取预算内的活跃 KV 块执行稀疏注意力，再滚动更新预测、驻留与淘汰状态。

论文报告了什么Reported findings

  • OasisKV 基于 vLLM 实现，并面向多 GPU、prefill–decode 分离及多层 KV 存储。
  • 在 2,048-token KV 预算下，前瞻稀疏预测把精度与完整注意力的差距控制在 0.7 分以内。
  • 论文的 PCIe 屋顶线示例使用 Qwen3-32B、单张 H100 SXM-HBM3、32K 上下文和 BF16，并说明逐步从 CPU DRAM 获取 10% 被关注 KV 会显著增加 TPOT。
  • 论文明确把 lookahead 稀疏预测、跨层预取重叠和稀疏度—精度权衡作为联合系统优化问题。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 与架构 B 更相关：Qwen3-Omni KV 在搜索、状态和通话 hop 中会累积长上下文，OasisKV 的分层驻留可作为扩大并发与会话长度的推理服务研究方向。
  • 对架构 A 的 ASR+RAG+晚期工具注入帮助较间接，因为其主要瓶颈可能位于 ASR、检索、工具等待或外部 TTS，而非单一模型的长上下文 KV。
  • 该技术优化的是端点检测之后的 decode 内存与吞吐，不能把 StreamingModelHarness 变成持续听说并行的模型层全双工系统。
  • 落地前需在真实 Qwen3-Omni、多 hop 上测首 token、逐 token 延迟、工具等待期间的 KV 生命周期与音频 token 注意力稀疏性；论文节选未提供这些车舱指标。

边界与局限Limits

  • 精度取决于有限 KV 预算及前瞻 token 对重要注意力块的预测质量，存在明确的稀疏度—精度权衡。
  • 方案依赖多 token 预测或推测解码，并需要后台注意力、异步预取与多层缓存管理的系统协同。
  • 跨 PCIe 或远端链路的可隐藏传输量仍受基础解码时间与链路带宽约束。
  • 论文节选未验证 Qwen3-Omni、流式音频 token、车舱低延迟或打断场景。
