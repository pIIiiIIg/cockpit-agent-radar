AV-Dialog: Spoken Dialogue Models with Audio-Visual Input

论文Paper · arxiv · 2025-11-14 · ◈ 13
摘要Summary
AV-Dialog 每 40ms 融合 DAC 音频 token 和唇部视觉特征，在多人噪声下流式跟踪目标说话者并预测 turn-event；干扰条件 A+V WER 为 38.8%，Auto-AVSR 为 71.8%。dual 版的外挂 TTS 与 Harness 有交集，但它能在回复中持续监听和让权，不能被 endpoint 后生成架构直接等同。 Dialogue models falter in noisy, multi-speaker environments, often producing irrelevant responses and awkward turn-taking. We present AV-Dialog, the first multimodal dialog framework that uses both audio and visual cues to track the target speaker, predict turn-taking, and generate coherent responses. 深度讲解Deep dive

AV-Dialog 用嘴唇视觉和保留声纹的 DAC token，在噪声及多人干扰下流式跟踪目标说话者、转写并预测何时接话；dual 版本再由文本 LLM 和外挂 Mimi TTS 回复。

它解决什么问题Problem

纯音频对话模型在鸡尾酒会环境中容易跟错说话者，造成错误响应和不自然轮替。

核心方法Core method

每 40ms 输入 16 路 DAC codebook 与 AV-HuBERT 唇部特征，LLaMA3-8B 预测目标转写和 normal/overlap/backchannel 事件。dual 架构把结果流入第二个文本 LLM，再交给 Mimi TTS；unified 架构在同一模型输出 turn-event 与文本回复。

怎么工作How it works

  1. 用 dlib 定位人脸，AV-HuBERT 提取唇部特征，DAC 编码音频。
  2. AV understanding LLaMA3-8B 流式输出目标用户转写和 turn-event。
  3. dual 模式在 LISTENING 时更新文本 LLM KV，turn token 到达后进入 SPEAKING。
  4. 响应中检测到新用户语音则让权并回到 LISTENING，文本交给外挂 Mimi TTS。

对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：dual 架构与 Harness 的外挂 TTS 有交集，可借鉴视听说话人跟踪和语义 turn token；但 Harness 等 endpoint 后才生成，不能声称同等流式轮替。
  • 编辑判断：论文没有工具调用证据；晚注入工具可能改变首响应和连贯性，必须把 endpoint、工具执行和 TTS 分段评测。

边界与局限Limits

  • 模型不显式处理笑声、叹气等非语言音频，视觉也基本限于嘴唇，不理解表情和手势。
  • 弱光、嘴部遮挡和极端头部姿态会损害目标跟踪与识别。
  • AV-HuBERT 两帧 look-ahead 使算法延迟约 120ms；dual 还需同时运行两个约 8B 模型。
  • 指定 arXiv v1 与官网后续版本的人评样本数和 MOS 增益不同，本站数字严格采用 v1。
