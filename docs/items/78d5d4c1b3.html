An Intelligent-Cloud Edge Multimodal Interaction System for Robots

论文Paper · arxiv · 2026-07-16 · ◈ 8
摘要Summary
TonyPi 在边缘端采集语音/图像和执行动作，云端以 YOLO-DC、VLM、LLM、规则引擎与 FSM 规划，再用统一 JSON 返回动作。其安全编排链可约束 Harness 的晚注入工具，但流程等待完整命令后 STT 和上云，不是增量或全双工语音方案。 Robust human-robot interaction in complex environments requires accurate gesture perception, semantic scene understanding, and reliable task planning under limited onboard computing resources. This paper presents a cloud-edge multimodal interaction framework that integrates an enhanced YOLO-based gesture detector with coordinated large language model (LLM) and vision-language model (VLM) agents. The proposed detector, incorporates the Convolutional Block Attention Module (CBAM) into the neck and replaces the baseline bounding-box regression objective with Distance-IoU (DIoU) loss. These modifications improve feature discrimination and localization for small or partially occluded gestures in complex backgrounds. The cloud layer performs gesture detection, scene understanding, multimodal fusion, and action planning, whereas the TonyPi robot locally handles data acquisition, communication, action execution, and feedback. Experiments on a public gesture dataset and a custom dataset show that YOLO-DC achieves precision values of 98.9% and 95.0%, with mAP@0.5 values of 90.7% and 92.7%, respectively. System-level evaluation yields success rates of 95%, 88%, and 82% for single-action, composite-action, and vision-dependent tasks. A 30 participant evaluation yields an overall mean satisfaction score of 3.69 out of 5. These results demonstrate the feasibility of combining refined gesture detection with multimodal agents for resource-constrained robotic interaction.

深度讲解Deep dive

TonyPi 在边缘端采集并执行，云端以 YOLO-DC、VLM、LLM、规则引擎和 FSM 完成手势识别、场景理解与动作规划；它是回合式云边机器人编排，而非原生全双工语音系统。

它解决什么问题Problem

轻量机器人难以在本地同时承担复杂背景手势检测、开放场景理解和多步任务规划；单一输入与固定指令映射又缺乏上下文推理能力。

核心方法Core method

YOLO-DC 在 YOLO11n neck 的 C2PSA 后加入 CBAM，并以 DIoU 替换原包围框回归目标。边缘端执行降噪、STT、图像缩放和 JPEG 编码；云端由 YOLO-DC 识别预定义手势、VLM 做场景理解，LLM 融合文字、手势和视觉描述并分解任务。规则引擎检查动作兼容性，FSM 约束顺序和状态，最后用统一 JSON 返回 intent、对象、位置、置信度、回复和动作序列。

怎么工作How it works

  1. TonyPi 接收完整语音命令并采集相机帧，执行 STT 与图像预处理。
  2. 把文本和图像发送到云端，由 YOLO-DC 与 VLM 分别提取手势和场景信息。
  3. LLM 融合多模态结果，规则引擎和 FSM 校验候选动作计划。
  4. 结构化 JSON 返回机器人，本地调用运动接口并按需输出 TTS 反馈。

论文报告了什么Reported findings

  • 公共集上 YOLO-DC 的 Precision/mAP@0.5 为 98.9%/90.7%，自建集为 95.0%/92.7%；相较 YOLO11n，自建集分别提高 16.0 和 6.0 个百分点。
  • 消融中 DIoU+CBAM 在公共集达到 P/R/mAP/F1 98.9/95.0/90.7/96.9；单独加入 CBAM 的 Precision 和 Recall 反而降至 96.4% 和 94.0%。
  • 单动作、组合动作和视觉依赖任务成功率分别为 95%、88%、82%，无效动作组合拒绝率为 90%；论文只报告 VLM 子步骤平均响应 210 ms。
  • 30 人对四种动作评分的总均分为 3.69/5；500 条回复的重复率低于 5%。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：可借鉴“多代理输出→统一 schema→规则/FSM→动作白名单”链路，约束 Harness 中较晚才注入的工具调用。
  • 编辑判断：流程由完整语音命令启动，先 STT、再上云、再返回动作；没有增量音频生成、barge-in、中途工具插入或同步说话/执行证据，不能写成全双工方案。
  • 编辑判断：210 ms 仅是 VLM 子步骤，不能与 Harness 首音频 P50 比较，也不能证明改善 endpoint 等待或 TTS TTFA。

边界与局限Limits

  • 未报告端到端语音到动作/首反馈延迟、网络抖动、吞吐、并发或中断恢复。
  • 公共集仅 600 张且未命名，自建集未给总规模；2:1 validation 同时用于模型选择和结果报告，没有独立测试集。
  • 系统任务成功率未给试验次数、置信区间或对照系统；生产环境仍缺认证、加密、访问控制、限流和审计。
