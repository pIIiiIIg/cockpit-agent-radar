Model or Harness? An Interaction-Centric Taxonomy for Localizing Agent Failures

论文Paper · hf · 2026-07-29 · ◈ 5
摘要Summary
论文以交互边、责任侧和最早未恢复故障组织 41 类智能体失败，并用 40 个真实案例验证独立 judge 能否复现人工归因。它适合给 StreamingModelHarness 的 endpoint、工具包装、外部 TTS 和环境错误建立证据化分流，但现有 taxonomy 需扩展音频实时组件，自动归因也不能替代人工事故复核。 Existing evaluations often reduce agent failures to system-level outcomes, obscuring where the fault originated and which intervention would improve the agent system. This creates a repair-assignment problem: the same visible failure may call for model post-training, harness engineering, environment redesign, or benchmark repair depending on its source. Because agent behavior emerges from interactions among models, harnesses, users, tools, memory, and environments, outcome-level labels are often insufficient for improvement. Most failure taxonomies do little to resolve this problem because they are benchmark-specific and lack a shared structure. We introduce an interaction-centric taxonomy that localizes failures to the interactions in which they originate and identifies the responsible component. It organizes 41 failure modes by assigning each to an edge between two components and a fault side indicating where the repair belongs. This makes the taxonomy actionable: model-side failures identify targets for post-training, harness-side failures point to scaffolding and tool-integration fixes, and environment or grader failures reveal evaluation conditions requiring redesign. The schema applies across agent architectures, from coding assistants to long-horizon personal assistants and multi-agent systems. We ground the taxonomy in worked examples from public benchmarks, model system cards, published reports, and logged agent trajectories, and evaluate its reproducibility using independent reasoning agents as judges. Across four frontier models, the strongest judge reaches Cohen's κ=0.76 against human category labels, suggesting that the categories capture shared structure rather than annotator-specific preferences.

深度讲解Deep dive

Model or Harness? 用“交互边 + 责任侧 + 最早未恢复故障”把 41 类智能体失败定位到模型、上下文、记忆、工具、用户、评测器或环境。

它解决什么问题Problem

同一个可见失败可能来自不同根因：工具包装器可能吞掉错误，也可能是模型看见错误后仍忽略；长会话约束丢失可能来自 harness 压缩，也可能是模型未使用仍在上下文中的信息。只记录任务成败或宽泛的执行错误，无法决定应该做模型后训练、harness 修复、环境修复还是 benchmark 重写。

核心方法Core method

论文定义模型、owner、grader、第三方、上下文、持久记忆、工具、本地环境和外部环境等组件，并把同行或子智能体作为 model—model 边上的角色。每个失败标签由两个端点构成的交互边、实际负责的 fault side 和具体 failure mode 组成。标注从最终系统失败沿因果链反向追踪，选择执行未能恢复的最早故障，而不是后续连锁症状。冻结 taxonomy 后，作者让四个独立推理智能体先重建原始证据、再分类、最后按消歧规则反思，以测试标签能否复现。

怎么工作How it works

  1. 保存任务规范、完整轨迹、工具输入输出、上下文压缩、记忆读写和环境状态。
  2. 从最终失败反向重建时间顺序与因果传播链。
  3. 选择最早且此后未恢复的故障事件。
  4. 为该事件指定交互边、责任侧和 41 个模式之一，并把安全影响作为独立标记。
  5. 对不确定案例由多个 judge 独立检索原始证据、分类并反思；只有达到一致阈值时才自动接受。

论文报告了什么Reported findings

  • 最终 taxonomy 包含 41 个模式，其中 36 个归于模型侧、5 个归于外围组件；验证集包含 40 个 worked examples，因此不能用于估计失败率。
  • 在 40 个例子上，GPT-5.5 的交互类别准确率为 0.80、macro-F1 为 0.69、对人类标签 Cohen's κ 为 0.76；完整 failure-mode 准确率为 0.72、macro-F1 为 0.64。
  • 四个 judge 之间最高类别一致性达到 κ=0.84，说明定义具有一定共享结构，但完整 failure-mode 的一致性低于粗粒度类别。
  • 至少 3/4 judge 同意时，类别覆盖率为 0.90、精确率为 0.83；要求 4/4 一致可把类别精确率提高到 0.96，但覆盖率降至 0.68，failure-mode 精确率为 0.89。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：当前 StreamingModelHarness 流式接收输入，但仅在 endpoint 后生成，工具晚注入，并使用外部 TTS；它不是原生模型层全双工，因此端点等待、工具注入或 TTS 停声造成的失败不能笼统归咎于底层模型。
  • 编辑判断：应为每次座舱失败记录最早未恢复事件、可见证据、可恢复性、交互边和责任侧。例如工具包装器丢掉局部失败属于 tool-side mistranslation，模型看见失败仍宣称成功才属于 tool-feedback neglect。
  • 编辑判断：现有 taxonomy 没有显式表示 AEC、VAD、语义 endpoint、音频流调度、外部 TTS 和车控执行器；落地时应扩展组件词汇，避免把这些实时链路全部挤进宽泛的 tool 或 environment 类。
  • 编辑判断：可用多 judge 一致性做离线事故分流，但论文最强单 judge 的类别准确率仍只有 80%；涉及车控安全、不可逆动作或证据不足时必须保留人工复核与 abstain。

边界与局限Limits

  • taxonomy 是描述性分类，不估计各类故障的发生频率、严重度或修复收益；40 个例子由作者择取，只适合说明覆盖面。
  • taxonomy 在审阅这些案例时迭代形成，同一批案例又用于 judge 标签复现，因此实验主要证明可复现性，不证明对全新系统或分布外故障的泛化。
  • 根因高度依赖证据完整性；论文也承认公开报告、系统卡和不完整轨迹可能同时支持模型侧与 harness 侧解释。
  • 把“更强模型本可避免或恢复”作为部分 model-side 归因依据，容易扩大模型责任；实际生产事故还需区分可恢复性、权限边界和基础设施职责。
  • 论文未发布可执行分类器、judge 流水线、机器可读 taxonomy 或完整标注数据包；所用前沿闭源 judge 和 API 配置也限制独立复现。
