Audio2Tool: Speak, Call, Act -- A Dataset for Benchmarking Speech Tool Use

论文Paper · arxiv · 2026-04-17 · ◈ 10
摘要Summary
Audio2Tool 以八级合成语音基准评测 152 个汽车、家居和穿戴工具，显示强模型在参数、多意图、多轮和背景意图混叠上仍明显退化。编辑判断：它适合补齐 Harness 的车控正确性与误触发回归，但不评测判停、生成、外挂 TTS 的在线时延，也不能证明模型原生全双工。 Voice assistants increasingly rely on Speech Language Models (SpeechLMs) to interpret spoken queries and execute complex tasks, yet existing benchmarks lack domain breadth, acoustic diversity, and compositional reasoning complexity to evaluate tool-calling performance. We introduce Audio2Tool, a large-scale dataset comprising approximately 30,000 queries designed to assess tool-calling capabilities of SpeechLMs across three primary domains: Smart Car, Smart Home, and Wearables. Our benchmark features a multi-tier complexity hierarchy, ranging from simple direct commands to complex multi-intent and needle-in-a-haystack extraction to isolate distinct failure modes. To ensure realism, we employ zero-shot voice cloning text-to-speech synthesis and diverse noise profiles to simulate in-the-wild conditions. Evaluations of state-of-the-art SpeechLMs and ASR-LLM pipelines show strong performance on simple commands but significant degradation under compositional and acoustic challenges. Code and dataset are publicly available on the project page: https://audio2tool.github.io/.

深度讲解Deep dive

Audio2Tool 用八级合成语音任务拆解从直接指令、参数抽取到多意图、纠正、多轮和前后台意图混叠的工具调用失败。

它解决什么问题Problem

现有语音工具调用评测通常领域和声学条件有限，也难以分别定位工具选择、参数落槽、多步组合、说话人区分与跨轮状态维护错误。

核心方法Core method

论文整理智能汽车、智能家居和可穿戴设备中的 152 个函数及 23 个类别，生成八级查询，再用 Qwen3-TTS、CosyVoice-3、多个公开说话人语料和汽车/室内噪声合成音频。模型以零样本方式从音频输出有序工具调用，分别按工具准确率、完整调用 Exact Match 和参数 Slot F1 计分，并比较端到端 SpeechLM 与 Whisper-v3→文本 LLM 级联。

怎么工作How it works

  1. 从三类设备 API 建立统一工具 taxonomy，并按直接、参数化、多意图、隐式、长上下文、纠正、多轮和意图混叠生成查询。
  2. 以分层采样和 farthest-point sampling 选择参考说话人，用零样本 voice cloning 合成语音。
  3. 加入汽车、室内及 babble、mechanical hum、impulsive 等噪声，形成不同声学难度。
  4. 向 SpeechLM 或 ASR→LLM 级联提供工具 schema，比较工具序列、完整参数和参数级 F1。

论文报告了什么Reported findings

  • 正文 §3.1 报告 taxonomy 含 152 个已核验函数和 23 个类别；§3.2 称主体数据约 29,680 条查询，但其分层计数没有单独交代 Tier 8。
  • Table 3 中 Qwen-3-Omni-30B 的 Tier 1 工具准确率为 92.4%，到 Tier 4 的 Acc/EM/F1 降为 33.4/11.3/23.4，Tier 7 为 54.6/16.3/26.8，Tier 8 为 41.7/12.4/19.9。
  • Table 3 中 Whisper-v3+Gemma-27B 在 Tier 8 的 Acc/EM/F1 为 50.5/15.7/25.6，高于 Qwen-3-Omni-30B 的 41.7/12.4/19.9，支持正文关于端到端 SpeechLM 尚未稳定胜过强级联方案的判断。
  • §5.4 在 babble、mechanical hum 和 impulsive noise 上使用 +15、+5、−5 dB SNR，报告噪声增加会显著降低性能，但正文未给出该图的逐点数值。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：优先将 Tier 2、3、6、7、8 改写为车控回归集，分别检查参数、聚合意图、改口、多轮状态以及主乘员与背景语音误触发。
  • 编辑判断：应同时记录工具名、参数、最终车态和误执行；只采用论文的工具准确率会漏掉参数错误，也不能满足真实车控安全要求。
  • 编辑判断：Audio2Tool 是离线音频到工具调用评测；当前 Harness 虽流式接收输入，但判停后才生成、晚注入候选工具并使用外挂 TTS，不能据此宣称模型原生全双工。

边界与局限Limits

  • 正文明确承认语音均由 TTS 生成，尚无真实录音；说话人参考、合成器和叠加噪声不能覆盖真实车内混响、回声、阵列波束和自然重叠说话。
  • 查询由 GPT-5.2、Gemini 2.5 Pro 和 Claude Opus 生成，再由 GPT-5.1/Gemini 判分；只有至少一个裁判失败的样本才人工核验，不能视为全量人工标注。
  • 正文/项目页称约 29,680 条查询，官方 Hugging Face v1.0 卡片则列 16,843 个查询条目、36,421 个音频文件和 59.6 小时，公开版本与论文口径未解释对齐关系。
  • 官方 GitHub 仓库主要是项目演示前端、少量样例和下载/绘图脚本，未包含论文的查询生成、噪声构造、模型评测与指标复现实装。

代码与模型开放情况Code and model availability

部分开放Partial   代码：GitHub 公开的是演示站点而非完整 benchmark pipeline，且仓库没有独立 LICENSE。数据：Hugging Face v1.0 公开八个 tier、工具表和音频，许可为 CC BY-NC 4.0；底层 VoxPopuli、YODAS、3D-Speaker、ECAPA/VoxCeleb/VoxLingua 仍受各自条款约束。权重：本工作没有发布专属模型或 checkpoint。
