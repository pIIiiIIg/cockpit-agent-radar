Phoenix-VAD: Streaming Semantic Endpoint Detection for Full-Duplex Speech Interaction

论文Paper · arxiv · 2025-09-24 · ◈ 23
摘要Summary
Phoenix-VAD 是一个基于 LLM 的流式语义端点检测模型，为全双工语音交互提供即插即用的“用户是否说完”判定模块。对本站的座舱助手直接有用：harness 里边说边听时最痛的难点就是语义级 endpoint/抢话判定，可以借鉴其把 LLM 语义理解能力用于流式 VAD 的思路，替代纯声学 VAD。 Spoken dialogue models have significantly advanced intelligent human-computer interaction, yet they lack a plug-and-play full-duplex prediction module for semantic endpoint detection, hindering seamless audio interactions. In this paper, we introduce Phoenix-VAD, an LLM-based model that enables streaming semantic endpoint detection. Specifically, Phoenix-VAD leverages the semantic comprehension capability of the LLM

深度讲解Deep dive

Phoenix-VAD 是直接听音频的二分类语义端点检测器，用来判断用户语义是否完整，而不只是检测有没有声音。

它解决什么问题Problem

能量 VAD 会把犹豫停顿当成话轮结束；ASR+文本端点模型虽然懂语义，却增加级联延迟并丢失声学信息。

核心方法Core method

约 150M 的 Zipformer 提取音频特征，两层 Adapter 对齐到 Qwen2.5-0.5B。模型查看约 2.56 秒滑动窗口，每 320ms 输出 Continue Speaking 或 Stop Speaking，并给完整与未完整语句使用不同等待阈值。

怎么工作How it works

  1. 持续接收用户原始音频，不依赖额外 ASR。
  2. 滑动窗口保留局部上下文并进行流式前向。
  3. 语义未完整时继续等待，完整时采用较短超时提交话轮。

论文报告了什么Reported findings

  • 论文测试集中完整和未完整语音场景准确率约为 98.6% 和 98.5%。
  • A6000 上单次状态预测约 50ms。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 可作为 RMS VAD 后的第二道语义闸，减少“然后把……”这类未说完就 commit。
  • 它只判断继续或停止，不负责区分多人身份、附和与真正插话。

边界与局限Limits

  • 训练语音大量由 TTS 合成；论文将真实录音和拒识能力列为未来工作。
  • 每次推理仍需要语音编码器和 0.5B LLM，需评估座舱端侧资源。
