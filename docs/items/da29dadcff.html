Chronological Thinking in Full-Duplex Spoken Dialogue Language Models

摘要Summary
CT-Duplex 在助手静音区生成可抢占的实体、意图、动作、知识和逻辑节点，提升推理型对话与 barge-in 成功率，但事实问答增益很小且轮次启动延迟由 0.45 升至 0.68 秒。Harness 可在流式输入期维护可撤销草稿，回答仍应在 endpoint 与工具注入后生成。 Recent advances in spoken dialogue language models (SDLMs) reflect growing interest in shifting from turn-based to full-duplex systems, where the models continuously perceive user speech streams while generating responses. 深度讲解Deep dive

CT-Duplex 在原生全双工模型的监听静音区生成可抢占的 Entity、Intent、Action、Knowledge、Logic 节点，用“用户说话时先想”改善推理型对话。

它解决什么问题Problem

全双工 SDLM 在用户说话时反复预测静音 token，既浪费监听窗口又可能强化重复退化；传统 CoT 要等完整输入后执行，过长且无法随未知 endpoint 抢占。

核心方法Core method

约 1.7B 的 CT-Duplex 由 12.5Hz 流式语音编码器、Qwen2.5-1.5B 初始化的 LLM 和自回归语音解码器组成。离线教师生成五类思考节点，训练时将完整节点尽量靠后填入助手静音区，空间不足则按节点截断，不挤占正式回答；用户停下后模型从思考切到文本与语音回答。

怎么工作How it works

  1. 生成对话文本，并由教师产生五类结构化思考节点。
  2. 用多说话人 TTS 合成双通道语音，并随机加入 barge-in。
  3. 按语音时间轴把完整思考节点写入助手静音区。
  4. 联合训练语音编码、文本 LLM 和语音解码，推理时持续思考并可被用户插话抢占。

对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：可在 Harness 的流式输入阶段维护可撤销的实体、意图和动作草稿，endpoint 后再与晚注入工具一起交给生成模型。
  • 编辑判断：论文把思考和语音解码训练在统一时间轴；当前 Harness 判停后生成并用外挂 TTS，不能据此声称原生监听时思考或模型级全双工。

边界与局限Limits

  • 评测主要依赖 Whisper 转写和 GPT-4o-mini，未报告多随机种子、置信区间或充分的真人研究。
  • 训练大量依赖合成对话、合成语音和固定时序增强，且未公开思考标签生成提示或未来信息泄漏审计。
  • 论文称无额外延迟，但 Table 5 中有思考版轮次启动延迟高 0.23 秒，正文叙述与表格还存在冲突。
