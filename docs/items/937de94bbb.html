Still Between Us? Evaluating and Improving Voice Assistant Robustness to Third-Party Interruptions

论文Paper · arxiv · 2026-04-19 · ◈ 8
摘要Summary
论文构建 TPI-Train/TPI-Bench，以同文本单说话人硬负例迫使语音模型依据声学说话人变化区分第三方打断，并学习可操作或可忽略的响应策略。它可为 StreamingModelHarness 增加说话人变更与工具确认测试，但论文仍是整段语音输入后文本输出的轮次式设置，不是原生模型级全双工。 While recent Spoken Language Models (SLMs) have been actively deployed in real-world scenarios, they lack the capability to discern Third-Party Interruptions (TPI) from the primary user's ongoing flow, leaving them vulnerable to contextual failures. To bridge this gap, we introduce TPI-Train, a dataset of 88K instances designed with speaker-aware hard negatives to enforce acoustic cue prioritization for interruption handling, and TPI-Bench, a comprehensive evaluation framework designed to rigorously measure the interruption-handling strategy and precise speaker discrimination in deceptive contexts. Experiments demonstrate that our dataset design mitigates semantic shortcut learning-a critical pitfall where models exploit semantic context while neglecting acoustic signals essential for discerning speaker changes. We believe our work establishes a foundational resource for overcoming text-dominated unimodal reliance in SLMs, paving the way for more robust multi-party spoken interaction. The code for the framework is publicly available at https://tpi-va.github.io

深度讲解Deep dive

论文用同文本、单说话人的声学硬负例，迫使语音模型真正依据说话人变化识别第三方打断，并学习何时采纳或忽略插话；任务仍是轮次式语音输入、文本输出。

它解决什么问题Problem

现有语音模型常把主用户与旁人的连续语音拼成同一人的指令，导致意图被覆盖甚至触发错误操作。仅增加多说话人训练样本仍可能让模型依赖矛盾、话题切换等文本捷径，而不学习声学说话人边界。

核心方法Core method

作者将七类会话打断分类扩展为 26 个第三方插话场景，构建约 8 万条双说话人训练样本，并把插话分为可操作与可忽略两类。对文本上像插话、但也可能是单人自我修正的样本，保持文本不变并用主说话人的声音重新合成，形成声学硬负例。随后以 LoRA 微调 Qwen2.5-Omni-7B，并用 TPI-Test、Janus-Test、真实语音集以及 RSF、OH 指标检验响应策略与声学敏感性。

怎么工作How it works

  1. 从 VoiceAssistant-400K 风格的用户请求中抽样，按 26 个场景生成第三方插话并以 Chatterbox 合成不同说话人的音频。
  2. 将插话标注为可操作或可忽略，并按预设策略生成训练响应。
  3. 筛选文本语义有歧义的样本，以同一主说话人重新合成完整音频，构造说话人感知硬负例。
  4. 混合 TPI 语料、普通双人语音助手数据和硬负例，以 LoRA 对 Qwen2.5-Omni-7B 监督微调。
  5. 分别在双说话人 TPI-Test、单说话人 Janus-Test、VoiceBench 和 100 条真实语音样本上评测。

论文报告了什么Reported findings

  • 正文表 II 报告：TPI-Full 在 TPI-Test 上的 RSF/OH 为 0.83/4.16，Qwen2.5-Omni-7B 基线为 0.24/3.22。
  • 在 Janus-Test 上，TPI-Full 的 RSF 为 0.16、OH 为 4.80；未微调基线为 0.12/4.44。硬负例大幅修复了无硬负例 TPI-VA 的 0.67/3.75，但误报指标没有优于原始基线。
  • 正文表 IV 报告：100 条真实语音上，RSF 从 0.17 提升至 0.60，OH 从 3.21 提升至 4.25。
  • 显式说话人提示只把基线 TPI-Test RSF 从 0.24 提至 0.37，同时 OH 从 3.22 降至 3.17，说明文字提示不能替代声学归属能力。
  • 直接 A/B 人评中，TPI-Full 获得 60.5% 偏好，基线为 28.0%，平局为 11.5%。
  • 场景文本和合成音频的三分制真实感均值分别为 2.87 和 2.63。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：TPI-Test 与 Janus-Test 可成为 StreamingModelHarness 的多人座舱回归集，用于检查流式输入在端点触发前是否保留了说话人变化，而不是把两人的话拼成一条指令。
  • 编辑判断：第三方提供的可操作信息只能进入候选上下文；涉及当前晚工具注入时，仍应由主用户明确确认，不能把旁人插话直接转换成工具授权。
  • 编辑判断：可先在端点器或 ASR 前增加在线说话人变更信号，再评估是否把该信号交给生成模型；论文没有提供可直接部署的在线检测头或 TPI-Full 权重。
  • 编辑判断：论文是整段语音输入后生成文本的轮次式方案，不覆盖当前 Harness 外挂 TTS 播放期间的持续监听、抢话恢复或原生模型级全双工调度。

边界与局限Limits

  • 主要训练语料由 LLM 和 TTS 合成；真实测试集只有 100 条，其中 59 条为按脚本重录。
  • 真实集仅保留文本系统可回答的任务，并排除了物理动作和视觉指令，不能覆盖完整座舱工具场景。
  • 可操作/可忽略策略具有用户和社会情境依赖性，论文只验证了一套参考策略。
  • RSF 和 OH 主要由 LLM 裁判产生；虽然作者报告与人评相关，但仍可能受裁判模型偏差影响。
  • 论文明确把全双工扩展列为未来工作，当前结果不能证明连续监听、何时说话或重叠发言控制能力。
  • Janus-Test 上 TPI-Full 的 RSF 0.16 略差于原始基线的 0.12，说明增强插话响应能力仍有单说话人误报权衡。

代码与模型开放情况Code and model availability

部分开放Partial   官方仓库公开标注、响应生成、硬负例和评测脚本；Hugging Face 已实际发布 80,571 条双说话人训练样本、7,519 条硬负例、2,000 条 TPI-Test 和 1,959 条 Janus-Test。未发布 TPI-Full 权重。论文称数据和自动化管线将采用 MIT，仓库 README 又称 Apache-2.0，但当前仓库没有 LICENSE 文件且 GitHub/Hugging Face 元数据未声明许可证，因此代码和数据的当前可复用许可证应视为未确认。
