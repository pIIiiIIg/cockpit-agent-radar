FATE: Frame-Level Audio-Visual Temporal Embedding

论文Paper · hf · 2026-08-01 · ◈ 4
摘要Summary
FATE 试图在同一音视频嵌入空间里同时表示“是什么声音”和“何时发生”：保留帧级序列、按物理时间对齐，再只比较对应时刻的音视频特征。它在时序检索、零样本事件定位和生成质量评测上均优于论文所比较的基线，说明全局池化确实会丢掉同步信息。 When a dog opens its mouth and barks, humans naturally recognize what the sound is and when it occurs. Building audio-visual models with this same ability requires representations that capture both semantic and temporal alignment. Current approaches fall short on one side or the other: embedding models match semantic but lose temporal information; synchronization models capture temporal offsets but lack semantic understanding. To bridge this gap, we propose FATE, Frame-level Audio-visual Temporal Embedding. Unlike prior embedding models that pool each modality into a single embedding and discard temporal information, FATE retains frame-level sequences, aligns them on the physical timeline, and computes similarity over strictly aligned frame pairs. Unlike synchronization models that output only an offset prediction, FATE encodes synchronization in a reusable embedding space, trained with a joint objective combining cross-video semantic and within-video temporal contrastive learning to capture both what sounds and when it occurs. Across three tasks, FATE surpasses the strongest baseline on temporal and semantic retrieval by a large margin, matches fully supervised methods on event localization in a zero-shot setting, and achieves the best correlation with human judgments as a generation evaluation metric. The source code can be found at https://github.com/guankaisi/FATE.

深度讲解Deep dive

不把一段音频和视频各压成一个向量，而是沿时间轴逐帧对齐后求相似度，并用跨视频语义对比与视频内时序对比联合训练。

它解决什么问题Problem

传统音视频嵌入模型擅长判断语义共现，却因全局池化对时序错位不敏感；同步模型能预测偏移，却缺乏可复用的语义表示。低帧率 Omni LLM 也难以承担细粒度同步，因此下游任务缺少兼具语义区分和时间区分的统一表示。

核心方法Core method

FATE 基于 PE-AV 双编码器，去掉全局池化并保留音频、视频的帧级 token。由于两种编码器的采样率不同，它以音频时间点为锚，用最近邻下采样视频特征；相似度取严格对齐帧对的平均内积。训练目标由跨视频语义对比和同一视频内带软标签的时间对比组成，使表示既排斥语义无关片段，也对时间平移敏感。

怎么工作How it works

  1. 分别编码视频帧和音频频谱，保留两路完整的帧级归一化特征序列。
  2. 以物理时间和音频 token 为锚，用最近邻方式将视频序列对齐到相同长度。
  3. 只计算时间对角线上对应帧对的平均相似度，使音频平移直接降低得分。
  4. 联合优化跨视频语义对比损失与视频内时间软对比损失，并将同一嵌入用于检索、定位和生成评测。

论文报告了什么Reported findings

  • 论文在 AVSync15 的 150 个视频和 VGG-Sync 的 595 个视频上进行时序检索；每个 10 秒视频被切成步长 0.5 秒的 2 秒片段。
  • 在 AVE 事件定位上，FATE 未使用 AVE 监督即取得 A2V 51.8%、V2A 44.7%、平均 48.3% 的片段级准确率，高于表中三个 AVE 监督方法的最高平均值 47.8%。
  • 在 AVSync15 视频内检索中，完整 FATE 的 V2A R@3 为 55.74，移除帧级设计后为 29.11；跨视频设置中相应为 34.13 和 19.33。
  • 论文摘要报告，相比最强同步基线，FATE 的时序检索 R@3 提升超过 13 个点，同时语义检索准确率提升超过 20 个点。
  • 作为联合音视频生成评测指标，论文报告 FATE 与人工同步判断的 Spearman 相关性在所比较指标中最高。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 若座舱产品未来加入摄像头、唇动、乘员动作或多媒体同步评测，FATE 可作为音视频时间一致性的表示和离线指标。
  • 当前 StreamingModelHarness 的主链路是音频输入和外部 TTS，没有视频编码与生成模块，因此它对现有实现只有间接价值。
  • FATE 评估的是跨模态同步，不处理话尾检测、并发说听、工具注入或对话打断，也不能作为原生全双工证据。

边界与局限Limits

  • 训练与多数测试数据都来自 VGGSound 体系，尽管作者核查了视频 ID 不重叠，领域迁移仍需额外验证。
  • 最近邻下采样把音频作为锚，可能丢失快于目标采样率的视觉变化，也依赖可靠的媒体时间戳。
  • 生成评测只覆盖五种模型、每种 150 个视频，人工相关性的外推范围有限。
  • 论文侧重短片段同步与事件定位，尚未验证长时序叙事、实时流处理或复杂座舱噪声。
