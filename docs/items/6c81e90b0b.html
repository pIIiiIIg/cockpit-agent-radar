OneDayAgent: Towards a Long-Horizon Harness for Autonomous Agents

论文Paper · hf · 2026-08-03 · ◈ 6
摘要Summary
OneDayAgent 用有限子任务、压缩执行记忆、全局验证和定点修复管理小时级跨工具任务，104 项上由 DIRECT 0.771 提升到 0.821，但平均耗时由 27.6 增至 53.6 分钟。对 Harness 最实用的是先在 endpoint 后加入 artifact-level verification；当前官方仓库尚无源码，且宿主机 shell 与压缩记忆存在安全风险。 LLM agents are increasingly applied to open-ended everyday requests that span work, study, and life. These tasks are long-horizon, cross-environment, and multimodal, forcing the agent to preserve goals and constraints across many steps while navigating heterogeneous tools and attachments. While prior work has addressed individual failure modes such as goals drift, states loss, and context overflow, whether a single harness can manage them jointly and remain effective across backends has received less study. We present OneDayAgent, a long-horizon harness for autonomous agents. OneDayAgent turns an open-ended request into a managed execution process that decomposes tasks into bounded subtasks, maintains execution memory under context pressure, and verifies and repairs the final deliverable. We evaluate OneDayAgent on AgentIF-OneDay across 104 tasks. With the GLM-5.2 backend, OneDayAgent sets a new state of the art with an overall score of 0.821. The same harness runs across five backend LLMs from three model families, indicating the harness generalizes across backends without tuning, even as different models induce distinct execution styles under the same workflow.

深度讲解Deep dive

OneDayAgent 把开放式长任务拆成有限子任务，用摘要、文件句柄和上下文压缩传递状态，生成结果后做全局验证与局部修复；提升明显但成本高，且源码尚未发布。

它解决什么问题Problem

跨网页、文件、计算和图像的小时级任务会同时出现目标漂移、状态丢失与上下文溢出，单条 ReAct 轨迹难以联合处理。

核心方法Core method

原始请求始终作为 global intent，planner 最多生成六个有序子任务；每个子任务用 ReAct 调用搜索、网页、论文、shell、文件和图像工具，并以摘要、证据和文件句柄提交结果。搜索、长网页和文件只保留结构化摘要及有限 raw prefix；128K 窗口到 90% 时由 LLM 压缩并保留 system、原任务和最近三轮，95% 时确定性裁剪。全部完成后 synthesis，verifier 对照原任务、子任务答案和附件检查 deliverable，失败时最多三次定点 repair。

怎么工作How it works

  1. 保留全局意图，把请求规划成最多六个子任务。
  2. 顺序执行 ReAct 子任务，把摘要、证据和结果文件写入执行记忆。
  3. 汇总各子任务状态和附件，生成候选 deliverable。
  4. 执行全局验证；发现缺失或不一致时定点修复并复验。

论文报告了什么Reported findings

  • GLM-5.2 在 104 个 AgentIF-OneDay 任务上总分 0.821，AutoClaw 为 0.799，Codex GPT-5.5 medium 为 0.664。
  • DIRECT、仅 decomposition、仅 verification、FULL 分别为 0.771/0.804/0.804/0.821，平均耗时 27.6/38.1/29.7/53.6 分钟。
  • 95/104 项首次验证通过，九项进入 repair，其中六项修复成功、三项仍失败。
  • 35/104 项触发上下文压缩；最高压力任务累计约 350K tokens，压缩次数与成绩近零相关。
  • 同一 harness 的五个后端均完成 104/104，得分 0.613–0.821；GLM-5.2 平均 3216.8 秒，Qwen3.5-397B-A17B 为 964.5 秒、得分 0.708。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：decomposition、compact state 和 artifact-level verification 可直接放到 search/state/call 与 late tool injection 周围，无需替换 A/B 音频路径。
  • 编辑判断：约 80% 的严格工具准确率意味着盲目增加调用会累积失败；verification-only 只增加约 2.1 分钟便达到 decomposition-only 同样的 0.804，适合作为第一阶段。
  • 编辑判断：论文没有 ASR、音频 KV、endpoint、流式语音生成或 TTS；只能放在 endpoint 后的任务执行层，不能作为原生全双工证据。

边界与局限Limits

  • 只在 AgentIF-OneDay 验证；官方基线与新结果使用不同 Gemini judge，作者虽估计新 judge 低 3.12 个百分点，跨 judge 比较仍有混杂。
  • execution memory 始终开启，因为关闭后无法完成任务，其独立因果贡献未被消融。
  • 实现描述允许在宿主机执行任意 shell、没有 workspace sandbox；网页提示注入还可能经压缩记忆传播到 verification/repair。

代码与模型开放情况Code and model availability

部分开放Partial   MIT 官方仓库目前只有 LICENSE、README 和图片，harness 源码与 prompts 标为 releasing soon；无专属权重。约 8.24 GB 官方 trajectories 已发布，但数据仓库没有 license metadata 或 LICENSE，不能继承 GitHub 的 MIT。
