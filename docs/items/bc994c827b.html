FlashLabs Chroma 1.0: A Real-Time End-to-End Spoken Dialogue Model with Personalized Voice Cloning

论文Paper · arxiv · 2026-01-16 · ◈ 9
摘要Summary
Chroma 1.0 以交错文本—声学 token、分层 RVQ 和参考声音条件化生成 24kHz 克隆语音，论文报告首音频 token 146.87ms 和 RTF 0.43。它没有内置轮次检测、打断、工具或确定性执行，更适合作为 endpoint 后的语音生成对照，而不是现有 Harness 的全双工替代品。 Recent end-to-end spoken dialogue systems leverage speech tokenizers and neural audio codecs to enable LLMs to operate directly on discrete speech representations. However, these models often exhibit limited speaker identity preservation, hindering personalized voice interaction. In this work, we present Chroma 1.0, the first open-source, real-time, end-to-end spoken dialogue model that achieves both low-latency interaction and high-fidelity personalized voice cloning. Chroma achieves sub-second end-to-end latency through an interleaved text-audio token schedule (1:2) that supports streaming generation, while maintaining high-quality personalized voice synthesis across multi-turn conversations. Our experimental results demonstrate that Chroma achieves a 10.96% relative improvement in speaker similarity over the human baseline, with a Real-Time Factor (RTF) of 0.43, while maintaining strong reasoning and dialogue capabilities. Our code and models are publicly available at https://github.com/FlashLabs-AI-Corp/FlashLabs-Chroma and https://huggingface.co/FlashLabs/Chroma-4B .

深度讲解Deep dive

Chroma 1.0 以 1:2 文本—音频 token 调度和分层 RVQ 解码流式生成 24kHz 克隆语音，论文报告低生成延迟，但没有证明原生全双工、轮次检测或用户打断。

它解决什么问题Problem

ASR→LLM→TTS 级联会累积延迟并丢失音色、韵律与情绪；已有端到端语音模型又常在低延迟和跨轮次声音一致性之间取舍。

核心方法Core method

Reasoner 提取语义与韵律表示，数秒参考语音和转录由 CSM-1B 编成 voice prompt；约 1B 参数 Backbone 按一个文本 token 对两个音频 code 交错生成，每帧先预测粗 RVQ code，再由约 100M Decoder 预测其余七层，最后用 Mimi 风格因果 codec 恢复 24kHz 波形。训练冻结 Reasoner，用全合成 S2S 目标分两阶段训练 Backbone 与 Decoder。

怎么工作How it works

  1. 接收完整用户语音/文本，并由 Reasoner 提取回复表示。
  2. 把参考声音条件和 Reasoner 表示送入 Backbone。
  3. 按帧交错生成文本表示与八层声学 code。
  4. 因果 codec 分块解码为个性化波形。

论文报告了什么Reported findings

  • H200、并发 1 且 voice prompt 已 prefill 时，首个音频 token 为 146.87ms；该数字不含 endpoint、网络和首个可播放 PCM。
  • 论文单样例生成 38.80s 音频耗时 16.58s，报告 RTF 0.43；Codec 总耗时 2.99s 是否与前级流水重叠未解释。
  • CommonVoice 上 WavLM 说话人相似度为 0.81；主观自然度对 ElevenLabs 的胜率为 24.4% 对 57.2%，音色相似胜率为 40.6% 对 42.4%。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 可作为 endpoint 后、无工具的原生语音输出对照，测 EOU→首 PCM、RTF、声音相似度和长对话漂移，研究能否绕开 Edge TTS。
  • Chroma 没有内置 turn detection、barge-in、结构化工具或确定性执行，146.87ms 不能与 Harness 约 3 秒端到端首音频直接比较，也不是 drop-in replacement。

边界与局限Limits

  • 输出仅英语，延迟只在 H200、并发 1、单样例上测量，且不支持 batch。
  • 正文没有打断、重叠说话、WER、绝对 MOS、长对话漂移或安全评测。
  • 训练数据规模、来源和参考声音授权未披露；论文所称完整训练管线在仓库中也未找到。

代码与模型开放情况Code and model availability

部分开放Partial   推理代码和 gated-public Safetensors 权重声明 Apache-2.0；训练数据、完整训练脚本和数据许可证未发布。模型加载需要 trust_remote_code，公开 README 示例仍在 generate 完成后整体 codec decode。
