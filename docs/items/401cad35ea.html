Filesystem-Based Memory for LLM Agents: Organization, Evolution, and Sustainability

论文Paper · hf · 2026-07-28 · ◈ 5
摘要Summary
该研究表明，文件系统记忆较确定的收益是降低大型材料的读取成本，而不是自动提高回答准确率。记忆效果取决于写入者、读取者、内容类型和工具接口，长期组织质量仍会随增长退化。 Deployed LLM agents increasingly keep their long-term memory as a filesystem: a directory tree of markdown files that the agent itself reads, writes, and reorganizes through generic file tools. Yet research has largely passed over this medium: prior systems design bespoke memory representations and study retrieval over them, leaving the default's two working assumptions untested: that an agent can keep a growing store organized as memories accumulate, conflict, and go stale, and that this organization pays. We present the first systematic exploration of filesystem-based memory for LLM agents. We formalize the setting as three roles around one memory filesystem: a management agent integrates and organizes incoming content, a search agent answers queries with cited sources, and an execution agent supplies task trajectories that are distilled into skills, unifying declarative memory and skills in a single store. Across long-conversation benchmarks and embodied tasks, we vary memory shape (agent-organized hierarchy, verbatim dump, chunk retrieval), stream scale, tool harness (sandboxed shell, memory-tool-style functions, varied search tooling), and the strengths of the management and search agents, tracking answer quality, cost, and store health as memory grows. What organization reliably buys is search economy: organized stores roughly halve retrieval cost where material is large. Today's agents, however, fall short of the default's promise: in our growth study, organization erodes for all but the strongest management agent, and no agent we measure converts organization itself into better answers. And the model is not the only lever over a store's shape: changing the tool set alone reshapes the store as strongly as swapping the model. The study turns the filesystem default from an assumption into a design space for agent memory.

深度讲解Deep dive

这项研究系统比较 Agent 自组织文件树、原样日志和分块检索，发现组织结构主要节省搜索成本，并不稳定提升答案质量。

它解决什么问题Problem

文件系统已成为部署中常见的 Agent 记忆介质，但“Agent 能长期维持组织、且组织值得成本”此前缺少系统验证。

核心方法Core method

作者把记忆拆成管理、搜索、执行三种角色，共享带路径、描述、Markdown 层级和引用的文件树；在 LoCoMo、PersonaMem、REALTALK 与 ALFWorld 上控制记忆形态、模型能力、规模和工具 harness。

怎么工作How it works

  1. 对话片段或执行轨迹按 chunk 到达管理 Agent。
  2. 管理 Agent 通过文件工具创建、编辑、合并、移动或删除记忆。
  3. 搜索 Agent 只读遍历文件树，返回带路径/行号引用的答案或技能。
  4. ALFWorld 执行 Agent 消费检索技能，其轨迹再回写为下一轮记忆。
  5. 持续测量正确率、引用质量、token/调用成本、树形结构和早期记忆存活。

论文报告了什么Reported findings

  • PersonaMem-32k 中重组存储每问成本为 1.4 美分、原样 dump 为 4.0 美分；128k 为 1.6 对 3.9 美分。
  • 强执行模型下 Episode log 为 87.1%、GS 为 82.1%；弱执行模型下顺序反转，GS 为 76.4%、Episode log 为 66.4%。
  • 仅将管理/搜索工具换成 Shell，弱执行模型成功率由默认工具的 76.4% 提升到 82.9%；同一材料的文件数也可从 1–2 个变为 147 个。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 与 StreamingModelHarness 的外部持久记忆和工具层直接相关，尤其说明工具接口本身会改变记忆形态。
  • 论文按完整 chunk 管理、按完整 query 检索，适合 endpoint/commit 后生成；未研究未提交的流式前缀或生成中的迟到结果。
  • 研究不涉及音频、外置 TTS 或原生全双工，不能据此评价声学交互延迟。

边界与局限Limits

  • LoCoMo 只测试一段对话，PersonaMem-128k 也只有一段对话和 42 个问题，小差距接近 judge 波动。
  • 32k 与 128k 层级包含不同对话，不能作为纯规模对照。
  • 最长增长实验只有一条 140-task 链和单段对话，未覆盖数月级记忆；增长期间也未测中间答案质量。
  • 主要实验基于 gpt-5.4 系列和 ALFWorld，外部效度有限。
