RelayS2S: A Dual-Path Speculative Generation for Real-Time Dialogue

论文Paper · arxiv · 2026-03-24 · ◈ 16
摘要Summary

深度讲解Deep dive

RelayS2S 让小型双工 S2S 模型先给出经 verifier 审核的约 5 词前缀，同时让 ASR→强 LLM 从同一前缀续写，以快路径启动速度换取慢路径回答质量。

它解决什么问题Problem

端到端 S2S 启动快但语义较弱，级联 ASR→LLM 质量高却随后端模型变大而增加首段生成延迟。

核心方法Core method

快路径在检测到 BOS/BOC 后分叉出自由解码的投机流，约 170K 参数 verifier 根据 hidden state、熵、log-probability 和 top-two margin 决定提交或回退；慢 LLM 被约束为从已经播放的精确前缀继续，最终统一交给 streaming TTS。

怎么工作How it works

  1. 每 160ms 编码用户语音并预测 SIL、BOS、BOC 或 STP。
  2. 决定发言时并行启动快路径前缀和 ASR→LLM 慢路径。
  3. verifier 审核投机前缀，通过则立即送 TTS，否则完全回退慢路径。
  4. 慢 LLM 从已提交前缀续写；持续监听的主分支在 STP 时停止播放。

对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：当前 Harness 可在 endpoint 后并行运行“小模型前缀+大模型续写”，但无法复现论文边听边附和和 barge-in 的模型级双工路径。
  • 编辑判断：晚注入工具与早提交事实性前缀冲突；工具结果确定前只能允许无命题短开场，且必须重测 endpoint→首个可听音频。

边界与局限Limits

  • 前缀越长低质量率越高，默认阈值仍提交 45.7% 的坏前缀。
  • backchannel F1 只有 50.8，说明最难的交互时机仍不稳定。
  • 81ms 延迟排除了 endpoint、网络与 TTS，且只在单张 L40S 上测量，不是用户听到声音的端到端延迟。
