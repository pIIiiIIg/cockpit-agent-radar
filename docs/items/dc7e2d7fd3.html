MASS: Multiplayer World Models with Authoritative Shared State

论文Paper · hf · 2026-08-05 · ◈ 3
摘要Summary
MASS 用唯一版本化 typed state 推进多人世界，再从同一状态按需渲染各视图；Snake 测试的状态恢复为 0.764、跨视图冲突为 0。对 Harness 的价值是“动作先授权并提交，TTS 只渲染已提交状态”的权威状态设计，而非可直接采用的实时全双工模型。 Current video world models struggle in multiplayer environments because they entangle world state with view-dependent visual latents, leading to redundant compute, view inconsistencies, and poor scalability. We propose MAS (Multiplayer world models with Authoritative Shared State) to resolve this limitation. Inspired by multiplayer game architectures, MAS disentangles world dynamics and view rendering. A learned Logic Engine advances a global, authoritative typed state from joint actions without any hand-written transition function, acting as the sole recurrent memory and synchronization reference. From this shared state, a learned Rendering Engine generates independent and consistent views for any requested camera on demand. This explicit disentangling allows MAS to achieve superior state accuracy and lower cross-view inconsistency compared to state-of-the-art multi-view baselines on a matched multiplayer Snake benchmark. It advances predicted worlds with 1,024 concurrent players for 10,000 recurrent steps. Our results show that explicit, authoritative state modeling provides a practical foundation for scalable and consistent multi-agent world simulation.

深度讲解Deep dive

MASS 将多人世界模型拆成推进全局 typed state 的 Logic Engine 和按需生成视图的 Rendering Engine；权威状态同时是唯一递归记忆、版本化同步消息和所有视图真值，显著改善状态恢复与跨视图一致性。

它解决什么问题Problem

视频世界模型把世界记忆和单一摄像机 latent 绑定，导致多人场景重复维护视图历史、同一实体跨视图冲突，世界推进成本还会随观看视图数增加。

核心方法Core method

每个游戏声明实体、字段、合法值域、排序和固定宽度 schema。Tokenizer 把每条实体记录与局部邻域、玩家动作和外生随机输入编码。六层 decoder-only Logic Engine 按记录批处理并受 schema mask 约束，统一组装下一版本状态；运动与碰撞等转移仍由模型学习。Rendering Engine 把同一状态投影成相机局部 16 通道张量，再由残差 U-Net 生成 RGB，不读取图像历史。更新中断时客户端短时推测，收到新版本后直接以权威状态覆盖。

怎么工作How it works

  1. 声明实体、字段、计数、值域、规范序列化与局部上下文 schema。
  2. 把当前权威状态拆成 typed records，并附联合动作与外生输入。
  3. Logic Engine 按 schema mask 解码各字段，统一组装下一状态并增加版本号。
  4. 每个相机从同一状态生成局部投影，再独立渲染画面。
  5. 服务器缺失时客户端短时推测；新版本到达后覆盖推测结果。

论文报告了什么Reported findings

  • Snake 测试中 MASS 的 LPIPS 为 0.098，Parser 状态恢复 0.764，跨视图不一致 0.000；次优视频基线状态恢复仅 0.128。
  • 直接状态预测在 H=1 时 semantic/position 为 97.9%/99.1%、冲突 0%；H=32 与 H=128 的位置准确率仍为 90.2% 和 72.3%。
  • 只知道本地动作时，更新中断一致率由 k=1 的 0.815 降至 k=8 的 0.429；完整联合输入则始终 1.000。
  • 千人 Snake 每 tick 预测 5121 条记录；单 H100 上，请求视图从 1 增至 1024 时总渲染耗时由 189.6ms 增至 842.4ms。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：单一版本化 typed state 可映射到 Harness 的候选授权动作和确定性执行器：动作先验权、提交，再推进状态，输出只读取已提交版本。
  • 编辑判断：Logic/Rendering 分离可类比语义/动作状态与外挂 TTS：TTS 只是可替换渲染层，不能反向改写执行结果。
  • 编辑判断：endpoint-before-generation 可采用其顺序约束；late tool 结果应作为下一版本的显式输入，不能静默修改已提交状态。
  • 编辑判断：MASS 是 tick 驱动快照系统，不是异步 token/audio 全双工，只提供权威状态设计依据。

边界与局限Limits

  • 每个游戏都需人工设计 schema、上下文、tokenizer 和独立权重，并非一个跨游戏通用模型。
  • typed mask、排序和唯一性 selector 直接保证部分结构有效性，零 invalid 不等于动力学正确。
  • 长时误差明显累积，Snake Parser 到 tick 128 降至 0.642，压力测试还会进入周期吸引子。
  • 千人规模不是完整实时网络系统：单视图已有 189.6ms，未知远端动作也快速降低一致率。
