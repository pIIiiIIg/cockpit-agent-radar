Mind the Pause: Disfluency-Aware Objective Tuning for Multilingual Speech Correction with LLMs

论文Paper · arxiv · 2026-05-12 · ◈ 8
摘要Summary
论文用 MuRIL 标记印地语、孟加拉语和马拉地语 ASR 文本中的不流畅 token，再以带负向对比约束的 3B LLM 重写完整流畅句，正文实验显示其优于无对比损失和 mBART 等基线。对 StreamingModelHarness，它可作为 endpoint 后、意图和工具解析前的文本纠错候选，但不提供原生模型级全双工，且必须先验证误删自我修正与车控关键词的风险。 Automatic Speech Recognition (ASR) transcripts often contain disfluencies, such as fillers, repetitions, and false starts, which reduce readability and hinder downstream applications like chatbots and voice assistants. If left unaddressed, such disfluencies can significantly degrade the reliability of downstream systems. Most existing approaches rely on classical models that focus on identifying disfluent tokens for removal. While this strategy is effective to some extent, it often disrupts grammatical structure and semantic coherence, leading to incomplete or unnatural sentences. Recent literature explored the use of large language models (LLMs); however, these efforts have primarily focused on disfluency detection or data augmentation, rather than performing comprehensive correction. We propose a multilingual correction pipeline where a sequence tagger first marks disfluent tokens, and these signals guide instruction fine-tuning of an LLM to rewrite transcripts into fluent text. To further improve reliability, we add a contrastive learning objective that penalizes the reproduction of disfluent tokens, encouraging the model to preserve grammar and meaning while removing disfluent artifacts. Our experiments across three Indian languages, namely Hindi, Bengali, and Marathi show consistent improvements over strong baselines, including multilingual sequence-to-sequence models. These results highlight that detection-only strategies are insufficient. Combining token-level cues with instruction tuning and contrastive learning provides a practical and scalable solution for multilingual disfluency correction in speech-driven NLP systems. We make the codes publicly available at https://github.com/deepak-kumar-98/Mind-the-Pause.

深度讲解Deep dive

Mind the Pause 先用 MuRIL 标出 ASR 文本中的不流畅 token，再以对比损失约束 3B LLM 重写句子，减少重复、填充词和假启动。

它解决什么问题Problem

仅删除检测到的不流畅 token 容易破坏语法、指代和语义完整性；普通指令微调又只奖励正确参考文本，没有直接惩罚模型重新生成输入中的不流畅片段。论文针对印地语、孟加拉语和马拉地语的低资源 ASR 后处理，研究如何同时保留原意并恢复句子流畅度。

核心方法Core method

第一阶段将平行的流畅—不流畅句对对齐，为每个词及其 WordPiece 子词生成二元标签，并联合微调 MuRIL。第二阶段把任务指令、不流畅句子、MuRIL 预测标签和不流畅 token 列表一起输入 Llama-3.2-3B-Instruct 或 Qwen2.5-3B-Instruct，目标为完整流畅句。训练除交叉熵外，还在每个响应位置汇总不流畅 token 的生成概率，并最小化 -log(1-s)；同一词的子词按 1、0.5、0.25 等几何衰减赋权，总损失为交叉熵加带 warm-up 的 λ=0.3 对比项。

怎么工作How it works

  1. ASR 先完成语音转写，产生可能含填充词、重复、假启动和自我修正的文本。
  2. MuRIL 对转写执行 token 级二分类，输出流畅或不流畅标签。
  3. 系统把原句、token 序列、预测标签和待抑制 token 列表组装为 Alpaca 风格指令。
  4. 微调后的 3B LLM 重写完整句子，而不是机械删除被标记的 token。
  5. 生成训练同时接受流畅参考的正向交叉熵监督和避免重现不流畅 token 的负向监督。

论文报告了什么Reported findings

  • Table 2 的真实 ASR 数据上，MuRIL 检测 F1 在孟加拉语、印地语和马拉地语分别为 0.9241、0.9699 和 0.9290；但整句准确率仅为 0.3267、0.6333 和 0.5040，说明 token 指标不能等同于整句无误。
  • 相对无对比损失版本，Llama-3.2-3B-Instruct 跨语言与数据集平均提高 1.97 BLEU 和 1.53 chrF2、降低 1.65 TER；Qwen2.5-3B-Instruct 分别提高 4.68、2.37，并降低 3.22 TER。
  • Qwen 对比模型在印地语人工编辑集达到 96.1 BLEU、98.0 chrF2、3.7 TER，在真实 ASR 集达到 91.1、94.9、6.0。
  • Table 5 的成对 LLM 评审在真实印地语和马拉地语上偏好对比模型的比例分别为 28.0% 对 9.3%、30.0% 对 8.0%；孟加拉语却为 18.0% 对 27.0%，且各语言平局占 55.0% 至 62.7%，效果并非所有主观评测条件下都一致。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 编辑判断：当前 StreamingModelHarness 流式接收输入，但仅在 endpoint 后生成，工具晚注入，并使用外部 TTS；它不是原生模型层全双工，因此本文属于判停后的文本清洗模块，不能据此宣称获得连续听说能力。
  • 编辑判断：可在 endpoint 提交转写后、意图识别和工具参数抽取前处理“开空调——不，开车窗”一类自我修正，但应保留原始转写、标签置信度和重写结果供安全审计。
  • 编辑判断：不宜直接把所有填充词和重复词强制删除；车内指令中的强调、合法重叠词和最终修正目标一旦被误标，可能改变工具调用语义。应先以只读影子模式评估中文、方言、多人远场和 AEC 残留数据。

边界与局限Limits

  • 这是 ASR 后的整句文本重写，不读取连续音频，也未报告流式增量推理、端点延迟、首 token 延迟或打断处理能力。
  • 训练主体约为 12 万条规则合成句对；真实测试集三种语言合计仅 700 句，且只依赖一个平行数据来源。
  • 实验仅覆盖两个 3B 模型并采用单次运行，未报告随机种子方差；对中文、代码切换和真实车内声学条件没有证据。
  • 正文称人工评价同时考虑流畅度和意义保持，但附录评分说明明确要求只评流畅与自然度、不评意义正确性，两处口径不完全一致。
  • 方法要求移除给定的不流畅 token；对检测误报、语义性话语标记和语言特有重叠词，强负向约束可能造成过度改写。
