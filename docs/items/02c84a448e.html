MerchantBench: Benchmarking LLM Agents for Long-Term Coherence in E-Commerce Operations

论文Paper · hf · 2026-07-30 · ◈ 5
摘要Summary
MerchantBench 把长期一致性具体化为一年期电商经营，要求 Agent 在资金约束、季节需求和延迟订单异常之间持续修正策略。当前模型明显落后于人类，还会出现活动衰减、过早放弃和错误策略长期固化。 Large language model agents are increasingly evaluated as autonomous tool users, yet most benchmarks focus on bounded tasks with immediate success criteria. Real-world deployments often require Long-Term Coherence, the capacity to preserve purposeful behavior across extended horizons while adapting decisions to accumulated evidence. Evaluating this capacity requires a persistent environment in which actions constrain future choices, feedback arrives at heterogeneous delays, and incoherent behavior produces measurable cumulative effects. Seller-side e-commerce provides a suitable setting for this evaluation through recurrent and interdependent decisions over Product Sourcing, Listing and Pricing Control, Cash-Flow Management, and Mixed-Latency Feedback Adaptation. We introduce MerchantBench, a 365-day order-level simulation grounded in 98,843 real e-commerce product records and equipped with 26 tools for agent interaction. MerchantBench couples promptly observable Upstream Supplier Events with delayed Downstream Order Outcomes, requiring agents to follow individual order lifecycles and revisit earlier decisions. We evaluate eight LLMs under two agent frameworks in 48 runs, each spanning 365 simulated days. Our results reveal a substantial gap between even the latest LLMs and human participants, with the best LLM configuration attaining only 27.3\% of the mean final net assets achieved by human participants.

深度讲解Deep dive

MerchantBench 用一年期电商仿真衡量 Agent 能否持续追求资产目标并根据延迟订单反馈修正策略；最佳 LLM 仅达到人类平均最终净资产的 27.3%。

它解决什么问题Problem

现有 Agent 基准多为短期、即时反馈任务，无法测量跨数百天保持目标、跟踪订单因果和适应非平稳需求的能力。

核心方法Core method

论文基于 98843 条 1688 商品记录构建 365 天、小时级 POMDP，包含 26 个工具、三类上游事件和六类下游异常，并比较八个模型在 ReAct 与 Hermes 下的长期经营轨迹。

怎么工作How it works

  1. 每 12 个模拟小时向 Agent 提交店铺、资金、订单和供应商观察。
  2. Agent 通过工具选品、上架、定价、下架和查询订单。
  3. 环境逐小时演化需求、库存、供应商事件和订单生命周期。
  4. 延迟退款、差评、罚款等结果出现后，Agent 应回溯并调整产品组合。
  5. 365 天后结算未完订单，以现金、保证金、在途资金和应收款计算净资产。

论文报告了什么Reported findings

  • 表 1 中最佳配置 Qwen3.7-Max/Hermes 的最终净资产为 59.46 千元，人类为 217.61 千元，即只达到 27.3%。
  • 跨八个模型平均，Hermes 相比 ReAct 的净资产、GMV、订单分别高 53.3%、71.5%、71.2%；但 Kimi K2.6 的净资产反而下降 4.1%。
  • 人类 SWR 为 100%；LLM 在 ReAct 下为 10.6%–99.4%，Hermes 下为 17.8%–66.1%。
  • Qwen3.7-Max/Hermes 虽均值最高，三次运行净资产变异系数仍达 55.1%。
对 StreamingModelHarness 的帮助（编辑判断）Fit for StreamingModelHarness (editorial analysis)
  • 决策窗口对应“输入流结束/commit 后才生成”，适合测试外部编排器的长期状态和工具闭环。
  • 延迟订单结果可映射为后续 commit 前的 late tool-result injection；论文没有测试把结果注入正在生成的响应。
  • 这是纯文本工具环境，与外置 TTS 正交，不构成原生模型级全双工证据。

边界与局限Limits

  • 数据只覆盖 1688、十个一级品类和单件代发模型，跨市场外推有限。
  • 每个模型×框架只有三次运行，人类基线也只有三名无电商经验参与者，且实验已显示高方差。
  • 只比较 ReAct 与功能更丰富的 Hermes，框架差异同时包含代码、规划、记忆和技能能力。
  • 公开仓库不含论文使用的真实业务数据，无法从公开材料完整复现实验。
