## 一、增量范围与结论

本报告读取了最新 `main` 的 `data/items.json`、`data/explanations.json` 和 2026-08-06
两份报告。候选窗口包括昨日 10:30 之后进入 Radar 的批次，以及此前已入库、但直到今天
才完成正文核验且未写入昨日报告的技术。

以下“论文事实”只来自论文正文、arXiv/Hugging Face 论文页、作者官方项目页、官方
仓库或官方模型页；“编辑判断”是结合 StreamingModelHarness 当前实测作出的建议。
Radar 摘要只用于发现候选，不作为结果证据。未核验的数字、许可证和开放状态均写未知。

### 今日结论

1. **P0：RestoreKV + Sparse Event-KV** 最直接命中 B 路径的持久 KV 失败。前者提供
   “固定预算内学习恢复”的候选，后者证明“删掉源音频 KV 不等于删掉其语义影响”。
   两者应先用于诊断和离线 A/B，不能写成现成的 Qwen3-Omni 修复。
2. **P0：LedgerMind + Silent Failures** 可把昨日 VAmoS/MIST 的最终状态契约继续扩展为
   “证据来源、工具轨迹、车态和口播一致”的双层验收。今天没有更好的理由继续只看
   工具名或最终答案。
3. **P1：OneDayAgent** 支持 endpoint 后的任务分解、全局验证和定点修复，但完整流程
   将平均耗时近乎翻倍。对实时车控应先只移植 artifact-level verification。
4. **P1：OPPO、AVSCap、FocusMem/SpatialSTALE** 分别提供模态反事实、音视频事件绑定、
   记忆相关性与陈旧度测试。它们是评测和控制变量，不是全双工延迟优化。
5. **P2：LS-MOPD** 说明共享冻结声学前缀的多教师蒸馏可改善多语 streaming ASR，
   但基座、代码和权重均未开放，训练门槛也远超当前项目，暂不进入实现队列。
6. 今日没有经正文核验、能直接改善 **AEC/降噪、中文语义判停、空间听觉、原生全双工、
   本地 TTS 首包或 110ms/token MoE 同步** 的新技术。昨日 NAC Endpointer、QIANGDA、
   Lychee-FD、CosyVoice 和无同步 fast path 继续跟踪。

## 三、今日优先技术

## 1. RestoreKV：固定预算下的学习式 KV 恢复

来源：[论文正文 / Hugging Face Papers: 2608.01247](https://huggingface.co/papers/2608.01247)；
[作者项目页](https://paper.pnu-cvsp.com/RestoreKV/)；
[官方 KVPress 实现](https://github.com/NVIDIA/kvpress/blob/main/kvpress/presses/restorekv_press.py)；
[官方适配器集合](https://huggingface.co/collections/higokri/restorekv-6a747ef7f486dc9e08d1de4c)。

### 问题与方法

**论文事实：** 查询无关的 KV 驱逐必须在未来问题未知时压缩上下文；现有方法通常只决定
保留哪些原始 KV，在极低预算下性能会显著下降。RestoreKV 在完整 prefill 后，让八个
可学习 restore embedding 通过一次启用 LoRA 的前向访问完整缓存，生成上下文相关的
恢复 KV；随后关闭 LoRA，将恢复 KV 与被驱逐器保留的原始 KV 拼接，总预算保持不变。
训练使用冻结 full-cache 模型做教师，只更新 restore embedding 和 LoRA。

### 明确结果

**论文事实：**

- Qwen3-4B 在 5% KV 预算下，KVzip 的 RULER-4K 从 38.2 提高到 73.2；
  QASPER/QuALITY/LongHealth 分别为 18.0→28.7、46.3→52.4、61.0→67.5。
- 五种驱逐方法、四项任务、三种预算的 60 个配对设置中改善 59 个；唯一退步为
  SnapKV/QuALITY、10% 预算的 53.0→51.8。
- Llama-3.1-8B、32K 上下文实验中，恢复 pass 增加 0.03–0.04 秒和 84MB 峰值显存；
  论文称其低于该设置总压缩时间的 0.5%。

### 对 StreamingModelHarness 的帮助

**编辑判断：P0。** 在音频 endpoint 时完整 KV 仍可用、未来工具或 query 尚未知，
这与 RestoreKV 的写入时机接近。可针对 B 路径训练 Qwen3-Omni 专用 adapter，比较：

1. full cache；
2. 当前驱逐/压缩；
3. 相同总预算的 RestoreKV；
4. 清除音频 KV、只保留结构化状态的外部记忆。

必须同时报告工具、参数、最终车态、context attraction、显存和长会话稳定性。它不应
进入在线车控，直到离线输出一致性和安全回归通过。

### 局限与开放状态

**论文事实：** 方法只能在完整 KV 尚未删除时恢复；恢复器与训练时驱逐器强耦合，
SnapKV 训练、KVzip 推理在 5% 预算只得 42.0，而匹配训练为 73.2。论文只测文本 decoder，
没有 Qwen3-Omni、音频、工具注入或 MoE offload。

推理实现已进入 Apache-2.0 的 KVPress；部分 8B adapter 以 CC BY-NC 4.0 发布。蒸馏
训练代码、精确训练清单及论文部分 adapter 未发布。RestoreKV 恢复 full-cache 行为，
不保证消除 full cache 自身的上下文吸引，也不解决当前 GPU→CPU 同步。

## 2. Sparse Event-KV：删除源行后仍存在的语义物化

来源：[论文正文 / Hugging Face Papers: 2607.23693](https://huggingface.co/papers/2607.23693)；
[作者官方仓库](https://github.com/oklen/Compute-Globally-Materialize-Locally)。

### 问题与方法

**论文事实：** 稀疏 event-KV 系统常先全局 prefill，再只服务少量事件 block。论文用
donor-pair 构造两条轨迹：已服务 token、位置、decoy 和未来 query 完全相同，唯一差异
是已删除源事件中的值。若输出仍随隐藏 donor 翻转，就说明被保留的下游 KV 已物化源
事件的计算结果，而非只表示可见文本。作者又用 root、carrier、reference edge、独立
重编码和 logit readout 区分写入、落点和读取。

### 明确结果

**论文事实：**

- Qwen3-8B root-only 的 donor-sensitive 输出 follow:anti 为 99:0；
  256-pair 复现为 130 follow、0 anti、125 const。
- 主动设计的 carrier 把 donor-aligned 恢复从 11/192 提高到 97/192；真实 LoCoMo
  被动 harvest 没有检测到收益。
- 载荷扩大后迅速失效：Qwen3 二元状态恢复率为 0.934，四分类 0.223，八分类 0.156，
  三位数精确恢复为 0/192。

### 对 StreamingModelHarness 的帮助

**编辑判断：P0 诊断。** 这直接修正“删除音频源 KV 就清除了旧音频影响”的假设。
应构造座舱 donor-pair：只翻转将被删除音频中的屏幕、座位或车态值，固定服务的 KV
位置、晚注入工具和最终 query，检查答案/工具是否继续随隐藏 donor 翻转。若翻转存在，
则 context attraction 可能已被写入保留行，不能只按源 token 是否存在解释。

### 局限与开放状态

**论文事实：** 语义物化是脆弱的小容量通道；逐字字符串转移只有 9.7%，结果依赖模型、
措辞、绝对位置、query 和共同服务的行。MIT 仓库公开环境、模型 SHA 和实验脚本，但
没有提交结果输出，部分数据需另取，早期运行还可能使用相邻 revision。无自训练权重。

**编辑判断：** 只把它用作反事实测试，不把 carrier 当生产记忆协议，也不尝试承载
参数、数字或完整工具载荷。

## 3. LedgerMind：工具结果的来源约束与类型化修复

来源：[论文正文 / Hugging Face Papers: 2607.28374](https://huggingface.co/papers/2607.28374)。

### 问题与方法

**论文事实：** 只看最终回答无法区分真实取证、语言先验和错误相消。LedgerMind 将
OCR、裁剪和搜索等工具输出规范化为 11 字段 Structured Evidence Ledger；后续声明
只能引用 active 账本项，并经覆盖率、实体一致性 ECC 和数字一致性 NCC 检查。失败后
只允许 Drop、Refresh、Retry、Acquire、Abstain 等七类有限状态修复，新增内容必须来自
工具输出。

### 明确结果

**论文事实：**

- Hard-200 上六个 backbone 的 Overall 增益为 11.25–19.75 个百分点。
- MMMU-Pro 消融中完整系统为 68.89；去掉账本为 53.50，去掉 typed repair 为 60.40，
  去掉 ECC/NCC 为 63.70。
- EMMA 最佳配置 Overall 为 58.29，相对对应 baseline 增加 9.58 个百分点；Coding
  子项反而下降 0.18 个百分点。

### 对 StreamingModelHarness 的帮助

**编辑判断：P0。** 将昨日 VAmoS 的证据链具体化为：

```text
音频/视频来源与版本 → endpoint/commit
→ 候选工具与证据引用 → typed call/参数
→ 执行器结果 → CarSim 最终车态 → 回执 → TTS 口播
```

每个口播声明必须引用当前有效的执行/车态条目；工具失败、状态变化或用户改口时，用有限
状态转换覆盖或失效旧条目。来源约束只能证明“来自哪个工具”，不能证明工具本身正确，
所以最终 CarSim 查询仍是硬门。

### 局限与开放状态

**论文事实：** 论文只研究静态图文 VQA；ECC/NCC 依赖确定性抽取和小型别名表，
没有统一报告额外延迟、token 或 API 成本。Hard-200 含未公开子集，固定审计器也有偏差。
截至 2026-08-07 未核验到官方实现、数据、专属模型或软件/数据许可证，开放状态未知。

## 4. Silent Failures：答案正确之外的轨迹正确率

来源：[论文正文 / arXiv:2607.19793v1](https://arxiv.org/abs/2607.19793v1)；
[作者官方仓库](https://github.com/DingWu1021/silent-failures-multimodal-agentic-search)。

### 问题与方法

**论文事实：** 论文把多模态搜索轨迹错误分为六类：模态捷径、伪落地、错证据碰巧答对、
过度检索洗白、跨模态矛盾和伪造来源。它从 MMSearch-Plus 抽样 200 题，让四个模型在
统一 ReAct scaffold 中最多调用十次工具，再联合判断最终答案和完整轨迹，计算
Trajectory-Correct Rate，并做空白图、跨裁判和工具消融。

### 明确结果

**论文事实：**

- committed 子集的 Accuracy/TCR 分别为 Claude 36.0%/34.6%、Gemini 2.5 Pro
  31.6%/28.6%、Gemini 3.1 Pro 61.3%/54.0%、GPT-4o 22.9%/22.3%。
- 答案正确性的跨家族 Cohen's kappa 为 0.817，但 modality-shortcut 只有 0.031，
  表明细粒度错误标签高度依赖裁判。
- 空白图压力测试总体仅 2/208 仍答对；反向图片搜索同时提高部分模型准确率并增加部分
  伪落地和跨模态冲突。

### 对 StreamingModelHarness 的帮助

**编辑判断：P0。** 对同一条回归同时给出：

- outcome：工具、参数、最终车态、口播是否正确；
- trajectory：是否使用正确音频/视频、是否引用真实工具回执、是否被旧状态污染；
- timing：endpoint、commit、首 token、工具到达、车态生效和首音频。

这可防止“车态碰巧正确”或“回答正确但使用了错误乘员/屏幕证据”被计为完整成功。
细粒度标签不能只交给单一 LLM judge，关键安全桶应有确定性断言或人工抽检。

### 局限与开放状态

**论文事实：** 主结果只分析各模型 62%–88% 的 committed 子集，每题每模型仅运行一次；
论文、README 和脚本的部分计数不一致。仓库公开 scaffold、工具、rubric 和分析脚本，
但未公开抽样清单、完整轨迹、标签和结果，也没有 LICENSE；复用许可未知。

## 5. OneDayAgent：endpoint 后的全局验证与定点修复

来源：[论文正文 / Hugging Face Papers: 2608.05013](https://huggingface.co/papers/2608.05013)；
[作者官方仓库](https://github.com/zjunlp/OneDayAgent)。

### 问题与方法

**论文事实：** OneDayAgent 面向跨网页、文件、计算和图像的小时级任务。它始终保留
global intent，最多分解成六个有序子任务；子任务以摘要、证据和文件句柄提交状态。
128K 上下文到 90% 时做 LLM 压缩，到 95% 时确定性裁剪。综合产物完成后，verifier
对照原任务、子任务答案和附件检查 deliverable，失败时最多做三次定点 repair。

### 明确结果

**论文事实：**

- GLM-5.2 在 104 个 AgentIF-OneDay 任务上总分为 0.821；DIRECT 为 0.771。
- DIRECT、仅 decomposition、仅 verification、FULL 的平均耗时分别为
  27.6/38.1/29.7/53.6 分钟，分数分别为 0.771/0.804/0.804/0.821。
- 95/104 项首次验证通过；九项进入 repair，其中六项修复成功。
- 同一 harness 的五个后端都完成 104/104，但得分和耗时差异很大。

### 对 StreamingModelHarness 的帮助

**编辑判断：P1。** 实时车控不应照搬完整长任务编排。先做 verification-only：
执行后对照原始语音、typed call、参数、CarSim 终态和口播计划；失败时只允许重新查询
状态、重试幂等工具、澄清或拒绝。若复杂搜索任务需要分解，再单独开启 bounded subtask。

### 局限与开放状态

**论文事实：** execution memory 没有关闭消融；不同结果使用不同 judge；实现描述允许
宿主机任意 shell，网页提示注入还可能随压缩记忆传播。MIT 官方仓库目前只有 LICENSE、
README 和图片，源码/prompts 标为待发布；轨迹数据页没有独立许可证，不能推定继承 MIT。

## 6. OPPO：用模态遮蔽检查音频、视觉主张是否忠实

来源：[论文正文 / arXiv:2606.25325v2](https://arxiv.org/abs/2606.25325v2)；
[作者官方仓库](https://github.com/ZhiyuanHan-Aaron/OPPO)；
[官方模型页](https://huggingface.co/AaronHan/OPPO)。

### 问题与方法

**论文事实：** 情绪 Omni-MLLM 会漏用音频/视觉线索，也会在某一模态被遮蔽时继续编造
该模态证据。OPPO 先把标注推理拆成视觉、音频和情绪线索，以语义覆盖作为奖励；训练时
随机遮蔽 70% 视频或音频，只对对应证据 token 施加完整输入与遮蔽输入之间的定向 KL
目标。整体采用 SFT 后接 GRPO。

### 明确结果

**论文事实：**

- MER-UniBench 九数据集平均分为 81.05，论文复现的 AffectGPT-R1 为 75.60。
- MEP-Bench 上 Baseline→OPPO 的 Recall 为 58.00→70.44，视觉遮蔽 Acc@V 为
  59.20→76.40，音频遮蔽 Acc@A 为 33.00→50.60。
- 只加感知奖励平均为 79.45，加入定向 Omni-Perception Loss 后为 81.05。

### 对 StreamingModelHarness 的帮助

**编辑判断：P1 评测。** 不训练 OPPO，先移植反事实协议：分别遮蔽目标音频、嘴部视频、
屏幕图像或晚到工具结果，检查最终声明和工具是否按预期变化。结合 QIANGDA 的同混音
成对测试，可发现模型实际只依赖声学强者、文本先验或旧工具结果。

### 局限与开放状态

**论文事实：** MEP-Bench 只有 300 条并依赖多个外部模型评分；零值遮蔽可能制造分布外
输入。只验证 Qwen2.5-Omni，训练使用 16 张 H100。仓库公开训练和评测代码并标
Apache-2.0；HF 有约 8.93B 参数权重，但模型卡未明确权重许可证。训练音视频和完整数据
许可不全，部分上游数据有非商业/审批限制。

## 7. AVSCap：按时间绑定 Speech、SFX、Music 与视觉事件

来源：[论文正文 / arXiv:2607.12820v1](https://arxiv.org/abs/2607.12820v1)；
[作者官方仓库](https://github.com/NJU-LINK/AVSCap)。

### 问题与方法

**论文事实：** AVSCap 不把视频描述简化成视觉字幕加 ASR，而是分别抽取视觉锚点与
Speech、SFX、Music 音频事件，用唯一占位符按时间融合，并检查标签唯一性、语义保持和
局部音视频绑定。模型先 SFT，再以长度、语音 LCS 召回和跨模态事件召回做 GRPO。
AVSCapBench 将人工真值拆成视觉、音频和 synergy 事件。

### 明确结果

**论文事实：**

- AVSCapBench 总分为 60.44%，AVoCaDO-7B 为 49.31%，Gemini-3-Pro 为 60.97%。
- Synergy Recall 为 57.70%，AVoCaDO-7B 为 29.13%；音频总体召回为 64.30% 对 61.07%。
- 模态屏蔽实验中 AVSCap-7B 的 Audio/Visual Leakage 为 4%/7%，
  Qwen2.5-Omni-7B 为 72%/25%；附录说明该指标对提示词敏感。

### 对 StreamingModelHarness 的帮助

**编辑判断：P1 评测。** 将座舱流切成 Speech、非语音车内事件、视觉事件、工具事件和
跨模态绑定，分别测召回、时间归属和最终动作影响。它适合 endpoint 后的离线质量评测，
不代表流式判停、持续监听或边说边听。

### 局限与开放状态

**论文事实：** 只覆盖英文，视频越长表现越差；数据构造和评测大量依赖闭源 judge。
项目页和判分脚本公开，benchmark 标为 CC-BY-NC-SA-4.0；仓库无顶层 LICENSE，训练、
数据构造实现不完整，论文所述模型页本次未核验到可用权重，因此权重开放状态未知。

## 8. FocusMem + SpatialSTALE：记忆相关性门与陈旧度审计

来源：[FocusMem 论文正文 / Hugging Face Papers: 2608.04530](https://huggingface.co/papers/2608.04530)；
[FocusMem 作者仓库](https://github.com/stanley-ju/FocusMem)；
[SpatialSTALE 论文正文 / Hugging Face Papers: 2608.04574](https://huggingface.co/papers/2608.04574)。

### 问题与方法

**论文事实：** FocusMem 用角色化 Q-Former 将 episodic/working evidence 各压成八个
latent token，再按当前状态动态读出，并以 HardConcrete 块级门拒绝无关轨迹。
SpatialSTALE 则在动态 8×8 FrozenLake 中翻转环境状态，比较无记忆、原样使用、自检、
读时陈旧过滤 OMCD 和 Oracle，联合测陈旧检测与下游导航风险。

两篇不是同一论文，也不是改名版本；本报告把它们放在同一节，是因为一个回答“是否相关”，
另一个回答“是否过期”，在 Harness 中应成为同一个工具/记忆准入门的两个字段。

### 明确结果

**论文事实：**

- FocusMem 五个 GUI 基准总体成功率为 48.3%，匹配的 Action-only Fixed 为 33.7%；
  在 MMInA-Shopping 上从无记忆 41.0% 逐步升到完整系统 59.0%。
- FocusMem 将污染轨迹从 0 增至 3 条时，门通过率从 86% 降至 35%，但每步时间从
  7.72 秒增至 13.10 秒。
- SpatialSTALE 的 GPT-4o L2 中，NoFilter 成功/死亡为 14.4%/74.4%，NoMemory 为
  28.8%/28.0%，OMCD 为 32.8%/31.6%。
- SpatialSTALE 的视觉陈旧检测平均 F1 在不同模型间从 0.887 到 0.067；检测 F1 与
  过滤后成功率相关性接近零，说明识别陈旧不等于动作正确。

### 对 StreamingModelHarness 的帮助

**编辑判断：P1。** 对晚到工具、跨会话记忆和屏幕/车态缓存增加：

```text
source_id + observation_version + produced_at
+ relevant_to_current_commit + stale/active + actually_cited
```

在它们影响后续 token 或 TTS 前，对照最新流输入和 CarSim 状态检查。短期用结构化摘要
和确定性版本门，不训练 latent token；相关不代表新鲜，过滤成功也不代表动作正确。

### 局限与开放状态

**论文事实：** FocusMem 主要只测冻结 Qwen3-VL-8B 与 Web GUI，主结果均为单次并依赖
专有 judge；官方仓库只有预览 README，代码、权重、数据和 LICENSE 未发布。
SpatialSTALE 是完全可观测符号网格，视觉导航样本很少，部分正文/表格数字不一致；
论文虽称开放，未核验到官方代码、数据或许可证。两者都没有语音、打断或 TTS 实验。

## 9. LS-MOPD：共享声学前缀的多语 streaming ASR 蒸馏

来源：[论文正文 / arXiv:2608.03610v1](https://arxiv.org/abs/2608.03610v1)。

### 问题与方法

**论文事实：** LS-MOPD 先分别用 DAPO 训练普通话、中文方言和英语专家及一个 generalist；
学生在自己的 rollout 上按语言选择验证集 top-K 教师，以 token 级 reverse-KL 蒸馏。
静态配置让教师和学生共享冻结的声学 encoder-adaptor，动态配置允许教师各自更新声学
前缀。基座 NIM4-ASR 为 2.3B，含 FireRed Conformer、下采样 adaptor 和 Qwen3 decoder。

### 明确结果

**论文事实：**

- 静态三教师 streaming 平均错误率为 5.18%；基座、generalist RL 和 best-teacher
  oracle 分别为 5.74%、5.43%、5.37%。
- 静态三教师 offline 平均为 4.45%，基座为 4.70%。
- 动态教师本身略强，但蒸馏后静态为 5.18%，动态为 5.30%，说明声学前缀一致性重要。

### 对 StreamingModelHarness 的帮助

**编辑判断：P2。** 只作为未来 B 路径训练参考：若要训练多语声学前缀，必须固定同一
prefix 表征并按语言分桶。当前 6.39% micro CER 与论文混合七个子集的 CER/WER 平均值
不可直接比较；该方法也不会改善 endpoint 后生成、工具正确率、TTS 或模型原生全双工。

### 局限与开放状态

**论文事实：** 只验证一个未公开基座；复现依赖 56 万小时内部预训练、多个 RL 教师和
8×A100。代码、基座、教师、学生、精确训练清单和论文专属许可证均未发布，开放状态为
不可用。

## 四、未进入主清单的新 Radar 条目

- `hermes-live-voice` 和 `vokra` 是新出现的社区工程条目，但前者主要封装外部 realtime
  服务，后者仍为预发布 runtime；两者没有可与项目比较的完成率、打断、尾延迟或座舱
  结果，因此不写成技术突破。
- 新出现的 Qwen2.5-Omni GGUF、Persona RLVR 和若干 LoRA 页面存在同底座、重复上传或
  训练来源不清的问题；没有完整评测和许可证闭环，不拆成多个新模型候选。
- FocusMem 的论文页与官方仓库、RestoreKV 的论文/项目/KVPress/HF adapter、
  OPPO 的论文/仓库/模型页均按单一技术谱系记录，避免把来源页重复计数。
- SpatialSTALE 与空间听觉无关：它研究空间**记忆陈旧**，不能被误写成声源定位或 FOA
  空间音频技术。
- AVSCap 是离线 omni-modal caption/evaluation，不是 VideoFDB、流式音视频 serving
  或原生全双工模型；没有合并为同一工作。
